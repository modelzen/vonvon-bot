owner 的原则（`docs/product.md` 第 11 节"智能模式不靠规则，关注度照人来做"）："智能模式下，bot 要不要创建一个新的话题、要不要回答，都是靠智能模式的提示词来判断的。回答内容由 bot 自己的 agent 决定；回答要不要艾特，也是由它自己的提示词决定的。这些都不是靠任何规则设置的。"本片只决定判断什么时候看、看多勤、一次看几条，和刹车（每小时上限、出错超时的兜底）。不加任何决定回不回、开不开话题、@ 谁的规则。规则模式不动。

## 1. 做什么

- 把 s25f 的 `Attention` 和 s25f2 的 lane 定时器接到今天的入口上。用户能看到的变化（`docs/product.md` 3.4"关注度和成本"）：
  - 智能群里没点名的消息不再每条都判。bot 刚在一个位置回过话（专注），那里每条真人消息到就判；没人找它（留意），消息先攒着，等这一阵说完（安静 20 秒）、离上一眼够久，一次判断看一批，从里面挑该接的那条回；扫了没它的事，下一眼隔久一点（1、3、5 分钟）。
  - 真人 @ 我（今天的 `mentioned`）、别的 bot @ 我（s27a）照旧马上判，判完影响关注状态：说回就专注。
  - 它说过话的话题重启后也接着盯（读话题登记表）。
  - 用到 45 次起不再扫一眼，到点额度不够就等到额度回来，回来只看最近 10 分钟的；到 60 次没点名的都不判，专注的位置冻成留意，诊断页每群每小时记一条。
  - 群切会话方式、解绑、改了智能提示词，这个群的关注从头开始。
  - 判断的输入多一行"为什么现在看"，扫一眼时新来的几条标"（新）"，判断模型从这一批里挑要接的那条（anchor），决策模型 Jev 看到 `why_looking`、`new`、`new_count`，锚点候选从 4 条放到 10 条。
- 一人聊的捷径（`solo`）、三条底线、"被 @ 一定回"都照今天，s25e 再去掉。
- 依赖：s27a（#424，`aside`、`judgeWake`、`submitWake`、`callJudge`）、s25f（`Attention`、`outcomeOf`）、s25f2（`LaneEntry.kind`、`LaneDeps.due/now/setTimer/clearTimer`、`judge(batch, signal, glance)`、`land(batch, verdict, glance)`、`prune`、落地串行、`JudgeBudget.take(chatId, now, kind)`、`used`、`freeAt`、`JUDGE_GLANCE_CAP`）三片都已合入。4.0 先验。从它们合入后的 `main` 开分支 `codex/s25g-attention-wire`。
- 产品依据：`docs/product.md` 3.4"智能模式怎么判断""关注度和成本"、3.5"bot 正在跑的时候又来了消息"；参数见 `docs/v1-plan.md` 第 5 节"关注度：专注什么时候退""关注度：留意什么时候扫一眼""关注度：判断次数"。

### 4.0 先核对依赖的片已合入

### 4.1 时钟注入：`D/bot/handle-message.ts`

```ts
/** 关注度、lane 的定时器和判断预算共用的时钟；测试换成假的 */
export interface IntakeTime {
  now(): number;
  setTimer(fn: () => void, ms: number): unknown;
  clearTimer(handle: unknown): void;
}
```

- `createOrchestrator` 的 `opts` 加 `time?: IntakeTime` 和 `attention?: Attention`（测试接缝，和 `droppedFile` 一样，产品代码不传）。`time` 默认 `{ now: Date.now, setTimer: (fn, ms) => { const t = setTimeout(fn, ms); t.unref(); return t; }, clearTimer: (h) => clearTimeout(h as NodeJS.Timeout) }`。
- s25f2 写进 `new SmartLanes({...})` 的 `now`、`setTimer`、`clearTimer` 改成 `time.now`、`time.setTimer`、`time.clearTimer`。
- `budget.take(…, Date.now(), …)` 两处（`judgeItem`、s27a 的 `judgeWake`）改成 `time.now()`。`Attention` 的每次调用都传 `time.now()`。别处的 `Date.now()`（诊断记录的 `at`、act 行）不动。
- `const attention = opts?.attention ?? new Attention()`，放在 `budget` 旁边。参数不传，用 `ATTENTION_DEFAULTS`。
- `const placeOf = (msg: NormalizedMessage): PlaceRef => ({ chatId: msg.chatId, place: msg.threadId ?? msg.chatId });`，放在旁边，下文的 `ref` 都用它算。
- `SmartItem` 加 `at: number`：lane 收到它的时间（`time.now()`），`submitSmart`、`submitWake` 建 item 时写。`pickGlance` 用它，不用 `createTime`（s25f 4.8："at 用收到的时间，和 due 的 pending 一样"）。这样 m0（一批里最后收到的）只要这一眼不空，就一定在 `look` 里；飞书重推的旧消息也不会因为 `createTime` 早被当成旧的。

### 4.2 `D/bot/attention.ts` 加 `freeze`

```ts
/** 到了 60 次（3.4"关注度和成本"）：专注的位置冻成留意，间隔 exitIntervalMs，misses 归 0；留意的不动。
 *  返回改了没有。没有状态不新建。摸 LRU。 */
freeze(ref: PlaceRef, now: number): boolean;
```

`now` 收下不用（和别的方法同形，以后记时间用）。其余规矩同 s25f 4.1：不读时钟、不抛。

### 4.3 `D/bot/smart-intake.ts` 加 `rearm`

```ts
/** 这个位置的待看重算 due：调用方的关注状态变了（比如进了专注，待看该马上判）。没有 chat 批在判就 arm；
 *  在判的，判完的 settle 自然会重算。没有这条 lane 什么都不做。 */
rearm(place: string): void {
  const lane = this.lanes.get(place);
  if (lane && !lane.judging) this.arm(lane);
}
```

`arm` 第 1 步先 `clearTimer`，所以 `rearm` 以后不变式照旧成立。为什么要它：s25f2 的 `settle` 只在没有定时器时 `arm`，进了专注以后，留意时设下的定时器还挂着，待看要等到点。它只在三处调（4.4 话题里被 @ 直接起的那一轮、4.8 `landSmart` 的 `finally`、`noteOpenedTopic`），都不在 `arm` 里面，`landSmart` 的 `finally` 在 `await` 之后跑，也不在 `flush` 的同步段里，不会重入。不在判断回来的那一刻调：那时这一轮还没落地，`prune` 还没拿走它带走的待看，马上起判就会把已经带走的再判一遍（design 1.7）。

### 4.4 入口：每条消息 `arrive`，话题从登记表恢复专注

`submitSmart(msg, variant, scan?, mine?)` 多一个参数 `mine?: boolean`。`shuttingDown` 的检查之后、建 `item` 之前：

```ts
const now = time.now();
attention.arrive(placeOf(msg), now, mine === undefined ? undefined : { mine });
```

item 里写 `at: now`（4.1）。

- `named`（`mentioned`）也调（s25f 4.4："硬信号也调"）。返回值不用：进待看还是马上判由 lane 的 `due`（4.5）定。
- s27a 的 `submitWake(msg)` 改成 `submitWake(msg, mine?)`，同样在建 item 前 `arrive`（带 `mine`）、写 `at`。入口那一行（s27a 4.1 的 `submitWake(msg)`）改成 `submitWake(msg, await topicMine(msg))`：别的 bot 在我说过话的话题里 @ 我，又是这个话题重启后的第一条，也要从专注开始；不读的话它会按留意新建状态，之后 `mine` 就不再看了。
- 话题入口（:1985-1988）：

```ts

  if (await alreadySeen(msg, ts.sessionKey)) return;
  submitSmart(msg, 'topic', scanned.topic, await topicMine(msg));
```

```ts

 *  有状态不读。登记表读的是本机文件，list/get 不抛；topics 没有就是 false。 */
async function topicMine(msg: NormalizedMessage): Promise<boolean | undefined> {
  if (!msg.threadId || attention.state(msg.threadId)) return undefined;
  const t = await topics?.get(msg.chatId, msg.threadId);
  const mine = Boolean(t && (t.sessions.length || t.openedBy?.kind === 'self'));
  if (mine) log.info('intake', 'attention-recover', { ref: msg.messageId.slice(-6), place: 'topic' });

}
```

- 主区不恢复（s25f 4.4：主区给了 `mine` 也按留意开始），主区入口（:1929）不改。
- 读登记表期间停机：`submitSmart` 开头的 `shuttingDown` 检查照旧挡住。

### 4.5 lane 的 `due`：专注马上、留意按 `Attention.due`、45 次按 `freeAt` 推后

`new SmartLanes({...})` 里 s25f2 的 `due: () => undefined` 换成：

```ts
due: (place, waiting, now) => {
  // 专注：今天的做法，判断中来的几条合成一批、逐条判、不是扫一眼（design 1.3）。
  if (attention.state(place)?.mode === 'focus') return undefined;
  const at = attention.due(place, waiting.map((w) => w.at), now)!;   // waiting 非空（s25f2 arm 第 2 步），不会是 undefined
  if (at > now) return at;
```

### 4.8 落地：`landVerdict`

状态：`const takenTo = new Map<string, { chatId: string; at: number }>();`，键是位置。"已带走到"：这个位置最近一轮起跑时触发消息的 `createTime`，只增（design 1.7 的"起跑登记"）。超过 1,000 个键时删最早插入的。它只管"哪些消息已经随一轮进了会话"，和关注状态无关，`forget` 不清它（4.10）。

```ts

function takeUpTo(ref: PlaceRef, at: number): void {
  const to = Math.max(takenTo.get(ref.place)?.at ?? 0, at);
  takenTo.delete(ref.place);                       // 重新插入，删最早插入的时它排在最后
  takenTo.set(ref.place, { chatId: ref.chatId, at: to });

  const pruned = smartLanes.prune(ref.place, (e) => e.msg.createTime <= to);
  if (pruned.length) log.info('intake', 'lane-pruned', { place: ref.place.slice(-6), n: pruned.length });
}
```

### 4.9 60 次：冻成留意，每群每小时一条诊断

```ts
async function advance(ms: number): Promise<void> {
  const end = clock + ms;
  for (;;) {
    const next = [...timers].filter(([, t]) => t.at <= end).sort((a, b) => a[1].at - b[1].at)[0];
    if (!next) break;
    timers.delete(next[0]);
    clock = Math.max(clock, next[1].at);
    next[1].fn();
    await settle();
  }
  clock = end;
  await settle();
}
```
