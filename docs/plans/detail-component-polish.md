# 详情导航、运行状态与搜索内光

## 需求与范围

owner 2026-10-26 看过三组现状 / 建议对比后要求按建议实施，并根据实际产品调整参数。基于当前 dev，保留已验收的主导航和群标题栏入口。

- 群设置四标签和 Bot 详情三标签采用官方 Gooey 滑块。
- 当前任务、注册处理中、Provider 连接与模型读取使用官方 Thinking Orbs。
- 全局搜索输入区增加静态底部内光，采用已存在的 Border Beam。

不更改搜索算法、路由、草稿保护、飞书绑定弹窗、注册 / 登录流程或后台协议；不新增依赖。

## 实现

复用 `NavigationIndicator`，把装饰层样式提取到自身文件。所有导航仍由原生按钮处理点击、焦点和选中语义。详情轨道高 36px、内边距 4px、圆角 10px；滑块高 28px、圆角 7px，按按钮实际宽度测量。保留已验收的 Move 参数与 200ms 过渡，键盘、减少动态效果、强制颜色和隐藏文档采用静态反馈；触摸控件维持 44px 高度。

状态提示复用 `OperationActivity` 的 2 秒延迟、20px 浅色主题和定时器清理。任务用 working，注册及连接用 connecting。按任务 id 重置显示延迟，结束卸载。等待用户扫码或输入授权码时保持静态，不编造运行阶段或进度。

搜索内光强度 0.5，装饰画布横向拉伸以覆盖整个输入区宽度，底部 4px 保持亮度并向上渐隐至 28px，暂停在同一帧；外边框保持中性，输入内容与焦点位于装饰层上方。搜索仍为即时本地匹配。强制颜色模式不绘制内光。

## 验证与验收

运行 UI 类型检查、现有 UI 测试及工作区构建。以实际组件和内存 fixture 检查不同宽度、鼠标切换、键盘切换、搜索及运行状态消失；不向真实群发送消息，不启动真实注册。构建签名后在本机 App 检查 Bot / 群设置页和搜索入口，交给 owner 验收。

风险集中于选中背景叠加、窄窗口排版、图标延迟和旧控件语义；复用现有组件和定向交互检查。产品差异记录于 product.md 3.1，进度记录于 v1-plan.md。预估产品变更低于 250 行，diff 不含真实 id、密钥或本机路径。
