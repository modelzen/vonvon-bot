# 发布提速

## 目标与范围

owner 2026-10-30 要求先小测试验证，再将有效方案固化为默认发布流程。固定已验收 main SHA 和双平台同版本，提前下载 Windows 产物，复用系统代理，并行版本化上传，候选绑定确认和官网回执交接。现有签名、公证、完整字节校验、禁止覆盖、CANCEL 和 stable 快照门禁保留。

## 实现

- `release-all.mjs`：Windows 成功后在 Mac 等待期间下载；序列化状态保存；退出时中止并等待后台进程组；同 OUT 续跑。
- `release-network.mjs`、`publish-windows.mjs`：显式代理优先，其次读取 Mac 系统 HTTP(S) 代理，只作用于下载子进程；下载有超时；每个 Windows 对象写入前检查取消。
- `release-publish.mjs`：生成绑定两平台来源/哈希/配置的统一计划，复用原发布器并行上传；分别保存成功回执；提升或续验 stable 后自动收集官网 handoff。
- `release-cos-publish.mjs`：允许 owner 对已展示计划作简短肯定回复，保持原始回复和计划哈希；拒绝否定、候选更改及错误计划。
- `verify-public-release.mjs`：每架构 ZIP/DMG 两条流完整校验，失败时 join 两条流。
- daemon Vitest 配置：Linux CI 使用报告的 CPU 数（最多 4 worker），让双核 runner 使用 2 个；Windows 单 worker 与本机原有上限保留。先小样本，再以完整 Linux CI 决定保留。
- skill、AGENTS 与操作说明：默认发现、授权范围、一次最终候选确认、原 OUT 续跑；不要求用户再次点名提速方案。

## 验证与验收

异步屏障证明提前下载；失败、CANCEL、信号、并发状态保存和已完成候选复用；统一计划篡改/来源不符拒绝；上传并行、失败保留另一平台；简短确认不能绕过来源和文件门禁。定向回归覆盖已有 helper。真实网络只读取同一公开对象的前 2 MiB，比较状态、字节、SHA-256 和时间。不提交 Apple、不写 COS、不安装或启动 Bot，不发飞书消息。CI 由另一开发流程任务维护，本改动不重复修改其平台策略。

## 风险与边界

风险是异步状态、子进程清理、发布恢复和确认门禁，须独立审查。实际 Apple 上传速度、完整大包和下一次正式发版时间仍需实测；本次不减少四次公证，不盲目并行共享 stage 的 Mac 打包，不关闭公网完整哈希核验。它是发布工具改动，不改变产品行为或产品版本。预计约 1,200 行（含测试与文档），不改 v1 功能完成度。
