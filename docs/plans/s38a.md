## 4. 怎么改

`personality-files.ts`导出判别联合PersonalityFile、FileRead（missing/present/error）、成功提交事实及错误种类。`createPersonalityFiles(botRoot,{maxCharacters,execution})`要求可信daemon明确选择 `daemon-exclusive`、`full` 或 `{kind:"restricted",backend}`，无默认降档。构造时捕获不可变execution/限制/提交操作引用，外部修改options不能改变既有实例授权。受限写当前直接返回 `boundary-not-established`，读仍按原契约；没有可伪造的bool/profile名/token开放该分支。字数策略仍显式，不新增产品默认。固定64KiB是安全读取上界，和内容字数限制分开。Unicode码点计字；严格UTF-8解码；读取存量超字数仍返回全文与整理标记。版本为实际内容SHA256，空文件和缺失不同。错误只有种类/相对文件标识，不含正文或绝对路径。

调用者传可信s36来源的physical canonical bot根；模块逐层lstat核对从文件系统根到bot根的所有祖先，并要求realpath与输入完全相同。包括macOS /var、/tmp在内的alias不自动信任；调用者必须先从可信配置明确解析系统路径，不接受agent提供的链接目标。根以下每层lstat拒链接/非目录；打开末端O_NOFOLLOW/O_NONBLOCK，fstat确认普通文件、单硬链接、大小，读前后核文件/目录身份。只访问枚举出的相对文件；id边界验证不接受路径。原子写先验证原对象，在同文件系统 `botRoot/daemon-staging/` 独占创建0600普通源文件，写/sync并持有句柄；固定目标basename从stage rename，不在可写memory中暴露可替换源。失败只在stage祖先/源对象身份匹配时清理该源，不沿memory清理。提交前读取持有源句柄的实际字节形成版本，rename成功即返回该原子时点的事实；合法后写（同inode或原子替换）由下一次read作为新变化，不能把本次已成功说成失败。close失败仅带source-close-failed收尾警告，不逃出结果联合；异常核验不是防目录置换的原子性证明。a不做隔离区/回滚，不猜写入者。模块没有watcher或后台任务，所有句柄finally关闭。

`personality-context.ts`从可信Location判别联合选择固定文件：group公共+本群，dm公共+此人（缺人仅公共），comment仅bot个性+公共。读取失败返回明确失败，缺失和空文件保留于快照，不兜底。身份采用当前输入，缺字段明确缺失。快照摘要包含位置、身份与各实际内容版本，改群名同样变化。开场instructions只含可追加部分，固定前缀仍唯一由resolver添加；修改bridge-instructions的固定红线。记忆标题daemon生成，正文逐行加`│ `，控制字符/块尾不能逃出每行边界。

导出完整开场、声明替换旧版且含新全文的更新块、UTF-8实际字节数、快照差异；更新注明“vonvon自动附，不是用户说的”。组合不截断、不设第二个内容上限。`confirmedWrite`只由成功原子提交返回，s40可将其file/version与当前快照逐项比较；这不是某会话已交付事实。b只在已证明模型实际接收边界维护其持久DeliveredSnapshot；读文件/造profile/入队绝不确认交付。同作者不是事实依据，合并新版本仍变化。
