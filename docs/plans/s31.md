### 3.5 SDK 0.3.296 的事实

- `CanUseTool(toolName, input, { signal, suggestions?, blockedPath?, decisionReason?, toolUseID, agentID?, … })`，返回 `{ behavior: 'allow', updatedInput?, updatedPermissions? }` 或 `{ behavior: 'deny', message, interrupt? }`（sdk.d.ts）。运行时还有类型里没写的字段，比如 `decisionReasonType`（e02 第 1 节）。
- 拒绝带原因、不带 `interrupt`：模型原样收到原因，这一轮接着做；带 `interrupt` 原因会丢，这一轮按出错结束（e02 第 2 节）。
- AskUserQuestion 的输入是 `{ questions: [{ question, header, options: [{ label, description }], multiSelect }] }`（`sdk-tools.d.ts`）。回答：allow，`updatedInput.answers` 的键是问题原文，值是选中的 label，多选用逗号分隔；CLI 自己给每题加"Other"。ExitPlanMode 的输入里可能有字串 `plan`。
- `bypassPermissions` 下只有 AskUserQuestion 和命中 ask 规则的调用进回调；deny 规则直接拒，不进回调（e03b）。删除关键目录推断会进（`safetyCheck`，`bypassImmune`，没实测）。
- `default`、`acceptEdits` 加沙箱（e03）：Bash 写文件不进回调，由沙箱挡；Bash 联网以 `SandboxNetworkAccess`（输入 `{ host }`）进回调；Read、Write 出工作区进回调，`decisionReason` 是 `Path is outside allowed working directories`；只读档 Write 写工作区里也进回调；Bash 读工作区以外不进回调。所有回调都没有 `blockedPath`。`acceptEdits` 下 Write `.mcp.json`、`.claude/` 下的文件也进回调（e02、e03b，理由是 sensitive file）。
- 开网设裸的 `allowedTools: ['WebFetch', 'WebSearch']` 时两个工具不进回调、能用（e03）。
- `hooks.PreToolUse: [{ matcher, hooks: [cb], timeout }]`；`cb` 回 `{ hookSpecificOutput: { hookEventName: 'PreToolUse', permissionDecision: 'deny', permissionDecisionReason } }` 就拒，回 `{}` 交给后面的权限流程。
- 启动带 `allowDangerouslySkipPermissions` 才能中途升到 `bypassPermissions`；resume 不恢复档（e02 第 3 节）。

判定：

```ts
export type Origin = 'hook' | 'callback';
export interface ToolCall { toolName: string; input: Record<string, unknown>; decisionReason?: string; extra: Record<string, unknown> }
export type Verdict =
  | { kind: 'continue' }                                   // 只有钩子用：不管，交给后面的权限流程
  | { kind: 'allow' }
  | { kind: 'deny'; message: string }
  | { kind: 'ask'; ask: 'choices' | 'confirmation' | 'permission' };
export interface PathFs { realpath(p: string): Promise<string>; stat(p: string): Promise<{ dev: number; ino: number }>; lstat(p: string): Promise<unknown> }
export function decide(access: ClaudeAccess, call: ToolCall, origin: Origin, fsx?: PathFs): Promise<Verdict>;
/** 按 4.0 B、E、J 找到的字段认"命中 ask 规则"；找不到能用的字段时一律 'rule'。已知不是规则的原因（4.0 J 记下的：读 cwd 外的 `Path is outside allowed working directories`、`default` 档 MCP 每次都问的那种）认成 'other'。 */
export function ownAsk(call: ToolCall): 'rule' | 'other';
```

导出的工具分组：`FILE_WRITE = ['Write', 'Edit', 'MultiEdit', 'NotebookEdit']`，`FILE_READ = ['Read', 'Glob', 'Grep', 'LS', 'NotebookRead']`。路径取 `input.file_path ?? input.notebook_path ?? input.path`；不是字串时，写工具拒（原因"出错"），读工具当 cwd。

回调（`origin === 'callback'`）：

write、qa 下先看一条，先于下表各行：除了 AskUserQuestion、ExitPlanMode、EnterPlanMode 三种提问，任何工具（Bash、写工具、读工具、`SandboxNetworkAccess`、WebFetch、WebSearch、`mcp__…`、Agent、Skill……）`ownAsk === 'rule'` → deny(自己要问)。用户给某个 Read、MCP 工具或网站配了"必须问"，这两档里就直接拒（product.md 3.8"完全访问下还会问什么"那段说的只读、读写档直接拒绝，不只 Bash、Edit；#440 审查）。下表 write、qa 两列是没命中规则时的判法。


| 工具 | full | write | qa |
|---|---|---|---|
| AskUserQuestion | ask choices | ask choices | ask choices |
| ExitPlanMode | ask confirmation | 同左 | 同左 |

钩子（`origin === 'hook'`，只挂在 write、qa）：写工具，qa → deny(只读)，write 下真实路径在 `realCwd` 外 → deny(工作区外)，其余 continue；别的工具 continue。钩子是为了用户和项目设置里的 `permissions.allow`、`additionalDirectories`：它们让写调用不进回调（4.0 I）。`fileHook(access)` 包一层 try/catch，出错一律 deny。

真实路径：

```ts
export async function resolveReal(p: string, cwd: string, fsx: PathFs): Promise<string>;
/** 只比字面：fold 为真时不分大小写。拒绝名单用（s31b）。 */
export function inside(base: string, target: string, fold?: boolean): boolean;
/** 按目录身份：target 或它的某个祖先和 base 是同一个目录（stat 的 dev、ino 相同）。工作区边界和 s31b 的放行名单用。 */
export function within(base: string, target: string, fsx: PathFs): Promise<boolean>;
```
- 相对路径接在 `cwd` 后面，**不先做字面上的 `..` 折叠**（`cwd/link/..` 在内核里是链接目标的上一级，字面折叠会算成 `cwd`）：原样拼出的路径先整个 `realpath`；报 `ENOENT`、`ENOTDIR` 时从末尾逐段去掉，找到第一个 realpath 成功的前缀，再接上剩下的段（要新建的文件）。剩下的段里有 `..` 或 `.` 的，直接按工作区外算。
- 每去掉一段，先 `lstat` 这一段对应的原样路径：报 `ENOENT`、`ENOTDIR` 才算"还没建"，接着往上找；`lstat` 成功说明目录项在、只是 realpath 不了，也就是悬空的符号链接（指向的东西还不存在，写它会在链接目标那里新建），一律按工作区外拒，不当成没建的后缀拼回去（#440 第三轮审查复现过：`Work/link -> ../outside/new.txt` 会在外面建出文件）。中间一级是悬空链接的同样在这一步拦下。循环链接 realpath 报 `ELOOP`，属于"别的错误"，按"出错"拒。别的错误往外抛，调用方按"出错"拒。
- `inside`：`relative(base, target)` 是 `''`，或者既不是 `..`、不以 `..` 加分隔符开头，也不是绝对路径。`fold` 为真时两边先转小写再比。
- 工作区边界用 `within(realCwd, t, fsx)`，不按大小写猜（#440 两轮审查：按平台统一转小写，或者翻大小写去 `stat` 探卷，都会被同级的 `work` 或指向工作区的大小写别名链接骗过）：
  - `inside(realCwd, t)` 逐字为真 → 真（真实路径的字面前缀，一定在里面）。
  - 否则从 `t` 往上逐级 `stat`，跳过 `ENOENT`、`ENOTDIR` 的（还没建的段），某一级的 `dev`、`ino` 和 `realCwd` 的相同 → 真；到根还没有 → 假。`realCwd` 的 `stat` 在这个会话里只取一次，缓存在 `ClaudeAccess` 上。
  - 这样不分大小写的卷上 `/v/WORK/f`（realpath 没改回 `Work` 的大小写）按身份认出在里面；区分大小写的卷上同级真目录 `work` 身份不同，在外面；指向工作区的别名链接 `wORK` 会被 `resolveReal` 解成 `Work`，本来就在里面。
- 拒绝名单（s31b 的配置文件、读名单的 deny）反过来要多挡：字面不分大小写（`inside(d, t, true)`）或身份相同，任一个成立就算命中。在区分大小写的卷上多挡一个 `.MCP.json` 没有坏处。
- 经工作区里的符号链接写到外面：真实路径在外，拒。

拒绝的原因（模型原样收到，也会出现在运行卡的工具结果里；`{path}` 用模型给的原样，截到 200 字）：

### 4.6 并发、出错和停机

| 场景 | 结果 | 怎么保证 |
|---|---|---|

| 子 agent 提问 | 照样出卡，不写"子 agent X 问"；s35 已合入时 `ask` 带 `subagentId: agentID` | s35 加卡头；见第 2 节 |
