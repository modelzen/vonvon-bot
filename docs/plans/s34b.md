### 3.2 停一个子 agent 的原生办法

- Codex：停一个子线程没有专门方法，对它的回合发 `turn/interrupt {threadId: 子, turnId}`（`docs/native-capabilities.md:148-160`）。子线程停下后来 `turn/completed`（status interrupted），s34a 的映射出 `subagent_status stopped`。
- Claude：SDK 0.3.296 有 `Query.stopTask(taskId)`，停完会发 `task_notification {status:'stopped'}`。`D/agent/claude-agent/thread.ts:331-427` 的 `runStreamed` 返回 `{events, turnId, lastActivity}`，`query()` 的句柄现在没留给返回值；选项在 `289-309`；`pump`（`316-329`）把每条消息交给 `this.sink?.`（`320`），回合结束 `finally` 清 sink（`416-418`）；`abort`（`620-642`）是 `interrupt()` 加 4 秒硬杀。不设 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` 时，Agent 默认在后台跑，父回合先结束（e01 第 23 行）；回合结束后再停它，这版拒绝。

## 4. 怎么改

### 4.1 Codex 的 `stopSubagent`（`D/agent/codex-appserver/backend.ts`）

- `CodexThread` 加 `stopSubagent(id)`：`children.get(id)` 没有或 `running` 为假 → 拒绝"这个子 agent 已经结束"；没 `turnId` → 拒绝"这个子 agent 还没开始回合"；否则 `turn/interrupt {threadId: id, turnId}`。不等 `turn/completed`，由通知自己到 `subagent_status`。
- `runStreamed`/`runGoal` 返回的 `AgentRun` 带它。`children` 不按回合清，所以父回合结束后、下一回合里还能停上一回合留下的子线程。
- `abort`、`routeNotification`、`CodexRequestScope` 不改。用户线程的 `thread/start` 照旧不带 `multi_agent`。

### 4.2 Claude 的 `stopSubagent`（`D/agent/claude-agent/thread.ts`）

- `runStreamed`（`331-427`）把 `query()` 的句柄留在闭包里，返回的 `AgentRun` 加 `stopSubagent(id)`：回合已结束或句柄没了 → 拒绝"这个子 agent 已经结束"；否则 `await query.stopTask(id)`，SDK 抛错原样转成中文前缀"停止子 agent 失败："加原文。
- 选项（`289-309`）不加 `perTaskStopAffordance`，不加 `agentProgressSummaries`，不设环境变量。`abort`、`close` 不变。`bridgeClaudeEnv()`（`backend.ts`）不动。

### 4.3 `handle-message.ts`

- `ActiveState`（`632-691`）加 `subagents?: () => SubagentRow[]`，不加 `stopSubagent` 字段（`state.run` 已经有，再加一份是重复状态，回合结束还多一处要清）。主循环 `render` 建好后（`6176` 附近）装 `state.subagents = () => render.snapshot().subagents`；`6473` 清 `state.run` 的地方一起清 `state.subagents`；`6701` 出错路径也清。目标循环 `launchGoalRun` 里建 `RunRender` 的地方同样装，每轮结束清。
- 卡片动作：在 `RC.stop` 的处理（`3952-3967`）旁边加 `RC.stopSub`，过同样的三道门（`runAllowed`、`runOwnerOrAdmin`、`healDeadRunCard`），从动作的 value 里取 `subagentId`，调 `state.run?.stopSubagent?.(subagentId)`；`state.run` 没了或没有 `stopSubagent` 走 `healDeadRunCard`；拒绝时用 `denyRunControl` 的方式回一句原因。s35 的按钮就发这个动作。
- RPC 的服务端：`5670-5673` 旁边加 `stopSubagent`：`!state || runId(state) !== request.runId` → `AdminWriteError('原任务已经结束，请刷新')`（照 `stop` 的写法）；`!state.run?.stopSubagent` → `AdminWriteError('这个任务不支持单独停止子 agent')`；调用被拒 → `AdminWriteError(拒绝原因)`。不用 `operation_failed`。`context`（`5670`）的 `run` 里加 `subagents: state.subagents?.() ?? []`，只取 `id, name, task, status, stoppable` 五个字段。
- 关机（`7720` 起）不改：`state.interrupt()` 走 `abort`，s34a 已经让它连子线程一起停。

### 4.4 RPC 和协议

- `P/collaboration.ts` 请求加 `stopSubagent {threadId, runId, subagentId} & sessionTarget`（照 `27` 的 `stop` 写，`.strict()`）；回复 `context.run`（`83`）加 `subagents: z.array(z.object({id, name, task, status, stoppable})).optional()`。
- `D/server/rpc/collaboration.ts:43-46` 的 `contextResult.run` 加同样的 `subagents` 可选字段。不加的话 `91` 的 `parse` 会把 bot 一侧的 `subagents` 去掉，网页端拿不到。`stopSubagent` 走默认 `applied` 分支，switch 不用改。
- `D/admin/collaboration.ts:15-34` 的类型和必填表加 `stopSubagent: ['threadId','runId','subagentId']`。

### 4.5 网页端（`U/management/ConversationPanel.tsx`）

- `106` 运行行下面每个子 agent 一行 `SettingsRow`，标题"<name>：<task 前 40 字>"，value 是状态的中文（运行中、已完成、失败、已停止），`running` 且 `stoppable` 的 trailing 一个"停止"按钮，点了 `execute({ action: 'stopSubagent', ...target, threadId: selected, runId: run.id, subagentId }, '已请求停止子 agent。')`，失败的原因走现有的 `error` 提示。用现有组件写，能用、不出错就行，不做样式，不做动画（界面最后由 owner 主导重整）。
- `58-67` 的 `useEffect` 旁边加一个：`run` 不为 null 时 `setInterval` 每 3 秒重拉一次 `context`（和 `102` 的"刷新"同一段代码），`run` 为 null 或换会话时清掉。没有它，子 agent 后来才出现的行、停了以后变 `stopped`，面板上看不到。

### 4.6 要 owner 定的

没有。停不了时的几句文案和 3 秒重拉是 Claude 定的；3 秒重拉写进第 7 节的默认值。
