# s27a2：bot 之间互相 @ 的说法和记录块

## 1. 做什么

依赖已合入的 s27a（#424）。按 product.md 3.4「bot 之间」，bot 的消息没进会话时只记日志和诊断，不另请 bot 重发；记录块显示 bot 是否 @ 你。

## 2. 范围

覆盖入口取消、目标运行中、晚到的 /new 前消息、八处批量丢队列提示、full-only 权限说明的安静期、记录块标记。保持真人提示和计数语义。s27a 已实现的手动提醒按钮和 requesterKind 不重做；不改判断、响应成员、提醒发送和产品定义。

## 3. 现在的代码

基线 a319417。`packages/daemon/src/bot/handle-message.ts` 的 handleTurn、prepareTurn、replyGoalBusy、startReservedRun、refuseFullOnly 仍对 bot 发操作提示。startReservedRun/launchRun 的错误路径、acquireRunSlot 的终态排队卡、运行停止和四处恢复/桌面操作收尾按 queue.length 请重发。QueuedTurn 已有 requesterKind、requesterOpenId、requestedAt、seen。

`packages/daemon/src/bot/context-weave.ts` 的 recordLine 只给真人行加 → @你；bot 行带 bot/还没答完标记。

## 4. 怎么改

- 在编排器内加 dropBotMessage：只处理 fromBot，日志 bot-wake-dropped 带 ref 尾号和 why；非关闭时记同名诊断。取消为 intake-cancelled/会话被停下了；目标为 goal-busy/会话在跑 /goal；晚到为 before-new/会话换成了新的（/new）。命中后返回，不发送对应提示。
- askAgain 接收 readonly QueuedTurn[]、chatId、place、why、detail，返回非 bot 条数。每条 bot 单记日志和诊断，关闭时只记日志，撤回沿用 noteNotReplied 的过滤。unknown 保持旧真人语义。
- 八处批量提示改用返回数，零条不发。两条失败路径先 splice 后计数；停止、排队卡、恢复/桌面操作在原收尾位置计数，不增加 await，不改变取消/释放顺序。占用、停止、失败的 detail 分别是会话被占用、会话被停下了、前一轮出错，排队的没跑。
- full-only 对 bot 的 @ 使用和免 @ 一样的组级安静期；每次仍记 tier-unavailable。真人 @ 每次说明，发送失败回退时间戳照旧。
- recordLine 在 bot 的括号后按 mentionsMe 加「 → @你」，与 streaming 标记兼容。
- 当前回合自身的固定失败卡文字和 runFailureMessage 的错误说明保留（s27a 计划 4.6 的既定范围）。

## 5. 测试

沿用 smart-inbound 的真实编排器与模拟外部 channel/agent；context-weave 使用真实织入函数。

- main 必败：bot 目标忙时无提示且有诊断；真人对照仍有目标提示。
- main 必败：bot 在入口准备期间取消、/new 晚到时无重发提示，非关闭时有诊断，真人语义保留。
- main 必败：混合排队停止/错误只报告真人条数，全 bot 队列不发批量提示；bot 各记诊断。关闭时不增加 bot 诊断。
- main 必败：full-only 连续 bot @ 只发一次说明，每次均记 tier-unavailable；真人 @ 不被安静期挡。
- main 必败：bot 记录行在 mentionsMe 时有 → @你，未 @ 和 streaming 行对照。
- 回归定向运行 smart-inbound、context-weave、run-retry、message-queue-races、queued-card、compaction、goal 和 one-tier 测试。build/typecheck/lint；不跑全量，交 CI。

## 6. Codex 的自测

交 JP-VPS。选择定向编排器回归作为本片自测：产品变化只在已解析 bot 身份后的提示、计数和格式化，s27a 已验证 Bot 7/8 隔离测试群的 bot 事件与身份；模拟 channel 可精确控制停止、异步失败和晚到事件，比真实目标运行时窗口稳定。本片不升级 accept daemon、不发飞书消息，不拿共享环境锁。真实 Bot 7/8 的权限说明次数、目标忙时静默和飞书记录展示本次未实测，明确留在 PR/M5 验收边界，不声称真实通过。无 Mac/桌面外壳变更。

## 7. 文档

product.md 不变。v1-plan 勾 s27a2，加做法和自测边界，不先写 PR 号；第 5 节补 full-only bot 安静期、批量请重发只数真人的默认行为。手动按钮沿用 s27a 的说明。

## 8. 验收要点

- 四处单条提示对 bot 安静，真人行为不变；非关闭 bot 诊断、关闭仅日志。
- 八处批量计数不含 bot；混合/全 bot 队列正确，错误和晚到路径有回归。
- full-only bot @ 受原安静期控制，每条仍有诊断，真人 @ 不受限制。
- bot 记录块标记与 streaming 并存；手动提醒实现未改。
- diff 无真实 id、密钥、本机路径；非 draft PR，独立审查待总管，不打标签不合入。

## 9. 风险和行数

约 450–750 行含文档和测试，上限 1500。风险是错误路径、并发、关闭清理：保持原队列所有权和释放顺序，计数同步完成，关闭不产生 bot 诊断。恢复的四处收尾使用同一计数函数；不新增 I/O。若超过 1500 行先停下拆分。
