# 会话响应速度与极简闪电入口

## 做什么

owner 2026-10-29 根据用户“分会话 fast / ultrafast 切换”的反馈要求开发。后续明确暂停合入 dev；本功能保留独立分支供本地验收，恢复合入需要 owner 另行说明。

每个会话独立选择 Codex 响应速度。它和模型、推理强度是三个维度；切换速度不新建会话、不清空上下文，下一轮生效。

这里的“下一轮”是下一条用户触发的消息或新任务。正在运行的任务（包括原生 goal 的内部继续）保持原档位，不为了应用设置而中断。

## 范围

- 三档为普通、Fast、Ultrafast，默认普通；没有“跟随群设置”。群主区也是独立会话，不向话题继承。
- 产品和飞书 `/model` 卡在模型 / 推理强度旁显示无边框闪电。普通时只有图标，点开选择后收起；启用时附短标签。
- 产品用小菜单；飞书用原生 Card 2.0 tiny text 按钮，点击后展开一行档位按钮。
- 模型和账号可用档位级联：只显示已确认的加速档位，完全不能加速时不显示入口；选择不支持原档位的新模型时原子恢复普通。
- 不改用户的 Codex 全局配置，不升级套餐、不购买额度、不替换本机正式 App。
- 判断模型、会话标题和云文档评论的独立速度配置不在本次范围。

## 现在的代码

- `agent/codex-appserver/models.ts` 读取原生模型目录。
- `agent/codex-appserver/backend.ts` 发起和恢复 thread、启动 turn。
- `project/registry.ts` 与 `bot/session-store.ts` 保存群和会话选择。
- `protocol/settings.ts`、`admin/settings.ts` 提供网页、CLI 与聊天共用的设置入口。
- `ui/settings/SettingsPanel.tsx`、`GroupDesignSettings.tsx` 与 `card/command-cards.ts` 承载用户操作。

## 怎么改

- 会话保存 `serviceTier: standard | fast | ultrafast`；缺省为普通。旧 project 字段只保留兼容，不再作为继承来源。
- 普通在 Codex RPC 中用 `serviceTier: null` 清除加速；公开 Fast 对应原生 `priority`，Ultrafast 对应 `ultrafast`。
- 不按 `planType: pro` 猜 $500 资格。要求当前 ChatGPT 登录、官方路由、新鲜且绑定账号的原生远端目录，并按 Codex 配置及工作区限制过滤。
- 内置、离线、自定义、旧账号或过期目录不证明权限，不提供加速选项。账号或目录文件变化、目录 TTL 到期时使内存权限快照失效。
- 保存和调度前再次验证能力；模型切换和明确的能力撤销会恢复普通。权限暂时无法确认时隐藏入口并使用普通，不从只读页面访问中擦除用户偏好。
- 会话保存沿用锁、revision 和鉴权。提示加速消耗更多额度，不承诺固定端到端耗时。

## 测试

- 原生 `priority` 和旧 `fast` 元数据映射；没有明确证据时不臆造选项。
- 新建、恢复、下一轮和后台继续时的速度传参；普通能撤销加速。
- 会话互相独立，无群继承。
- 不支持的模型、非 Codex、失效目录、过期 revision 被拒绝。
- 登录、远端缓存来源 / 版本 / 新鲜度、账号变化、工作区禁用和离线快照。
- 网页与卡片的折叠 / 展开、可用档位、未支持模型和模型切换复位。

## Codex 自测

Mac 隔离 worktree 运行定向 daemon、protocol、UI 测试，执行 typecheck 和构建，并用实际组件预览验证可见交互。隔离 CODEX_HOME 对照真实登录和未登录的原生 RPC，并用实际集成代码验证过滤结果。没有指定真实测试群，不主动发送飞书消息。本次没有具备 Ultrafast 的真实账号作为正例，不把模拟选择或传参测试写成真实 Ultrafast 推理验收。

## 文档与验收

更新 `docs/product.md`，权限验证记录放在 `docs/research/2026-10-29-speed-permissions/report.md`。检查结果和未覆盖的真实账号验收记录在 PR。暂停合入 dev，不发布。

验收：不同会话分别选择；默认普通；闪电入口紧凑；档位按实际能力级联；切换保留上下文；回到普通不残留加速；未知权限不假装成功；diff 不含真实 id、凭据或本机路径。

## 风险和行数

主要风险是原生档位的延续语义、恢复会话后旧覆盖残留、目录可用性变化及跨模型组合。用传输测试和设置并发测试覆盖；控制实现与定向测试总改动约 1,000–1,500 行。
