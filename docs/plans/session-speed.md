# 会话与群默认响应速度

## 做什么

owner 2026-10-29 根据用户“分会话 fast / ultrafast 切换”的反馈要求设计、开发并合入 dev；main 与下一版本发布由 owner 统一处理。

群和会话可以独立选择 Codex 响应速度。它和模型、推理强度是三个维度；切换速度不新建会话、不清空上下文，下一轮生效。

这里的“下一轮”是下一条用户触发的消息或新任务。正在运行的任务（包括原生 goal 的内部继续）保持原档位，不为了应用设置而中断。

## 范围

- 群设置的“响应速度”：跟随 Codex、Standard、Fast、Ultrafast。
- 话题设置和飞书 `/model` 卡：跟随群设置、Standard、Fast、Ultrafast。
- 跟随群设置的已有会话，下一轮采用群的新设置；单独覆盖的会话不受影响。
- 只给 Codex 提供速度控件。加速能力来自实际模型目录，不能凭模型名字推断可用性。
- 不改用户的 Codex 全局配置，不升级套餐、不购买额度、不替换本机正式 App。
- 判断模型、会话标题和云文档评论的独立速度配置不在本次范围。

## 现在的代码

- `agent/codex-appserver/models.ts` 读取原生模型目录。
- `agent/codex-appserver/backend.ts` 发起和恢复 thread、启动 turn。
- `project/registry.ts` 与 `bot/session-store.ts` 保存群和会话选择。
- `protocol/settings.ts`、`admin/settings.ts` 提供网页、CLI 与聊天共用的设置入口。
- `ui/settings/SettingsPanel.tsx`、`GroupDesignSettings.tsx` 与 `card/command-cards.ts` 承载用户操作。

## 怎么改

- 保存 `serviceTier: standard | fast | ultrafast`；缺省表示继承。兼容旧数据，未配置时维持原生 Codex 默认。
- 会话覆盖优先于群，群优先于 Codex 默认；每轮重新读取最新值。
- Standard 在 Codex RPC 中用 `serviceTier: null` 清除加速；Fast、Ultrafast 用原生字符串。
- 从覆盖改回继承时，必须显式恢复群或原生默认；不能因为省略字段而继续用上轮的 Ultrafast。
- Fast、Ultrafast 保存前验证当前后端、模型和可信目录。不支持时说明原因，不能静默换模型或换速度。
- 模型切换后不能保留一个明知不支持的加速组合；提示先改为普通。
- 群和会话的速度设置使用原有保存锁、revision 和鉴权；继承时真正删除覆盖字段。
- UI 保留已保存但当前不可用的档位，并提供回到继承或普通的出口。提示加速档位消耗更多额度，不承诺固定端到端耗时。

## 测试

- 目录的新旧速度元数据映射，目录没有公布时不臆造选项。
- 新建、恢复、下一轮和后台继续时的速度传参；普通与恢复继承都能撤销加速。
- 两个会话的覆盖相互独立；群默认只影响继承者。
- 不支持的模型、非 Codex、失效目录、过期 revision 被拒绝。
- 保存、重读和恢复继承后的落盘值；模型保存保持速度组合有效。
- 网页和飞书卡片的可选、不可用、已保存和继承状态。

## Codex 自测

Mac 隔离 worktree 运行定向 daemon、protocol、UI 测试，执行 typecheck 和构建，并用独立预览验证可见交互。没有指定真实测试群，不主动发送飞书消息。本次不测用户账号实际 Ultrafast 推理速度，不能把模拟选择和传参测试写成真实加速验收。

## 文档与验收

更新 `docs/product.md` 的后端设置说明。实现结果、运行过的检查和未覆盖的真实账号验收记录在 PR。合入 dev，不发布。

验收：不同群、话题可分别选择；切换保留上下文；下一轮使用已保存档位；回到继承和普通均不残留加速；不可用不假装成功；diff 不含真实 id、凭据或本机路径。

## 风险和行数

主要风险是原生档位的延续语义、恢复会话后旧覆盖残留、目录可用性变化及跨模型组合。用传输测试和设置并发测试覆盖；控制实现与定向测试总改动约 1,000–1,500 行。
