# Native community

## 1. 做什么

在桌面应用内浏览社区、获取配方、查看已获取和管理自己的私人草稿与发布版本。社区归属于当前窗口的账号，不依赖所选设备在线。

## 2. 范围

实现目录搜索及每次八项加载、公开/凭码详情、获取与账号库、创作中心草稿列表/详情/编辑/删除/发布、发布记录与批量一次性分享码。当前云快照只支持角色和 setup，其他配置字段诚实显示未指定或空态。群内准备、安装和运行隔离由并行片实现。公共详情不出现发布管理。

## 3. 现在的代码

`account-session.ts` 持有令牌并提供固定 API origin 的已登录请求。`bridge.ts` 和 `facade.ts` 提供类型化主进程边界。`DesktopRoot.tsx` 的账号 provider 高于设备门禁。`LocalShell.tsx` 原导航是此刻/Bot/群组。已有云服务支持目录、版本、草稿、发布、获取、账号库和分享码。

## 4. 怎么改

新增 protocol 的严格请求与响应 schema 和命名 community shell。主进程将操作映射为固定 API 路径/方法，不暴露任意 URL、headers 或 token。匿名仅允许目录和详情。响应限制体积并严格校验；请求完成及响应读取后复查账号代次。写请求携带独立幂等键和草稿 revision。UI 以路由联合类型组织目录、详情、账号库、私人工作区和编辑器；账号变化立即重建私人状态，迟到响应不得回写。社区 provider 在设备门禁之上，离线连接页保留入口。安装只在并行片提供真实能力后接入。

## 5. 测试

主进程测试匿名路由、固定路径、拒绝未知字段/响应 token、错误脱敏、换号/退出后迟到响应、幂等键与 revision。UI 测试导航位置、公共详情无管理入口、凭码隐藏配置、账号变化清理、分页合并去重、写入回执与发布确认。

## 6. Codex 的自测

Mac 隔离 worktree 运行 protocol/desktop/UI 构建、类型检查及针对性测试，不访问 owner 数据、不启动真实服务、不发飞书消息。实际浏览器和真实云联调由集成负责人统一验收，此片不把静态渲染当作真实服务通过。

## 7. 文档

遵循 `docs/design/accounts-recipes/prd.md` 的导航、获取、创作、分享码语义。该设计文档是本批行为依据。无需改变默认设置。

## 8. 验收要点

导航此刻/社区/Bot/群组，原入群入口位置不变。无虚构目录、分类、热度或免费标签。公共详情与私人管理路由分开。凭码未获取不返回/呈现配置。获取不表示已安装。分享复制以实际回执显示已复制。草稿并发冲突保留输入；发布必须确认且以云回执为准。diff 不含真实 ID、密钥或本机路径。

## 9. 风险和行数

预估 2000–3500 行，按 protocol/主进程边界与原生 UI 分模块审查。风险是账号切换后的异步响应、云响应漂移及重复写入，分别由代次校验、严格 schema 和稳定幂等键覆盖。无推送、PR、合入或发布授权。
