# s28c：响应成员从群里选；建议都开智能

## 1. 做什么
网页和私聊设置卡能从群成员（包括 Bot）添加响应成员；多 Bot 群的绑定表单和群详情提示建议都开智能。依赖 s27a（#424）已合入。

## 2. 范围
只改选择与提示。已有响应名单、管理员豁免、权限校验和响应判断保持原有语义。不做 u09 重构、不自动切智能、不扩大飞书权限。

## 3. 现在的代码
- `bot/handle-message.ts` 的 `roster`：本 Bot 的群 Bot 名册，member_id 与响应名单使用同一 open_id。
- `bot/bot-roster.ts`：有界首页、3 秒超时，成功缓存十分钟，失败一分钟后重试；出站 guard 允许保留旧快照。
- `bot/names.ts` 的 `fetchChatMembers`：只读真人首页，失败降级手填，也被管理员选择器使用，不全局改它。
- `admin/settings.ts` 项目视图只有已保存的成员 ID；网页 `settings/SettingsPanel.tsx` 手填 ID。
- `card/dm-cards.ts` 的 `buildAddAllowedCard` 只列真人，最多五十项，其余手填。
- `project/pending-groups.ts`、`admin/groups.ts` 和 `JoinGroupDialog.tsx` 负责未绑定群；`management/ProjectPanel.tsx` 负责会话方式。

## 4. 怎么改
- 在 protocol 定义可选 `members.roster`：状态 complete / partial / unavailable，候选 entries（openId、name、person/bot）和已观察到其他 Bot 的标志。旧 daemon 缺字段时照常支持手填。
- 新增 `readResponseRoster`，并行读取真人首页与既有 Bot roster。真人和 Bot 都指定 open_id，三秒超时；不读通讯录、不读其他 Bot 的文件。按 ID 去重，Bot 优先，名册缺页或一个来源失败标 partial，两个都失败标 unavailable。
- Bot roster 新增 selection 只返回最近一次成功读取对应快照；失败刷新不得将旧名册冒充新名册。既有出站 guard 的 stale 行为不变，重试仍遵循原有一分钟退避。
- 网页候选与私聊卡显示名称、Bot 标记及 ID 尾段，区分同名候选。无名成员显示“未命名成员/Bot”。既有名单中本次未读到的 ID 继续保留，可移除；名册从不替换响应名单。私聊卡列最多五十项，Bot 在前，其余保留手填。读取失败或不全时说明现有名单不受影响，检查群读取权限后重开/重新读取重试。
- 网页仍用现有带 revision 的增删动作，私聊沿用现有管理员检查和函数式更新，离线只读不开放写入口。
- `hasOtherBots?` 随待绑定群/已加入群的只读结果传到绑定表单。群详情读取项目设置的 roster。仅在成功观察到其他 Bot 时显示 product 3.4 的原文：“群里还有别的 bot。几个 bot 都选智能，它们才能互相 @、各自判断接不接话。”未知不提示，选智能照常提示，不改变选择。
- 所有读取有界；关机通过既有 orStop 截断，名册读取无磁盘写入。权限失败仅降级，不影响设置读取或名单。

## 5. 测试
- main 必败：真人与 Bot 合并，同名显示与 Bot 标记，按 open_id 去重。
- main 必败：Bot 首页不完整、真人失败、Bot 失败和全部失败的状态；过期 Bot 刷新失败不提供旧候选。
- main 必败：网页已有名单保留、候选添加走原动作、只读禁用、旧 daemon 无字段手填继续可用。
- main 必败：私聊候选含 Bot，超过五十与失败提示不谎称完整。
- main 必败：已知多 Bot 显示精确提示，未知和单 Bot 不显示；选择智能不隐藏提示。
- 回归：bot-roster、names、settings-owner、settings-parity、admin-groups、pending-groups 与网页相关测试。

## 6. Codex 的自测
交 JP-VPS。用 #422 的 Bot 6/7/8 及 `test-chats.json` 记录中已经绑定的专用测试群，测试程序只在内存读取标识，不输出真实 ID/群名，不查其他群，不发消息。
1. 真实飞书只读名册：通过现有测试 Bot 的 channel 读取该群真人与 Bot 名册，输出状态和数量，确认包含 Bot。lark-cli 如需核对仅 `--profile jojo --as user` 的测试群成员读取，不做群写操作。
2. 验收 daemon 升级前拿目录锁，检查取消，停止并备份，再切本片 head 构建、启动；结束报告其 sha 和运行状态。
3. 应用 verify skill 的已有真实浏览器控制，在网页群详情展开成员设置，观察 Bot 候选、现有名单、添加/移除与建议文案。优先使用现成浏览器工具，不写 Playwright 脚本。用现有 capture/doctor 保留证据。缺少可用浏览器控制就据实报告，不能以内部 RPC 冒充网页验收。
4. 私聊卡用定向结构测试；没有授权私聊真实发送的验收步骤不发送。

## 7. 文档
更新 v1-plan 的 s28c 勾选与做法，先不填 PR 号。产品 3.4 已有行为，不改产品决定；默认值不变。

## 8. 验收要点
- 真人和群 Bot 可选，ID 与 s27a 名单比较一致；权限与响应逻辑不变。
- 名册失败、部分结果、重复姓名和已不在名册的保存成员均可解释，不清空名单。
- 只读禁写，动作仍走已有 revision/管理员校验。
- 三个入口提示精确，未知不提示，不预选智能。
- diff 没有真实 ID、密钥、本机路径。
- 构建、typecheck、lint、定向测试通过，真飞书和网页结果单列。

## 9. 风险和行数
错误路径：失败不提供过期名册，不改响应名单；读取超时或停机不阻塞关闭。预计约 700–1000 行（含测试与本文），上限 1500，不含 lockfile/generated，超限先拆。
