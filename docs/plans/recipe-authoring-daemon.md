# 私聊制作文字配方草稿

## 1. 做什么

作者在已登录的 App 核对群角色并关联自己的飞书私聊。所选 Bot 主动发送确认卡。点击生成后，云端保存一份私人草稿。作者可以在同一私聊提交文字修改并确认保存。

## 2. 范围

源数据是一个已绑定群的补充职责和作者填写的 setup。编辑支持公开名称、简介、概览、版本文字、角色与 setup。App 主进程负责账号验证和申请云票据。富内容、自动发布和自然语言识别由其他切片负责。

## 3. 现有入口

实际 Bot 进程持有飞书 SDK 和当前管理员配置。主进程通过 owner RPC 和 host→Bot IPC 选择正确的运行实例。私聊入口在 ask 的准确回复之后、普通私聊会话之前消费配方指令。已有的云端协议见 [在线私人草稿操作契约](../design/accounts-recipes/authoring-operations.md)。

## 4. 实现

设备端以账号、设备身份与公钥、Bot 注册实例确定作用域。App 启动挑战，当前管理员在真实私聊发送 `/recipe link <code>`，App 在原连接上读取收件人和证据摘要，再确认建立关联。挑战只在内存驻留五分钟，最多尝试五次，保存的是随机码摘要。重新关联生成新的绑定。断线、超时和退出暂停新的正向操作。

来源预览和冻结分别读取所选绑定，核对群成员资格、有效角色、绑定代次、设置修订和已安装来源。身份关联、已审来源、操作、提案和卡片状态保存在数据根的独立 journal。Bot 删除不删除 journal。不同进程通过数据根下的专用目录互斥更新，文件与父目录持久化以后才派发下一步。

每次操作先持久化 X25519 临时密钥、随机 nonce 和 UUIDv7。App 以原账号登记，daemon 提交 dispatch 证明并取得回执。发送时分步记录卡片实体、消息 UUID、首次发送时间和消息 ID。正常回复必须给出相同物理私聊。提前回调或结果丢失时，通过读取消息和 CardKit idConvert 验证对应关系。

已确认后只为规范候选字节申请 accept。卡片仅展示固定文案和动作引用。App 可在点击前查看候选补丁，点击后取得相同字节和摘要。保留的云端回执指向原 draftId 和 revision。取消等待云仲裁，若接受先完成，客户端显示已保存。

## 5. 测试

测试覆盖实际私聊入口和卡片分发器，合成 SDK 通过本机 HTTP 发送卡片。断网、过期重发和错收件人不能改变已有草稿。改回旧角色仍以修订判断来源变化。摘要、凭据形状与云服务共享校验，测试向量另行核对证明字节。

## 6. 自测方法

在 Mac 隔离 worktree 构建 protocol、client、daemon。运行 daemon 的 `recipe-authoring.test.ts`、原私聊、RPC 权限与 CLI 对照测试。安装 recipe-api 依赖并设置 PostgreSQL 15 的 `PG_BINDIR`，运行 `node packages/daemon/test/fixtures/run-authoring-pg.mjs` 可用临时数据库和合成签发者重复完整的创建、编辑测试。飞书服务和收件人均为本机测试替身。

## 7. 文档

账号配方设计中的 [私聊交互](../design/accounts-recipes/chat-drafts.md)、[运行时](../design/accounts-recipes/runtime.md) 与[预算](../design/accounts-recipes/limits.md) 是字段、状态和限额的来源。此切片不增加 v1 已有配置的产品默认值。

## 8. 验收要点

- 从 App 核对来源、在本人私聊确认并保存；两端显示相同的私人草稿和修订。
- 修改正文、在 App 核对候选，再在原卡确认。旧提案、错误私聊、移除管理员及过期上下文无法接受。
- 网络结果不明时复用原操作与消息 UUID；过了上游去重期只能明确重发。旧卡立即失效。
- IM 不携带源群名、职责正文、setup、记忆或敏感路径。云只收本次允许的字段。diff 不含真实凭据、收件人和本机路径。

## 9. 风险和行数

本片约 1,300 行，按身份与来源、持久化与发送、云证明与本地编排、真实边界测试分开审查。上游消息 UUID 一小时内至多发送一次。自动重试使用 55 分钟窗口，给处理与网络延时留余量。[官方 SDK 的 uuid 说明](https://larksuite.github.io/oapi-sdk-java/com/lark/oapi/service/im/v1/model/CreateMessageReqBody.Builder.html)
