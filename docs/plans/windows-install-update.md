# Windows 安装和应用内更新

## 1. 做什么

owner 2026-10-30 已认可 `docs/research/2026-10-30-windows-install-update/report.md` 的方案并要求实施。Windows 不采购 Authenticode 证书，首次简短安装向导允许改路径，后续在应用里下载、验证、安装并重启。官网只主推 Setup，停止新增 Windows ZIP。

## 2. 范围

桌面更新、公钥配置、签名清单、现有 NSIS 与发布链路、更新进度、官网交接。保持当前用户安装和旧版本数据兼容。Mac 更新机制及两平台统一版本规则不变。只开发、测试和交付验收，不公开发布或切 stable。

## 3. 当前实现

`windows-updates.ts` 在检查前及安装前强制 Authenticode；`build.mjs` 默认空 Windows 更新配置。NSIS 一键安装；构建和发布脚本假设 EXE/ZIP 都存在、更新关闭。界面已有检查/下载/安装阶段，缺少实际百分比。

## 4. 怎么改

- 共享 `windows-update-manifest.mjs` 验证 Ed25519：签名覆盖原始 JSON UTF-8 字节，清单严格绑定产品、版本、架构、固定版本化 EXE URL、尺寸与 SHA-512，可包含纯文本更新说明。公钥随应用内置，私钥仅放外部发布配置指向的文件中。
- 自定义 electron-updater provider 只返回从签名清单解出的元数据；不再次读取未验证 YAML。x64/ARM64 分别使用 `stable/<arch>/update.json`。保留 updater 独立网络分区的 HTTPS/域名/路径限制。
- 下载和安装前分别核对最终 EXE 的尺寸/哈希；检查、下载、安装各自去重。校验失败不停止 daemon；状态文件写入成功后才调用原有停机清理。取消安装确认不退出；安装未生效继续提供重试。
- 升级状态沿原桥推送实测百分比和已签名更新说明。安装前显示连接/任务可能中断的提示及“稍后”。现有快照没有对话执行状态，因此本片显示通用中断提示，不猜测正在运行的任务数。
- NSIS assisted 模式只提供当前用户安装，路径必须可写；升级用 `--updated` 跳过选择并按 `--force-run` 重新打开。保持原卸载兼容 hook，不删除用户数据。
- 新 format2 inventory 只要求 EXE/blockmap/feed，绑定内置公钥及更新能力；历史 ZIP/manual inventory 仍可读取。新签名 JSON 在本地发布计划阶段生成，在原 owner 审阅和确认后的 stable 阶段才提升；公开 EXE 先全量复核，feed 最后提升并保存独立回执。官网只有匹配的成功回执才宣告应用内更新可用。

## 5. 测试

清单改字节、错钥、错架构、元数据替换、缓存 EXE 同尺寸篡改、安装前篡改均拒绝；并发操作去重；真实进度及异常数值；安装记录与重试。发布签名、对象摘要、旧产物续跑、stable 快照变化、取消和中断恢复。真实 NSIS 编译及 Windows 连续升级另验，模拟结果不能代替。

## 6. Codex 自测

Mac 负责隔离构建、类型检查和自动化测试。按 owner 本轮新指示，Windows 虚拟机内的安装/升级/界面验收交给虚拟机上的 Codex，owner 转发固定 SHA、命令与验收清单；本会话不继续操作虚拟机界面。使用独立 AppId、测试签名密钥、数据目录和缓存验证 A→B→C，避免覆盖默认安装。此片不发送飞书消息。

## 7. 文档

更新产品的安装与更新约定、v1-plan 追加当前实施状态，以及 Windows 发布文档的签名/ZIP/feed 说明。用户需要从旧 0.7.8 手动覆盖安装一次；不能靠服务器解除旧版的本地更新禁用。

## 8. 验收要点

用户不配置密钥、不导入证书、不更改系统安全设置。首次路径可改；后续沿原路径升级；数据哨兵保留；失败可重试；受系统安全策略阻止时如实说明。源码不含真实凭据、设备/群标识或本机路径；公钥可以公开。未进行真实 Windows 验收时明确标为待验收，不宣称完成。

## 9. 风险和行数

更新执行文件与发布入口属于高风险路径，需独立安全审查。预计 Bot 仓库非生成 diff 约 1,100–1,400 行；网站独立 PR。若超限，验收工具拆成独立 PR。无公开发布授权，不把本次方案认可当作具体安装包已验收或 stable 确认。
