# 添加群聊与默认决策模型

## 做什么与范围

owner 已认可添加/连接群聊预览，要求前后端一致，并补充设置中的默认决策模型。按 product.md 3.1–3.4 实现；不改旧群的显式选择，不移除内部项目数据模型。

## 现在的代码

`JoinGroupDialog` 原本包含项目复用、系统目录选择和逐群决策 Provider；`DecisionProviderSettings` 仅管理每家模型配置，`initial-settings` 根据旧 Bot/后端推导判断模型。网页目录接口已有目录边界与短期选择 token。

## 怎么改

- 添加/连接弹窗删除项目行，统一“沟通方式”，目录搜索作为同一弹窗内的步骤，选择成功返回表单。
- `directory.suggest` 支持名称、绝对路径、`~/`、子目录与键盘选择。限制扫描数量、深度和耗时；不跟随符号链接递归，保留 canonical home 边界及 token 复核。
- Host judge 添加可选 `defaultProvider`，缺省稳定为 Codex；UI 同时展示对应模型。保存 profile 不丢失默认选择，旧客户端提交保留已有默认值。
- 新群保存显式 default 标记；仅智能模式在创建/连接/启用前验证默认模型可用性。运行时跟随全局设置，不按可用性静默切换。
- 旧数据继续原继承规则；`judgeInheritsHostDefault` 区分全局默认与历史缺省，使群设置可明确改回默认。
- 页面重开、重试后拒绝旧异步响应；目录失败保留输入，提供重试；创建结果不明沿用现有防重复锁。

## 测试与 Codex 自测

Mac 本地：UI 全套、daemon 定向测试、protocol、全 workspace typecheck/build；网页控制验证弹窗、目录搜索、错误态和默认模型展示。测试覆盖主目录边界、搜索截断、过期 token、跨 Provider 默认变化、无 key/不可用服务、旧配置兼容及重开竞态。未指定真实飞书测试群，不发送消息或创建真实群聊。App 更新后再核对 UI 与后端产物。

## 文档与验收要点

更新 product.md 3.1/3.2 与 v1-plan.md 当前桌面验收约定；本次验收和合入另记，不提前宣称已合入。

- 添加/连接界面没有项目复用和决策模型二次选择；三档沟通方式与群设置一致。
- 桌面和远程网页都浏览 daemon 主机目录；不用系统文件弹窗。
- 设置默认值、创建/连接校验及真实判断使用同一配置；群可覆盖，旧群不被静默迁移。
- diff 无真实 Bot/群 id、密钥或用户主目录路径。

## 风险和行数

含实际挂载目录超时回归后，按两片提交：先是目录 RPC、组件及测试，再是建群与全局默认模型贯通；后续 PR 分片保持各自低于 1,500 行。本地 App 将两片一起供 owner 验收。风险是旧数据继承、异步过期响应、默认 Provider 不可用以及目录边界，均由针对性测试覆盖。实际 owner 验收、远端合入及真实飞书运行状态分开报告。
