# 添加群聊与默认决策模型

## 做什么与范围

owner 已认可添加/连接群聊预览，要求前后端一致，并补充设置中的默认决策模型。按 product.md 3.1–3.4 实现；不改旧群的显式选择，不移除内部项目数据模型。

## 现在的代码

`JoinGroupDialog` 原本包含项目复用、系统目录选择和逐群决策 Provider；`DecisionProviderSettings` 仅管理每家模型配置，`initial-settings` 根据旧 Bot/后端推导判断模型。网页目录接口已有目录边界与短期选择 token。

## 怎么改

- 添加/连接弹窗删除项目行，统一“沟通方式”，目录搜索作为同一弹窗内的步骤，选择成功返回表单。
- `directory.suggest` 支持名称、绝对路径、`~/`、子目录与键盘选择。限制扫描数量、深度和耗时；不跟随符号链接递归，保留 canonical home 边界及 token 复核。目录建议在独立子进程中读取并受硬超时约束，避免 macOS 受保护目录的挂起读取占用 daemon 线程或阻止退出；名称发现不隐式递归个人受保护目录，显式输入仍可尝试读取。
- Host judge 添加可选 `defaultProvider`，缺省稳定为 Codex；UI 同时展示对应模型。保存 profile 不丢失默认选择，旧客户端提交保留已有默认值。
- 新群创建时保存完整默认值快照，包含 Provider、模型、Effort；后续与全局变更独立，仅智能模式在创建/连接/启用前校验可用性。不按可用性静默切换。
- 旧完整值保留；旧 default/provider 引用在全局变更前固化其实际生效值。旧 Bot 缺省与未知配置保留兼容，不重建不可知的创建历史。群页面直接显示完整有效值，不提供跟随或恢复全局默认。
- 页面重开、重试后拒绝旧异步响应；目录失败保留输入，提供重试；创建结果不明沿用现有防重复锁。
