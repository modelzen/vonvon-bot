### 4.2 运行状态（`D/card/run-state.ts`、`D/card/run-render.ts`、`D/agent/types.ts`）

- `SubagentRow` 加三个字段：
  ```ts
  stepCount: number;   // 一共开始过几步；steps 只留最近 5 步，省略数 = stepCount - steps.length
  startedAt: number;   // 收到 subagent_start 的时间
  endedAt?: number;    // 进终态的时间；又回到 running（续跑）时清掉
  ```
- `RunState` 加 `awaitingSubagents?: true`。
- `AgentEvent` 加 `| { type: 'awaiting_subagents' }`；`ask` 改成 `{ type: 'ask'; request: AskRequest; subagentId?: string }`。全仓库 `switch (ev.type)` 有穷举检查的地方都补上新类型（`grep -rn "case 'subagent_status'" packages/daemon/src`）。
- `reduce(state, evt, now = Date.now())`：
  - `subagent_start`：新行 `stepCount: 0, startedAt: now`；
  - `subagent_step` 新的 running 步：`stepCount + 1`，步骤列表照旧留最近 5 步；
  - `subagent_status` 终态：`endedAt: row.endedAt ?? now`；从 completed 回到 running：清 `endedAt`，`startedAt` 不变；
  - `awaiting_subagents`：`{ ...state, awaitingSubagents: true, footer: null }`，`terminal` 不变；
  - `closeSubagents(state, status, now)` 收行时一起写 `endedAt`；`markInterrupted`、`markIdleTimeout`、`finalizeIfRunning` 和 `error` 分支都传 `now`。
- `RunRender`：`apply` 传 `Date.now()`；加 `seedSubagents(rows: SubagentRow[]): void`，当前没有行时才放进去（给 4.8 用）。

### 4.3 Codex：子 agent 都收口才出 `done`（`D/agent/codex-appserver/backend.ts`）

`docs/product.md` 3.9："子 agent 都跑完了，这张卡才算结束"。Claude 打开变量后天然如此（父回合等前台子 agent）。Codex 的父 agent 可以不 wait 就结束回合（`docs/v1-plan.md`"s34a 探测"：父停了子还在跑），所以在后端里等，`AgentRun` 的约定写成：`events` 的 `done` 在本线程所有 running 的子 agent 收口后才出；父回合先完成时先出一个 `awaiting_subagents`。

- `CodexThread` 加：
  - `private parentDoneTurnId?: string`：父回合已完成、还在等子 agent 时是父回合的 id；
  - `private runningChildren(): number`：`children` 里 `running` 为真的个数（含还没开始回合的，含以前回合留下、又被 `sendInput`/`resumeAgent` 叫起来的）。
- `runStreamed` 的 `gen`，`for (const ev of routed)` 里：
  ```ts
  if (ev.type === 'done' && !deferred && self.runningChildren() > 0) {
    deferred = ev;                         // 先不出
    activeTurnId = undefined;              // turnId() 为空：插话改排队（3.4 的 2434）
    self.parentDoneTurnId = result.turnId; // abort 不再停已经完成的父回合
    requests.finishTurn(result.turnId);    // 父回合的待答按没人回答
    yield { type: 'awaiting_subagents' };
    continue;
  }
  ```
  致命 `error` 照旧马上出并返回。每处理完一批 `routed`：`if (deferred && self.runningChildren() === 0) { requests.close(); yield deferred; return; }`。
- 等的时候子线程的通知照旧刷新 `lastActivityAt`，看门狗照常（4.9）。
- `finally` 里加 `self.parentDoneTurnId = undefined`。事件流在等的时候断了（app-server 退出、`close`），不补 `done`，由主循环按今天的"没 done 就结束"处理。
- `abort(turnId)`：`const parentLive = turnId !== this.parentDoneTurnId`；`parentLive` 才 `cancelRequests` 和对父回合发 `turn/interrupt`；子线程照旧全停。父没发请求时不抛错。
- `runGoal` 不做这个等待：目标模式由 Codex 自己接着开下一轮，等不住，见 4.8。

### 4.4 Codex：子线程的提问（`server-requests.ts`、`jsonrpc.ts`、`backend.ts`）

- `CodexRequestScope` 构造加第二个参数 `childTurn: (threadId: string) => string | undefined = () => undefined`，返回登记过、`running` 为真的子线程当前的 `turnId`。`openRequestScope(threadId, childTurn?)` 透传。`runStreamed`、`runGoal` 开范围时传 `id => { const c = self.children.get(id); return c?.running ? c.turnId : undefined; }`。
- `add` 只看 `closed`，不再看线程：请求到达时，排在它前面的子线程登记通知可能还没被 `gen` 处理，这时判"不是我的"会误杀子 agent 的提问。线程在 `accepts` 里判，那时前面的通知都处理完了。
- `accepts(question, turnId)`：父线程比 `turnId`；子线程比 `childTurn(question.threadId)`，对得上返回 true；都对不上照旧 `respond` 空答案、返回 false。不认识的线程到这里被回空答案，和今天的结果一样，只是晚到 `gen` 读到它的时候。
- 加 `finishThread(threadId): string[]`：把这个线程还挂着的提问都按没人回答回掉，返回它们的 `request.id`。
- `gen` 里：
  - 接受的提问，线程不是父线程的，出 `{ type: 'ask', request, subagentId: question.threadId }`；
  - 处理到某个子的终态 `subagent_status` 时，先 `for (const id of requests.finishThread(ev.id)) yield { type: 'ask_cancelled', requestId: id }`，再出这条状态。卡由提问协调器的 `cancel` 收成"暂时无法回答"。

     - 行头：`{图标} {名字前 20 字}：{任务前 40 字} · {stepCount} 步 · {时长}{后缀}`。图标：running 🔄、completed ✅、failed ❌、stopped ⏹；卡已收尾（`terminal !== 'running'`）而行还是 running 的用 ⚠️。时长 = `(endedAt ?? now) - startedAt`，用 `formatElapsed`（从 `run-process.ts` 导出）。后缀按顺序取第一个：`waiting` 指向这一行 → ` · ⏸ 等 张三 回答（见下方卡片）`（就是协调器给的那句）；failed → ` · 失败`；stopped → ` · 已停止`；卡已收尾而行是 running → ` · 没收到结束消息`；`carried` 且行是 running → ` · 接着显示在下一张卡`。收起时这些都在行头上，所以折叠后仍看得到待回答、失败和停止（3.9 第二条）。
     - 正文第一段：省略数大于 0 时先一行 `前面还有 K 步`，再每步一行 `{✅|❌|🔄} {标题前 60 字}`；没有步骤写 `还没有步骤`。
     - 有 `result` 时第二段 `**结果**` 加结果（s34a 已截到 600 字）。
     - 按钮只在 `cardKey` 有、`running` 为真、行是 running、`stoppable` 为真时画。
     - 缩进：沿 `parentId` 在行里往上数层数，最多 3 层，每层 16px；`parentId` 有但找不到这一行的算 1 层。
  3. 行数超过 `SUBAGENT_FULL_ROWS`：先挑完整显示的 8 行，次序是：`waiting` 指向的那一行（等回答的一定完整显示，后缀和按钮都在）、在跑的、失败和停止的、已完成的，同一类按开始的先后；挑出的 8 行按开始先后画。其余的放进一个 `collapsible_panel`（`element_id` `sa_more`，`expanded false`，标题 `另有 N 个子 agent`）：
     - 每个溢出的在跑行一个 markdown 行 `{图标} {名字前 20 字}：{任务前 20 字} · {stepCount} 步{后缀}`（后缀同完整行，`waiting` 指向它时也写 ⏸），后面跟一个停止按钮，样式和 value 同完整行，`element_id` 是 `so_` 加同样的 12 位十六进制，`e` 也是它。按钮的条件同完整行。在跑的子 agent 每个都能在卡上单停（3.9）。
     - 溢出的在跑行超过 `SUBAGENT_OVERFLOW_STOP_ROWS` 个时，多出来的只写一行 `另有 K 个在跑，卡片放不下停止按钮：⏹ 停整轮，或到网页端单停`，日志 `subagent-rows-capped { shown, hidden }`。同时在跑 32 个以上子 agent 才会走到这里。
     - 失败、停止的每个一行 `{图标} {名字}：{任务前 20 字} · {stepCount} 步`，已完成的只写 `另有 K 个已完成`；这几行没有按钮，合成一个 markdown。
     - 在跑和等回答的子 agent 一个都不藏（3.9 第二条）。
- `components` 数：总述 1；每个完整行 = 面板 1 + 步骤 1 + 结果 0 或 1 + 按钮 0 或 1；溢出面板 1，加每个溢出的在跑行 2（markdown 和按钮），加没按钮的那段 0 或 1，加"放不下"那行 0 或 1。最多 1 + 8×4 + 1 + 24×2 + 1 = 83，在 `PROCESS_COMPONENT_BUDGET`（120）以内。
- `run-card.ts`：
  - `RunCardState` 加 `askWaitingSubagentId?: string`、`subagentsCarried?: true`。
  - `renderRunning`：过程面板（或用时那一行）之后、回答之前插子 agent 区；`buildProcessBody` 的预算改成 `PROCESS_COMPONENT_BUDGET - section.components`。页脚：`askWaiting` 照旧优先；否则 `state.awaitingSubagents` 时写 `⏳ 主回合已答完，等 N 个子 agent 结束`（N = running 的行数），代替 `footerStatus`。

### 4.7 主循环（`handle-message.ts`）

### 4.9 并发和交错

| 情况 | 结果 |
| --- | --- |
| Codex 父回合完成，子还在跑 | 出 `awaiting_subagents`，卡留在运行态，页脚"主回合已答完，等 N 个子 agent 结束"；⏹ 和每行停止照常；`turnId()` 为空，群里的新消息排队（3.9"插话或排队"，父回合已经没有可插的回合），等这张卡收尾再跑；最后一个子收口后出 `done`，卡收尾 |
| 等子 agent 时子都不出声 | 子的通知刷新看门狗；超过空闲阈值走今天的超时路（杀进程恢复），running 的行收成已停止，卡写"⏱ … 没有输出，已自动停止" |
| 等子 agent 时按 ⏹ | `abort` 用回退的 turnId，只停子；子收口后出 `done`，卡"⏹ 已被中断"，进程留用；5 秒没收尾照旧强停 |
| 单停和这个子自己结束撞上 | 先到的终态为准（`reduce` 里 stopped、failed 不再改）；停的请求失败而行已不是 running，不回话（4.7） |
| 单停后马上 ⏹ | `abort` 对这个子再发一次 interrupt，失败只记 warn（s34a）；行的状态以先到的为准 |
| ⏹ 后再点单停 | 卡已收尾的按钮已经没了；旧画面上点到，`runsByCard` 没了走 `healDeadRunCard`；还在 5 秒收尾窗口里，`stopSubagent` 成功或拒绝"已经结束"，拒绝时行已不是 running，不回话 |
| 单停一个还没开始回合的子 | 照 s34b 拒绝"这个子 agent 还没开始回合"并回话 |
| 子 agent 的提问在等时，这个子结束或被单停 | `finishThread` 回掉它的提问，出 `ask_cancelled`，提问卡收成"暂时无法回答"，行头的"等回答"去掉 |
| 子 agent 的提问在等时按 ⏹ | 照 s30：`askTurn.close('stopped')`，卡"⏹ 已停止"；Codex 那边由 `requests.close()` 回空答案 |
| 父回合等子时，父还有待答 | `finishTurn(父)` 按没人回答回掉（父已完成，不该有，兜底） |
| Claude 的 `result` 到时还有 running 的行（打开变量后不该有） | 不等（`result` 之后 sink 已清，等不到）；收尾的卡上这一行写"没收到结束消息" |
| 插话分卡 | 旧卡一行"子 agent（N 个）接着显示在下一张卡"，新卡带全部行和按钮 |

### 4.10 停机

- `shutdown()`（`7754`）的顺序不变：`asks.shutdown()` 把所有提问卡收成"⏹ 已停止"，再对每个回合 `state.interrupt()`，再关进程。
- 等子 agent 的回合：`state.interrupt()` 按上表"等子 agent 时按 ⏹"走；进程先被关掉的，事件流断了，没有 `done`，`settleOrdinaryTurnRender` 按"被中断"收尾，`markInterrupted` 把 running 的行收成已停止，卡收尾不带按钮。`gen` 的 `finally` 清 `parentDoneTurnId`、关请求范围。
- 后台服务崩了、没走停机的旧卡：上面的行按钮点了按 4.7 自愈。

### 4.11 要 owner 定的

没有。8 行上限、步骤跟每秒时钟刷、等子 agent 时新消息排队、"没收到结束消息"这几句、⏹ 停不停得下来的判定，是 Claude 定的，写进第 7 节的默认值。

## 8. 验收要点

- Claude 会话（新开和续上）的环境里 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`，盖得住进程环境里的别的值；辅助查询不变。
