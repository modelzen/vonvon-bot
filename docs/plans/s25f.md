## 4. 怎么改

### 4.1 导出：`D/bot/attention.ts`（新）

```ts
import type { JudgeResult } from '../judge/types';

export interface AttentionParams {
  places: number;                 // 最多记几个位置
  intervalsMs: readonly number[]; // 留意的间隔，从短到长
  exitIntervalMs: number;         // 从专注退回留意时的间隔
  quietMs: number;                // (a) 最后一条之后安静多久算这一阵说完
  batch: number;                  // (b) 攒到几条马上看；也是一眼最多看几条新的
  overdueMs: number;              // (c) 最早一条等了 I 再加多久，就不等安静
  lullMs: number;                 // 安静多久以后又来消息，间隔回到第一档
  mainFocusMs: number;            // 主区：距上次回话超过多久，下一条按留意
  mainMisses: number;             // 主区：连着几次不回退出专注
  topicMisses: number;            // 话题：连着几次不回退出专注
  windowMs: number;               // 扫一眼只看最近多久的待看
}
export const ATTENTION_DEFAULTS: Readonly<AttentionParams>;

export type AttentionMode = 'focus' | 'watch';
/** 这次判断是哪一种：硬信号、专注逐条、扫一眼 */
export type LookKind = 'signal' | 'focus' | 'glance';
/** 判断的结果：要回（回在主区、开话题、话题里回）、不回、出错（含超时、放弃、关机） */
export type LookOutcome = 'reply' | 'skip' | 'error';

/** 主区：place 就是 chatId。话题：place 是话题 id。 */
export interface PlaceRef { chatId: string; place: string }

export interface PlaceView {
  chatId: string;
  topic: boolean;          // place !== chatId
  mode: AttentionMode;
  intervalMs: number;      // 留意的间隔；专注时不用
  lookedAt?: number;       // 上一眼：扫一眼或专注逐条的判断开始的时间
  arrivedAt?: number;      // 上次收到消息
  repliedAt?: number;      // 上次判断说回、或起跑成功
  misses: number;          // 专注时，自上次回话起连着判成不回的次数
}

export class Attention {
  constructor(params?: Partial<AttentionParams>);
  arrive(ref: PlaceRef, now: number, opts?: { mine?: boolean }): AttentionMode;
  due(place: string, pending: readonly number[], now: number): number | undefined;
  glanced(ref: PlaceRef, now: number): void;
  verdict(ref: PlaceRef, kind: LookKind, outcome: LookOutcome, now: number): void;
  replied(ref: PlaceRef, now: number): void;
  state(place: string): PlaceView | undefined;
  forget(chatId: string): void;
  notePrompt(chatId: string, hash: string): boolean;
  pickGlance<T extends { at: number }>(pending: readonly T[], now: number): { look: T[]; old: T[] };
}

export function outcomeOf(result: Pick<JudgeResult, 'decision' | 'error'>): LookOutcome;
```

规矩：
- 时钟由调用方传：用到时间的方法都收 `now`（毫秒）。模块里不调 `Date.now()`、`new Date()`，不起定时器，不 `await`，不读写文件，不 import 飞书和判断的运行时代码，只 import `JudgeResult` 的类型。
- 每个 bot 进程一个 `Attention`（s25g 在 orchestrator 里建），只在内存，重启全丢。
- 构造时 `params` 盖在 `ATTENTION_DEFAULTS` 上。`intervalsMs` 是空的、或不是从小到大，抛 `RangeError`。别的方法都不抛错。
- 测试和以后给决策模型调参数（把间隔减半）都走构造参数，不另写一套。

### 4.2 参数

`ATTENTION_DEFAULTS`：

| 参数 | 值 | 出处 |
|---|---|---|
| `places` | 200 | 和 `RECENT_PLACES` 一样 |
| `intervalsMs` | `[60_000, 180_000, 300_000]` | 1、3、5 分钟三档，owner 2026-10-19 选最慢 5 分钟 |
| `exitIntervalMs` | 180_000 | 退出专注后 3 分钟 |
| `quietMs` | 20_000 | (a) 安静 20 秒 |
| `batch` | 10 | (b) 攒到 10 条；一眼最多看 10 条新的 |
| `overdueMs` | 60_000 | (c) 最早一条等了 I + 60 秒 |
| `lullMs` | 300_000 | 安静 5 分钟以上又来消息 |
| `mainFocusMs` | 600_000 | 主区 10 分钟 |
| `mainMisses` | 3 | 主区连着 3 次不回 |
| `topicMisses` | 5 | 话题连着 5 次不回，不按时间退 |
| `windowMs` | 600_000 | 只看最近 10 分钟的待看 |

值和 `docs/v1-plan.md` 第 5 节那两行一致。对不上时以第 5 节为准，Codex 停下，结果写"卡住了"。

### 4.3 状态和 LRU

- 内部一个 `Map<string, 状态>`，键是 `place`，状态里存 `chatId`。按使用顺序存，写法照 `RecentLines.place()`。
- 摸一下（移到最后）：`arrive`、`glanced`、`verdict`、`replied` 碰到一个已有或新建的状态时。超过 `places` 就删最前面的。
- `state`、`due`、`pickGlance` 不摸顺序，不建状态。
- 新建的状态：`mode: 'watch'`、`intervalMs: intervalsMs[0]`、`misses: 0`，没有 `lookedAt`、`arrivedAt`、`repliedAt`。下面"按默认"都指这个。
- `state(place)` 返回一个新对象，改它不影响里面。没有就是 `undefined`。
- 待看的条数不存在这里：lane 记待看，`due` 由 lane 把待看的时间传进来。这样撤回、`prune` 只改一处。

### 4.4 `arrive(ref, now, { mine })`：来了一条消息

调用方对这个位置收到的每一条消息都调一次，硬信号也调。返回调完以后的状态，调用方只拿它分没点名的消息：专注的马上判，留意的进待看。

1. 没有状态：新建，`arrivedAt = now`。
   - 是话题、而且 `mine` 为真（调用方查了登记表：这个话题有我的会话，或者是我开的）：`mode: 'focus'`，`misses: 0`。
   - 别的（主区、`mine` 不为真的话题）：按默认，就是留意、从没看过、间隔 1 分钟。主区给了 `mine` 也不管。
   - 返回 `mode`。
2. 有状态：`mine` 不看。按顺序：
   1. 主区、专注、有 `repliedAt`、`now - repliedAt > mainFocusMs`：改留意，`intervalMs = exitIntervalMs`，`misses = 0`。正好 10 分钟不退。
   2. 留意、有 `arrivedAt`、`now - arrivedAt >= lullMs`：`intervalMs = intervalsMs[0]`。
   3. `arrivedAt` 取原来的和 `now` 里晚的那个，原来没有就是 `now`。
   4. 返回 `mode`。
- 第 1 步在第 2 步前面：主区专注过了 10 分钟、又安静了 5 分钟以上，先退到留意，再回到 1 分钟。
- 话题从不按时间退。
- 时间倒退（`now` 比存的早）：差值是负的，两条都不成立；`arrivedAt` 不往回改。

### 4.5 `glanced`、`verdict`、`replied`：看了、判完了、起跑了

`glanced(ref, now)`：一次要看这个位置新消息的判断开始了，也就是扫一眼，或专注逐条。`lookedAt = now`。没有状态就按默认新建再记。硬信号的判断不调它：硬信号问的是它自己那条，待看没被当候选看过，不算"上一眼"。

`verdict(ref, kind, outcome, now)`：判断结果回来时调，按回来的先后算。

| 结果 | 现在专注 | 现在留意 | 没有状态 |
|---|---|---|---|
| `reply`（哪一种都一样） | 专注，`misses = 0`，`intervalMs = intervalsMs[0]`，`repliedAt = now` | 同左 | 新建，同左 |
| `skip`，`signal` | `misses + 1`，够数就退 | `intervalMs = intervalsMs[0]` | 不建 |
| `skip`，`focus` | `misses + 1`，够数就退 | 不动 | 不建 |
| `skip`，`glance` | 不动 | 间隔升一档 | 不建 |
| `error` | 不动 | 不动 | 不建 |

- 够数就退：`misses` 到了 `mainMisses`（主区）或 `topicMisses`（话题），改留意，`intervalMs = exitIntervalMs`，`misses = 0`。`lookedAt` 不动，所以退出后下一眼离上一次逐条判断至少 3 分钟。
- 升一档：`intervalsMs` 里第一个比现在大的；已经最大就不变。退出后的 3 分钟升一档是 5 分钟。
- 专注时扫一眼说不回不算不回：那一批是进专注之前攒的，说明不了我回话以后的事。
- 留意时专注逐条的不回不动：判断期间这个位置已经退出了专注，退出时已经设过间隔。
- `error` 什么都不改，只摸 LRU：出错、超时不算不回，扫一眼出错时这批算看过（`lookedAt` 在 `glanced` 时已经记了），间隔不变。
- 没有状态时不回、出错不新建：被 `forget` 或 LRU 丢掉的位置，回来一个"不回"不该留下状态。说回就新建：我要在那里说话了。
- 主区判断说开话题：主区按上表进专注；新话题的 id 起跑后才有，由 `replied` 进专注。

`replied(ref, now)`：我在这个位置起跑成功（`handleTurn`、`startTopicDirectly`、今天话题里被 @ 直接起的那一轮）。效果和上表 `reply` 那一行一样，没有状态就新建。两个名字分开，是为了调用处看得懂。

### 4.6 `due(place, pending, now)`：什么时候扫一眼

`pending` 是这个位置待看的消息收到的时间（`arrive` 时传的同一个 `now`），先到的在前。返回该看的时间（毫秒），不早于 `now`；等于 `now` 就是马上看。

1. `pending` 是空的：返回 `undefined`。
2. 取状态，没有就按默认。
3. 专注：返回 `now`。专注不攒，待看在下一次逐条判断里一起判。
4. `pending.length >= batch`：返回 `now`。
5. 留意，算两个时间：
   - (a) `max(最后一条 + quietMs, lookedAt + intervalMs)`。最后一条取 `arrivedAt` 和 `pending` 里最晚的那个，硬信号也算一条。从没看过（没有 `lookedAt`）时只看前一半。
   - (c) `pending` 里最早的 + `intervalMs` + `overdueMs`。
6. 返回 `max(now, min(a, c))`。

### 4.7 `forget`、`notePrompt`

`forget(chatId)`：删掉 `chatId` 是它的所有状态，主区和每个话题。别的群不动。清掉以后照"没有状态"走：主区和别人开的话题从留意、从没看过开始；我说过话的话题由调用方再给 `mine`，从专注开始。

`notePrompt(chatId, hash)`：每次判断前，调用方把这个群读到的智能提示词算一个 hash 传进来。
- 第一次见这个群：记下，返回 `false`。
- 和上次的一样：返回 `false`。
- 不一样：记下新的，`forget(chatId)`，返回 `true`。
- hash 表也只在内存，最多 `places` 个群，最久没用的先丢，写法同 4.3。`forget` 不删 hash 表。
- 放在这里，是为了让 s25g 少几行；hash 怎么算由 s25g 定。

### 4.8 `pickGlance`、`outcomeOf`

`pickGlance(pending, now)`：扫一眼前挑这一眼看哪几条。
- 新的：`now - at <= windowMs`（正好 10 分钟算新）。
- `look`：新的里面最晚的 `batch` 条，保持传进来的先后。
- `old`：其余的，保持先后。调用方把它们留在环里当背景，算进"N 条没判"。
- `at` 用收到的时间，和 `due` 的 `pending` 一样。

`outcomeOf(result)`：有 `error` 是 `error`（`mentioned` 失败时 `decision` 是 `main`，也是 `error`）；`decision` 是 `skip` 是 `skip`；`main`、`topic`、`reply` 是 `reply`。

### 4.9 并发、出错和停机

- 方法都是同步的，JS 单线程，每次调用不会被别的调用插进来。两个判断同时在飞时，`verdict` 按回来的先后各算一次，结果确定。
- 不抛错（构造时的 `RangeError` 除外）。没有状态的位置照 4.4、4.5 处理。
- 没有定时器、没有 IO，停机不用收尾，随 orchestrator 一起丢。
- 内存有上限：最多 200 个位置、200 个群的 hash，每个都是几个数。

### 4.10 后面两片怎么调（本片不写，只用来定接口）

- 每条消息（过了今天的门以后）：话题、而且 `state(place)` 是 `undefined` 时，s25g 读一次登记表算 `mine`；再 `arrive(ref, now, { mine })`。
- 硬信号：马上判；结果回来 `verdict(ref, 'signal', outcomeOf(result), now)`。
- 没点名、`arrive` 回 `focus`：今天的做法，马上判。判断开始时 `glanced`，结果回来 `verdict(ref, 'focus', …)`。
- 没点名、`arrive` 回 `watch`：进 lane 的待看，定时器设在 `due(place, 待看的时间, now)`。到点 `pickGlance`，`glanced`，判断，`verdict(ref, 'glance', …)`。
- 起跑成功：`replied(ref, now)`。从主区开的新话题，`ref.place` 是新话题的 id。
- 判断前 `notePrompt(chatId, hash)`。群切成规则、解绑、绑定时 `forget(chatId)`。
- s25f2、s25g 写计划或实现时发现这里的接口不够用，在自己的 PR 里改 `attention.ts` 和它的测试，写进 PR 描述。
