# 0.10.0 老 Bot 私聊升级准备

## 做什么和范围

owner 在 0.10.0 本地验收时发现已注册 Bot 没有私聊入口，要求所有用户升级都自动得到私聊数据。修复 daemon 的升级准备和失败展示，保留现有设置和群绑定。发布、版本号和 stable 提升另行验收。

## 原因与改法

原实现只在运行的 Bot 子进程初始化私聊，先验证目录身份，再等待 Provider 模型列表。停用、Provider 不可用，或备份恢复导致目录 dev/ino 改变，都会让入口缺失，失败只记日志。

1. host 启动时恢复旧注册表，为全部已注册 Bot 准备各自的私聊项目；沿用 Bot 子进程的幂等补建，覆盖新注册及独立运行。读取和写入使用显式 Bot 文件路径，不切全局当前 Bot。
2. 新项目从本地配置复制默认值；不启动 Provider。已有私聊先读取并保留，未指定模型的私聊不跟随后续 Bot 默认模型修改。
3. 默认数据目录内的已分配目录，在账号、真实路径、同卷、无链接及整棵树校验通过后，在 bots 互斥锁内原子重登记。自定义根、链接、冲突、未完成分配和导入预留继续拒绝。群注册、绑定的检查不放宽。
4. 准备失败保存独立错误，状态读取可重试；protocol 增加可选 `dmError`，UI 保留不可用私聊入口和原因，正常群继续可用。旧客户端仍可解析，旧 daemon 缺少该字段不产生假告警。

## 验证与验收要点

- 老注册表、无 allocation、停用 Bot、多个 Bot、离线 Provider 均得到唯一的私聊项目。
- 默认目录复制恢复或设备编号改变后，自动重登记且不修改目录内容；普通群设置保留。
- 原私聊的 cwd、people、模型、技能、沟通方式及原文件内容在重复准备时保留。
- 损坏 JSON、权限错误、目录链接和外部目录不被覆盖或接管；恢复后可重试。
- 并发准备无重复项目、不丢群、不部分发布目录账本。
- 私聊错误不污染群状态；无群、已有旧快照、失败恢复及旧协议兼容均有回归。
- 用隔离数据执行构建及相关自动化检查，再将修复预览交 owner 本地验收。不得同时启动使用相同真实 Bot 凭据的两份 daemon。
- diff 不含真实账号、密钥或本机路径。

## 风险与文档

涉及文件系统目录身份恢复、跨进程数据写入和启动错误路径。目录操作保留现有互斥锁和原子发布；自动恢复限制在应用管理的默认子树。需要独立审查及相关 Linux、macOS、Windows 检查。产品行为更新于 `docs/product.md` 目录和私聊两节。
