# 桌面自动检查更新频率

## 1. 做什么

owner 2026-11-02 要求缩短更新发现时间，自行验收后合入 dev。App 持续运行时也能发现后来发布的版本，无需用户重启或先进入设置。

## 2. 范围

macOS、Windows 共用调度器，CPU 架构不影响检查策略。保留当前更新源、签名校验、下载和安装交互；本次不增加推送服务，不发布版本，不替换 owner 的安装包。

## 3. 现在的代码

- `packages/desktop/src/updates.ts` 的 `scheduleUpdateChecks`：启动约 60 秒检查，正常间隔 24～25 小时，失败间隔 1～2 小时。
- `packages/desktop/src/main.ts`：签名更新源可用时创建调度器，结果同步窗口和托盘；退出时停止调度。
- `packages/desktop/test/updates.test.ts`、`native-lifecycle.test.ts`：调度单元测试与原生主进程接线测试。

## 4. 怎么改

产品行为见 `docs/product.md` 第 2 节的桌面更新说明。

- 窗口加载完成后固定等待 2 分钟首次检查，此后每轮结束固定等待 90 分钟，不加随机、不对齐整点。
- 仅北京时间（UTC+8）05:00（含）至次日 02:00（不含）发起自动检查，不随电脑本地时区改变。
- 夜间或下载中跳过本轮，下一轮沿用自己的 90 分钟节奏；休眠错过多个时点时跳过旧时点，不批量补跑，不统一挪到 05:00。
- 失败和结果通知异常都继续循环。自动检查只发现更新，下载和安装仍由用户选择。
- 通过可注入的 `onResume` 订阅唤醒，Electron 使用 `powerMonitor.resume`；唤醒时已到期且在允许时段内补查一次。未到期不改变原来的计时。
- 保持 `scheduleUpdateChecks` 返回停止函数，取消计时、移除唤醒监听，退出后丢弃在途结果。定时器和唤醒共用并发门；已取消的陈旧回调不改变新计时。系统时钟回拨后重新安排剩余等待，不能耗掉唯一计时器。
- 手动检查继续直接调用更新器，不受自动检查时段影响；沿用更新器已有的同一时间只查一次机制。
- 将公共 `updates.test.ts` 加入 Windows CI 和构建脚本的专项清单，并验证两份清单一致，保证公共调度器在 Windows runner 上也实际执行回归。

## 5. 测试

- 首次 2 分钟前不发请求；此后准确间隔 90 分钟，后来发布的版本无需重启即可发现（旧实现必败）。
- 午夜、01:59:59、02:00、04:59:59、05:00、23:59:59 的北京时间边界；不同电脑时区结果一致（旧实现必败）。
- 首次落在夜间、连续跳过、05:00 不集中检查，保留不同启动时间的相位（旧实现必败）。
- 首次网络失败、下载中、慢请求、通知异常，循环继续且不并发。
- 唤醒提前、到期、重复唤醒、与定时器不同到达顺序、夜间恢复、多轮错过只补一次。
- 系统时钟回拨不会永久停止检查；退出取消监听和计时，在途结果不通知也不重排。
- 主进程等待页面加载后才计时；无签名源不检查、不监听；自动结果同步窗口与托盘，夜间手动检查正常。

## 6. Codex 自测

Mac 隔离 worktree 运行：全包构建、桌面 typecheck/lint、桌面全量自动化测试、不同 TZ 下的定向调度回归。Electron 生命周期测试采用可控时间和网络响应，直接驱动真实更新器与主进程接线，模拟连续运行和发布后版本变化。

本次没有 UI 布局变更，不操作 owner 的正式 App、daemon、Bot 或飞书群。无需真实下载或安装更新。Windows 共用调度和更新器回归由 CI 验证；主进程生命周期模拟在 macOS/Linux 验证。物理 Windows 休眠和真实服务器更新另行说明，不把模拟测试写成实机验收。

## 7. 文档

更新 `docs/product.md` 的桌面检查策略，以及 `docs/v1-plan.md` 的默认值和本次实现记录。旧版客户端保留旧检查周期，安装包含本次修改的版本后才使用新周期。

## 8. 验收要点

- 新版本发布本身不重建调度器，已运行客户端下一轮检查就能发现。
- 无需首次检查成功，夜间跳过或网络失败也不会停止循环。
- 北京时间时段、90 分钟周期、独立启动相位均有边界测试。
- 自动检查不自行下载或安装；现有版本比较和签名验证不变。
- 唤醒监听与计时器在退出时清理，无重复请求、退出后通知或重新挂起计时。
- diff 不包含真实 id、密钥、本机路径。

## 9. 风险和行数

主要风险是休眠恢复、时钟变化、夜间边界以及退出时在途检查。预计约 500 行变更，独立审查重点覆盖调度、生命周期及 Windows 回归清单；CI 清单改动按规则执行全包、Linux、自托管 macOS 和 Windows CI。检查通过后仅合入 dev。
