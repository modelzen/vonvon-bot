# 决策模型页面细化与推荐策略统一

## 做什么与范围

2026-10-25 owner 在当前 dev 的逐页 UI 验收中确认第四版决策模型预览，并要求后端一起纠正推荐行为。实现本页的紧凑布局和共享默认策略；不变更执行模型、不迁移现有显式配置。依据产品定义 3.4。

## 现有代码与修改

- `DecisionProviderSettings.tsx` 将 Codex / Claude 的模型和 Effort 都使用同一个下拉组件。推荐提示只在选项中出现；选择值不附加提示。
- Jev 模型和 API 密钥并排，密钥状态与操作紧邻，使用范围折叠收起。标题冻结，读取操作保留为对应分组的图标按钮。复用已有草稿、保存冲突和密钥验证流程。
- `protocol/decision-effort.ts` 提供 UI/runtime 共用策略：Codex 默认模型从实际可见目录中依次选择 gpt-6-luna、其他 Luna、目录默认、第一项；无目录时保持既有回退。Effort 优先 none，其次 low；均不支持时仅以最低合法项兜底，不标成推荐。自定义模型没有凭空推断的推荐档位。
- 后台 `judge/model.ts` 在真正的 JudgeCall 中应用相同策略。Claude 省略 Effort 仍发送关闭思考语义，Jev 不新增 Effort。
- 未保存的 UI Codex 配置根据当次成功的模型发现展示；已保存模型/Effort 不因打开页面而改写。host.read 保持只读，不为展示而启动模型发现。
- 旧入口中“最低一档”提示改为如实的默认文案，none 显示关闭思考。

## 测试与本地自测

- 目录提供 minimal/low 时选 low；有 none 时选 none；显式 minimal/high 保留；目录缺失、自定义和空目录不伪造能力。
- 可见目录没有 Luna 时，前后端选择同一可见默认；隐藏模型不作为默认候选。
- UI 下拉一致、推荐不污染当前值、只读不写入、刷新不覆盖已选值；密钥验证、错误、删除与使用范围沿用原回归。
- 在隔离目录构建 UI/daemon，用 Codex 浏览器查看真实组件的常规、窄窗口、目录异常、密钥异常以及保存/重新读取行为。所有 fixture 标明为演示数据；不操作 owner 的 App 或真实 Bot。

## 文档与验收

产品定义 3.4 和 v1 当前桌面约定同步新推荐规则；历史实施计划保留原记录，以本计划为当前修订。确认项：推荐影响真实调用、旧设置不被覆盖、无真实密钥和本机路径进入 diff、页面与批准预览一致。

## 风险

共享 SelectControl 新增可选 dropdown 展示模式，其余使用处默认行为不变；后台默认档位会影响从未显式保存 Effort 的下一次判断。预估少于 700 行，不涉及数据迁移、账号授权或 App 发布。
