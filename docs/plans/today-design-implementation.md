## 产品边界

- 不增加应用登录。首次打开检测旧飞书 Codex Bridge；可导入、取消，执行失败能够回滚。新用户先准备 Provider（安装、登录与可用性检查），再扫码注册 Bot、开权限并发布，最后连接飞书群。绑定成功进入当前 Bot 的本群设置。
- 日常首页为概览，主导航为概览、Bot、群聊；搜索与设置在工具栏。用量、Provider、工具安装和授权、决策模型凭据、导入、诊断、应用更新放在设置。
- Bot 详情为群聊、个性与记忆、管理 Bot。旧有管理员、评论任务、并发和生命周期功能保留在管理入口；不新增 Bot 级技能库。
- Bot × 群依次为能力、个性与记忆、模型、工作区、回复规则。进入默认能力。群用法和历史收在上下文菜单，解除绑定与群内使用开关语义区分。
- 个性与记忆各一个输入区；灰色 Bot 引用块可整块移除，移除仅取消继承，不删除本群文本或 Bot 原文。
- 模型选择一个 Provider；模型和 Effort 是两组独立多选。群内切换、恢复、普通任务、目标任务都按允许集合校验。
- 多个工作区目录中指定一个主目录；多个仓库不分主次。Electron 原生多目录选择；网页浏览运行主机的目录，不使用文件上传模拟本机路径。
- Skill 从工作区、个人与 Provider 原生来源发现；本群开关控制真实加载。通过私聊在当前 Bot × 群工作区添加技能，没有 Bot 级技能库。提示页明确目标，用户复制命令并自行发送。
- CLI 安装、授权和 MCP 配置集中管理，不提供虚假的群级 CLI 开关，不推断 Skill 的工具依赖就绪状态。
- 回复规则包括聊天方式、时机、成员、排队/插话、过程展示和结束提醒，语音转文字放在能力。智能模式有独立决策 Provider/模型/Effort 与两段提示词，也支持 Jev。建群先沿用默认决策配置或推荐小模型，默认最低支持的 Effort / 关闭思考，可修改；缺少有效配置时不能创建。

## 集中 MCP 配置范围

本轮增加机器级 `machine.mcp` 操作，集中列出、添加和移除 Codex / Claude 的原生用户配置。Codex 使用 `CODEX_HOME/config.toml`（默认 `~/.codex/config.toml`），Claude 使用 `CLAUDE_CONFIG_DIR/.claude.json`（默认 `~/.claude.json`）；项目、插件等其他来源继续由 Provider 原生加载，本页明确仅展示用户配置。

- 被动读取不连接 MCP 服务、不判断授权、不启动聊天。摘要只展示命令 basename、参数数量、URL origin 与环境变量/请求头名称，不回显参数、变量值或 URL 路径及查询。
- Codex 添加使用官方 app-server `config/batchWrite` 和版本校验。没有使用 `codex mcp add --url`，因为该命令会自动进入 OAuth 流程。Claude 添加使用官方 `mcp add-json --scope user`；移除使用各 Provider 的原生命令，保留其凭据清理行为。
- 修改检查文件 revision；Codex 原生写入再次检查配置层版本，Claude 原生命令不提供跨进程 CAS，保存后读取并确认目标变化，不声称能够锁住外部编辑器。失败或无法确认时显示重新读取，不报告保存成功。
- 授权仅提供官方 `mcp login` argv 供用户在终端执行，不在 UI 假设已授权。当前原生 CLI 支持该命令；较旧 CLI 需先更新。配置在下次建立会话时读取，不承诺正在运行的会话立即刷新。
- 隔离 fixture 覆盖被动摘要、敏感值不回显、并发旧 revision、原生命令失败、未确认写入以及可选本机 CLI 往返。真实 OAuth、第三方 MCP 连接、owner 现有配置均未操作。

官方合同参考：[Codex MCP](https://developers.openai.com/codex/mcp/) 与 [Claude Code MCP](https://code.claude.com/docs/en/mcp)。
