# s25e2：判断事实与诊断

基线 b39dda2（s25e，#456）。任务 120，JP-VPS 实现。产品依据：product 3.4 智能模式、关注度和 bot 之间；v1-plan 的 s25e2。与 s25e 紧邻交付，随后进行 M5 正式验收。

## 1. 做什么

判断看到其他 bot、当前位置、观看原因与 bot 往返事实。默认智能提示词说明先看对谁说话，以及无人插话时适时结束 bot 往返。诊断页显示每智能群真实关注状态，并提醒旧自定义提示词缺少新版段落。

## 2. 范围

完成事实、LLM/Jev 同形输入、main 格式描述、默认提示词和诊断。保留规则群、命令门、fallback、超时、45/60 预算、排序与落地保护。没有硬性往返上限，不查询其他 bot 的设置，不自动修改用户提示词，不重做 SDK 前门。Jev 真调用和 M5 长时间验收不在本片。

## 3. 现在的代码

- `bot/handle-message.ts` 的 `callJudge` 组装请求，先补 `RecentLines.fill`；named/aside 仍缺 why。
- `bot/salience.ts` 返回 at-me、quote-me（quote/root）、name、plain；partial 是长名简称，不能当短名提示。
- `bot/recent-lines.ts` 的 `lines` 读实际位置，含真实回答和 act: 决定记录；后者不能算 bot 发言。
- `bot/bot-roster.ts` 的 selection 返回最新读取完整性；失败清 latest，peek 可能仍旧，交接闸门独立。
- `judge/prompt.ts`、`decision.ts` 分别渲染语言模型和 Jev；`smart-file.ts` 读取群覆盖、bot、默认，整层替换。
- `bot/attention.ts` 的 state 是真实内存状态；`bot/diagnostics.ts` 经 IPC 汇入 supervisor store，protocol 可选诊断字段传页面。

## 4. 怎么改

事实用独立纯函数，从当前位置最近消息与当前触发构造。列表按身份去重，事件按 id 去重，名称去控制字符并压成安全单行；来源与未知明确，资料不是指令。话题开头读取现有登记和已授权根消息，不借其他话题填空；主区不假造发起者。历史只有有界环，明确可能不全。

名册与现有最近消息填充并行，复用 load 的缓存、期限和进行中请求。完整且成功的 selection 才显示全名单；失败/不完整只列最近确知发言的 bot，注明可能不全。不得为了事实放松 peekForHandoff。名册与补环合并共用 3 秒总预算（含共用请求等待），现有登记读取另限 3 秒，组装读取合计至多 6 秒；撤回/关停立即放手，失败降级。事实读取在判断组装处，不在落地重查与同步起跑之间插入 await。

bot 往返按最后真人之后的实际 bot/self 消息数，含当前 bot 触发，每条消息计一次，排除 act:。0/1 不显示，2 起显示；计数以最近可见记录为来源，标“至少”和历史可能不全；即使看到真人边界，也不能假定中间补拉完整，缺口中是否有真人发言未知。冷环或截断不能称从零开始。不新建持久化计数器，不无限补历史。重复事件、自己的最终回答按消息 id 合并。

why 保留 salience 的 quote/root 来源，覆盖真人 @、引用/回答根、完整名、bot @；专注/扫一眼沿用现有真实原因。短名/常见词只在正文真的出现完整显示名时附同名词提示，不提升 name 信号，不与长名 partial 混淆。

JudgeRequest 增可选 facts；LLM 与 Jev 从同一清理结果渲染，Jev state 增 other_bots、here、bot_exchanges_since_person。main 去掉“没有点名谁”，选项、解析不改。

新默认段落用共享常量，检测生效的非默认 prompt 是否完整包含共享的新段落常量。读取群覆盖后的文本才通知；默认不报。提醒按每个 Judge 实例的 appId:chatId Set 去重，在首次实际使用后同步登记，两个并发读完成也只能第一次发事件。重启内存清空；用户文件不写入、不恢复默认。诊断明确新增段落内容供主人自行采用。

Attention 增只读聚合视图与变更通知，按群汇总主区 mode 和话题专注/留意数量。UI 合并实际智能绑定：无状态显示尚无状态，规则群不显示；停用、解绑、模式切换按既有 forget 清理，重启无状态（话题仍由既有登记恢复）。预算限制由 daemon 的 JudgeBudget 提供 45 次停扫、60 次仅真人点名的级别和恢复时间；一个可取消计时器在最早预算恢复时重发，关停解绑观察者并取消计时器，不由 UI 猜关注状态。新增协议字段可选，旧客户端忽略；新客户端连旧 daemon 显示状态未提供，不假装为冷状态。UI 不作视觉重整，新增行纳入搜索索引并运行整份 search 测试。

## 5. 测试

1. 事实：完整名册与失败兜底、位置隔离/未知、单行名称与身份去重、真人边界、当前触发、重复/act:、0/1 隐藏与 2 起展示、截断至少数。新增行为 main 必败。
2. 协议：why 各来源、短名/常见词实际出现与 partial 区别、LLM/Jev 同形事实、main 格式保持可解析。旧安全断言保持。
3. 提示与诊断：默认与自定义、群覆盖胜 bot、第一次并发去重/重启、真实 Attention 聚合与空状态/预算、旧新字段兼容。新增行为 main 必败；原继承能力基线可能绿。
4. 新等待：失败/超时/关闭迟到不落地，沿用未修改的入口及落地回归；只在共享接缝被改时扩展相关套件。

重命令统一 heavy 锁；测试 HOME/VONVON_HOME 用 mktemp 隔离。安装复用现有 npm 工件缓存，prefer-offline/no-audit/no-fund。跑 build、typecheck、lint、实际改动定向测试（UI 显式 tsx）与 search 整文件。真 provider 套件只编译。main 反证在独立临时树跑新增测试，分清模块缺失、断言失败、原依赖已存在而绿，不称全红。

## 6. Codex 的自测

JP-VPS，严格按 #422 第 4 节与任务 120 边界，只用 Bot 7/8 验收环境。每次真实操作前查取消。

先在内存读当前 registry 与两 bot 的实际 bindings，选唯一已登记共同智能群；空、多个或未登记立即停止，不建群、不重绑、不改登记，不用旧 cid 缓存选群，不打印 id/名单/凭据。只通过 lark-cli profile jojo、as user 在核准群发少量正常消息；Bot 8 的有限发言使用既定工具，最多有限一轮，不强迫模型回或无限互叫。

拿目录锁并写任务 120 owner，按 #422 停 daemon、备份 pre-s25e2、切准确已提交 head、依次构建 protocol/client/daemon/ui 后启动，只用此事件接收器。锁占用等待，超过一小时报阻塞，不放别人的锁。

先记录会改的唯一测试对象：Bot 7 在核准共同智能群的群层 SMART.md（存在性与原字节）。第一轮用原生效默认提示词发一条明确 @ 的正常问题，观察实际判断/回答或 skip；若原生效为自定义，仅在本测试群临时使用默认以覆盖默认段落。随后只将此群 SMART.md 临时写为旧默认提示词，发一条正常测试消息触发首次提醒；浏览器真开诊断页看每智能群状态和一次提示，截图只保留本机，公开结果匿名。所有提示词更改 finally 恢复原文件存在性/字节并 readback，失败也报告恢复状况后放自己的锁。bot 层、owner 全局、登录设置不改。

同组消息尽量复用位置/名册/why/往返证据；若日志仅摘要哈希，不增加原文日志、不从回答猜完整输入，缺少的结构由确定性测试证明并写真实未验。模型未选分支记未验到；短名不改真 bot 名，故障/截断/预算/关停竞态不用真实破坏手法。Jev 不读 key 不真调。真实多模型、停止性和两项一小时观察留正式 M5。验收 worktree 留准确已验 head，交代 daemon 状态与最终 SHA。

网页遵循 verify 技能，使用真实页面操作；不能内部 RPC/mock 冒充页面。浏览器无法运行时明确未验项，不能拿组件测试充页面。Mac 无专属项。

## 8. 验收要点

- [ ] 事实来源、未知和完整性真实，LLM/Jev 一致；why、同名词及计数符合第 4 节。

- [ ] 每智能群一行真实关注汇总，规则群不显示；预算、清理、重启与旧 daemon 表达准确。
- [ ] 定向测试与 main 反证记录准确，真实自测恢复 readback，未验范围写明。
