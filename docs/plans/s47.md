# s47：结构化 settings / feishu 命令

## 1. 做什么

终端和 bot 的 vonvon 工具共用返回结构化结果的命令函数。终端增加版本参数、JSON 错误和只读群成员查询；agent 复用 s46 的来源及提交点检查。依据 product 3.7、任务 142；依赖 s07a（已合入）和 s46（#464，含 4.4a），基线 eaf526e。

## 2. 范围

- 保留 s07a 的 bot/group/settings 本机凭据入口。增加 `settings access`、`set --revision --reason`、`feishu groups [--cursor]` 和 `feishu members <groupId> [--cursor]`。
- bot 登记 `settings_get/access/set`、`feishu_groups/members`；共享登记表只在私聊清单中暴露 settings 类写工具，群/评论保留只读工具；调用时仍检查 not-dm，清单不缓存触发人/开关的权限快照。终端与工具直接调用 `admin/structured-commands.ts`，不启动 shell 或捕获 stdout。
- 设置仅开放今天已有的 section patch，仍由现有 schema 决定字段。MCP edit 必须持有 revision；终端显式 revision 原样发送。终端旧字段 patch 允许读取当前版本，以兼容已有入口。今天没有整段文字 writer；后续 s54/s56 的整段文字写回必须显式持有 revision，不得沿用字段 patch 的自动读取。
- 不做 s46b 的 Codex 路由、令牌文件或环境令牌，不开放通用 agent 管理 RPC。不做 s48 历史、s54 skill/文字、s55 新命令、s56 回执撤销、s57 建群邀请。

## 3. 现在的代码

- `cli/index.ts` 的 preAction 跳过 bot/group/settings 数据租约；命令只通过 `daemon-client.ts` 连接运行中的 daemon。
- `cli/commands/settings.ts` 的 runSettingsGet/Set 解析目标、打印结果；set 现读 section revision。
- `admin/settings.ts:createSettingsOwner` 执行 schema 校验、版本比较及 bot/project/session 保存；bot 用 AppPreferencesWriter，项目用 mutateProject，会话用 session-store。
- `agent/entry/registry.ts` 已实现 s46 的来源检查、FIFO、deadline、ctx.commit/guard 和已提交结算；默认只有 session_info。
- `admin/groups.ts:createGroupExecutor` 查询已加入群并处理飞书错误；本机 command RPC 已有 listJoinedGroups。

## 4. 怎么改

### 共享函数与适配

`settingsGet(service,scope)` 返回 `{view}`；`settingsAccess` 从可见 sections 导出 access；`settingsSet(service,edit,options)` 返回已有 SettingsSave 联合。`feishuGroups/Members` 接收有类型的服务适配器并保留分页结构。业务保存仍由 createSettingsOwner 统一完成。

CLI 适配器调用同一份 settings/command RPC，保留中文人类输出。`--json` 错误返回 `{ok:false,error:{kind,message,current?},exitCode}`；成功沿用命令的数据对象。退出码：failed=1、bad-args=2、connection=3、refused=4、conflict=5、outcome-unknown=6。参数先校验；daemon 不在时只报 connection，不自启、不建数据目录。

新增 listGroupMembers 的 protocol schema、只读 RPC、AdminService 和 AdminGroupOp。executor 验证机器人群成员身份，再查询成员；保留 page_token/has_more，缺游标或上游错误不能报空成功。终端一次返回一页，原 group joined 的聚合行为不变。

### 授权与可见范围

createCommandTools 在 bot 子进程登记，scope 必须属于本 bot，host 一律拒绝。群会话只看当前群；私聊的当前授权管理员可读本 bot 的设置和群；文档会话不扩大到其他群。读工具不套 settings 写入的私聊/人类回合限制。只给 agent sections，不返回管理员私聊名单或密钥元数据。access 的无权与不存在同形。

写工具 class=settings，s46 在接纳、排队后及提交点现查来源回合、管理员、开关。共享函数不得把终端主人凭据当作 agent 身份。

### 提交点与错误顺序

MCP settings_set 解析 edit/reason，检查可见目标，调用 `ctx.commit(guard => settingsSet(...,{beforeCommit:guard,notAfter:ctx.notAfter}))`。旧终端 RPC 不携带 agent context。

bot preferences、project、session 三种 writer 在锁/读盘/临时文件准备之后，把 beforeCommit 传到 rename 前；在同一同步段检查 notAfter，再 guard，再发 rename。准备中回合结束、撤权、开关关闭、超时均不能写。未提交的 conflict/rejected/unavailable 不冒充成功，也不要求 guard 已调用。

今天这些保存实际由 bot 子进程本地执行，未新增 bot→host 写入路径；notAfter 在实际 owner 的提交点检查。以后若跨 host，发送前 guard 与 host rename 前的 notAfter 缺一不可。

已提交成功返回实际保存结果及 reason；提交后未知错误交 s46 返回“可能已经改了”，不重试。过期未写抛 ToolRefusal(timeout)。停机/关闭沿用 s46；本片不新建常驻进程或队列。

## 8. 验收要点

- CLI 和 MCP 直接使用相同命令函数；无环境令牌、shell CLI、数据租约、自启 daemon 或通用 agent 管理接口。
- 显式 revision 不被内部最新值替换；冲突只带已授权 current；access 无权/不存在同形。
- 每个新 settings writer 提交点具有真实文件 readback 测试，成功/未知不重试；期限已过明确没改。
- 群读范围不借管理员身份扩大；飞书错误不伪装空成功，游标原样续读。
- 不碰共享验收环境。diff 没有真实 id、密钥、本机路径。

## 9. 风险和行数

主要风险是异步保存时权限变化、提交后报错误重试、群查询越界。用 writer 提交点、结构化联合和可见范围适配统一约束。预计生产约 430 行、测试约 430 行、文档约 110 行，总计低于 1500；实际新增+删除在 PR 报告。超限先提最小技术拆片，不通过删安全断言压行数。自审不代替总管独立审查；不冻结、不合入。
