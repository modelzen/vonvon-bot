# 原生配方安装编排与原入群流程复用

## 做什么

作者或领取者从配方详情把确切版本添加到所选设备的 Bot 群。主进程把账号权益和现有设备授权连接起来，预览、确认及恢复均指向同一个 Bot／物理群位置。

依赖已审查云端授权 PR 768、后台安装器及原生社区切片。未完成独立审查的依赖须先修复再合入功能集成分支。

## 范围

先连接已有绑定群的角色与 setup 安装、更新、确切版本忽略及恢复，再在同片复用原有建群／已在群中两条表单路径。正文仍受已实现 schema 限制；完整技能、记忆与任务模板由可移植配置切片补齐。安装不改变 Bot 全局身份、权限或其他群。

## 现在的代码

`NativeAccount.request` 仅在主进程携带账号令牌。`bridge.ts` 的 `viewSeq`、`localGen`、具体客户端和远端 `ViewSession` 区分设备及连接代次；通用 `registerClient` 的进入检查不能覆盖中间 await 后发生的变化。

`DeviceConnections` 保存已配对设备的公钥，设备状态 RPC 可提供本地设备公钥。后台 `recipeInstall` 已实现准备、带 reviewToken 的选择、提交、状态和取消；云授权在确切版本权益上校验。原入群按钮、Bot 选择和表单位置保持原样。

## 怎么改

### 主进程边界

增加用途明确的安装 IPC 和主进程控制器。Renderer 只传版本引用、目标 Bot／群、用户选择以及不透明 handle；不收账号令牌、操作 ticket 或私有 nonce。主进程解析全部输入和输出，限制缓存数量及有效期。

每次操作捕获当前业务账号及账号会话代次、具体设备客户端、viewSeq、localGen、设备 ID 和公钥。每次 await 后检查，账号退出／重登和设备 A→B→A 都使旧确认失效。账号 lease 应直接随会话失效而终止，不能只比较账号 ID；退出时等待安全存储清理也不能延长旧授权。

预览先读取拥有或已获取的版本 manifest，再通过捕获的设备连接读取设备身份和准备状态。远端公钥必须与已配对登记一致，本地通过已验证的本地 owner 连接确认。后台返回的目标公钥必须相同。内容和 SHA 均以服务端确切字节为准。

第一次冲突展示当前、原版及新版职责／setup；选择携带同一 reviewToken。后台返回新 review 时重新显示变化，不沿用原选择。正常确认才申请 `/v1/operations/:id/authorize`，再向捕获的后台发送 scoped authorization。发送前再验账号及目标；已经派发的事务按实际回执恢复，不因换号虚构取消。

用户明确取消时，原账号向云仲裁，再处理本机。云返回 in_progress 时显示进行中；云 cancelled 或 expired 的确定结果允许后台结束尚未兑换的操作。原账号不在时暂停，不能借用下一账号。请求超时后按 operationId 恢复，不重新建群或重应用职责。

### 界面与创建群

详情主动作沿获取→原入群表单前进；已获取资源可再次添加。表单只增加只读配方项，沿用原 Bot 选择、建群和 Bot 已在群中入口。社区和编辑器属于账号，设备切换不清空其输入；目标离线时给出可恢复状态。

新建／绑定成功必须先写真实群 ID 的创建 journal，再调用同一安装器。安装失败重开的是该群和该操作，不重新建群。入口与按钮位置不移动。一个物理群中不同 Bot 的来源独立，同一 Bot 位置只允许一份配方，不能降级已有较新 revision。

桌面端重连时，按主进程发给当前设备视图的 `reattached` 事件清除群名和确认资格。新连接的快照序号可能更大，不能据此判断连接未变。恢复必须重新 `begin`，后续请求只用新回执的 handle。在当前操作里，原 Bot、原群和同一 reviewToken 的未提交文本与选择可回填。目录令牌不随草稿保留，需要重新选择目录；更换目标或 reviewToken 后重新选择内容。

建群请求派发前保存原始表单。飞书已返回群 ID、绑定未保存时，按该 ID 恢复；回执丢失时按原请求标识查已保存的绑定，也可在现有群中明确选择并连接。结束跟踪只清理桌面记录。

群设置显示当前配方来源及确切版本；检测更新时重验新版本权益。云端检查返回后重新读取本地来源。忽略操作携带展示时的来源快照，后台在同一 Bot 注册身份和群绑定锁内比对后写入确切目标版本。三方冲突必须明确选择；setup 作为文本保存和比较，不能按下标继承另一个版本的执行状态，更不能因获取或安装自动运行。

## 测试

- 主进程真实 typed IPC／HTTP 校验：领取资格、严格字段、ticket／JWT 不进入 renderer。
- 每一个 await 边界的退出、同账号重登、A→B→A、断线重连和目标密钥变化；旧选择不得向新客户端派发。
- review→他人修改→选择时重新确认；提交后并发修改按 CAS 处理；同版恢复、旧版拒绝、同群双 Bot 和共享目录隔离。
- 云取消和兑换两个顺序、授权／兑换／落盘／云回执各处响应丢失，原操作恢复一次。
- 建群／绑定成功后安装失败，重启或重试仍只有一个群和一个绑定。
- UI 用真实生产组件及真实协议边界测试，覆盖全局搜索、输入保留、Unicode 和部分已兑换的分享码回执，不能只用宽松 mock 证明主流程。

## Codex 自测

Mac 隔离数据、userData 和持久证据目录。先用合成 issuer／账号与测试 HTTP 服务自验，再用 #322 已指定测试 Bot 和专用群实际核对职责和独立来源。网页使用浏览器控制；仅桌面自己的行为使用 Computer Use。不访问其他飞书群或默认产品数据。owner 本轮已跳过真实 GitHub 登录，不把合成登录列为真实 OAuth 通过。

## 文档

沿用 PRD、runtime、edge-cases 和云端 install-operations 契约；完成后更新 implementation-status 和真实验证记录，区分集成分支、dev 与部署。确认相关 UI 文案后统一使用同一套称呼。

## 验收要点

- 主进程账号证明和设备控制分别校验；无通用 renderer 云 fetch 或 token getter。
- 用户确认的版本、账号和目标不可被中间状态替换。
- 不假报取消、安装完成或云同步成功。
- 原入群按钮位置、两个路径和多 Bot 独立配置保持一致。
- diff 不含真实测试 ID、密钥或本机路径；真实外部联调与模拟结果分别记录。

## 风险和行数

约 1,500–2,500 行，涉及主进程异步授权、设备连接、创建 journal 和跨端恢复。按控制器／协议、UI、入群恢复分模块审查，并由不同模型通读跨模块错误与取消路径。只在整批集成到 dev 时运行必要的累积 CI。
