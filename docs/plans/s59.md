# s59：bridge 导入只读预检

## 1. 做什么

按 product 第 5 节第 2 步，为之后的导入页提供每个 bot 的群数、目录、旧密钥、hook、运行状态和自带 Codex 检查。依赖已合入 s58（#373），基线 `4c589d9150f253342efd99122977f4f6239ce91d`。

## 2. 范围

移植 #226 的受限本地读取、旧密钥解密和预检规则，只做 macOS。没有准入锁也可检查；现行 V1 数据准入与租约不动。不做 s60 的换算、s61/s62 的停服务、占锁、复制、重新加密、卸 hook、回滚或迁移持久状态，也不接 s63 的 UI/RPC。

## 3. 现在的代码

- `D/service/control.ts` 保留旧 Windows 服务检测/控制；`host/client.ts` 使用 `inspectInstallation`，不能删现有 macOS/Linux 路径。
- `D/config/keystore.ts` 是 V1 新密钥库，不能用它读取旧格式；`config/data-access.ts` 是现行机制，不改。
- #226 `ed66253d` 的 `import/bridge/bounded-local-files.ts`（131 行）、`legacy-keystore.ts`（100 行）、`preflight.ts`（363 行）可复用。其旧平铺自动解析、Windows/准入锁、持久事务设计不采用。
- 已读 research 索引、迁移 inventory 和 e07；e08 尚未完成，不能把 e07 函数层或假快照当作原生服务验收。

## 4. 怎么改

- `import/bridge/bounded-local-files.ts` 复用文件大小、超时、严格 UTF-8、非阻塞/不跟随末端符号链接的读取。增加祖先路径检查，限制路径在显式根内；系统临时目录先 realpath 后作测试根。
- `legacy-keystore.ts` 复用真实主机名和当前用户名的 PBKDF2/AES-GCM。不创建 salt、不写密钥库；解密结果只返回布尔并清零缓冲，不输出明文。
- `preflight.ts` 提供 `inspectBridgeSource({sourceDir, homeDir, ...seams})`：显式绝对根，macOS 才检查；返回 not-found / upgrade-required / invalid / inspected。顶层错误只给源相对文件名和错误码；逐 bot 错误保留全部 bot 的结果，不以一个 bot 失败丢弃其他 bot。
- 有顶层 `processes.json`、无 `bots.json` 时返回 upgrade-required 和产品定文案；不读其内容、不启动 bridge。旧平铺配置同样提示升级，不报没有数据。每次调用重新读取，升级后正常检查。
- 复用 #226 的注册表、身份一致性、群/会话字段验证与数量界限；不返回密钥、管理员 id 或完整原始配置。项目目录为绝对路径，只检查存在性，既不创建也不搬；目录符号链接按不安全报告。群数来自群绑定。
- `secrets.enc` 和 `.keystore.salt` 位于源根。只检查当前配置引用的旧本地密钥；纯文本标记可用，外部 env/file/exec 标记未验证，绝不执行 getter、读外部文件或扩大凭据访问。缺失/损坏/解不开区分报告，解不开提示扫码刷新。
- 只读读取显式 home 下 Claude/Codex 的 hook 配置；识别 bridge 命令和 bot 参数，不执行命令。Codex 安装状态包含 config.toml 的 hooks 开关；损坏/无法辨认报告 unknown/needs-repair，不误报 absent。
- 运行状态读取每 bot processes.json，确认 appId/pid/startedAt 及 ps 的命令身份和进程年龄；另用只读 launchctl print 检查固定 bridge label。失败是 unknown；未加载和已退出都报 stopped，不把 plist 存在当运行中。测试注入快照，不探 owner 的服务。
- 自带 Codex 检查源根 `codex-cli/node_modules/.bin/codex`，允许 npm 正常的末端链接仅在包内目标为可执行普通文件时通过，不执行 CLI。
- 按 v1-plan 第 6 节 s59 明示范围，删除 `service/control.ts` 中 Windows Run 键和计划任务的检测，保留现行 macOS/Linux、消费者及不在本片内的旧控制路径。

## 5. 测试

新模块在 main 不存在，以下均为 main 必败：

- 两 bot、一个坏配置仍返回两项，失败不影响另一项；注册表重复/越界/不一致、缺失/损坏配置/群/会话报错。
- 群目录存在、缺失、文件冒充目录、符号链接；恶意 appId 逃逸和文件/祖先链接被拒。
- 隔离假数据按真实主机名/身份生成旧 AES-GCM 密钥，只断言 match；错 salt、错 tag、缺文件、非法格式均不泄露值，不创建文件；没有旧准入锁照常检查。
- 平铺 processes.json 返回固定升级文案，注册表出现后重试正常；bots.json 存在时顶层 processes.json 不阻止检查。
- Claude/Codex hook 安装、部分安装、其他 hook、另一 bot、Codex 开关关闭和配置损坏；自带 Codex 普通文件/正常 npm 链接/逃逸链接。
- 注入 launchctl/ps 的 running、stopped、not-loaded、unknown、PID 复用/不同 argv；所有进程调用仅只读。
- 递归记录隔离源/home 的路径、类型、链接目标和每文件字节；成功/失败前后完全一致。

交 Mac Codex，在 mktemp 下独立 HOME/VONVON_HOME 跑 npm ci（复用既有 npm 缓存）、build、typecheck、lint、上述定向测试，不手动全量。测试环境按 #322 串行；当前只写代码，重命令等队列授权。无需飞书 bot/群、lark-cli、浏览器、Computer Use 或真实 provider。

真实验收需授权 bridge 0.6.14 测试数据副本和另一个测试用户/服务：复用现有副本，不读 owner bridge 或钥匙串，不复制个人密钥；仅检查已授权测试 service。没有可用副本/测试用户时明确未验并交总管；假快照只证明解析和错误路径。验收记录准确 head、版本、命令、用例数和未验项。

## 8. 验收要点

- 每个 bot 六类检查都有结果；失败不导致跳过 bot，旧用户升级后全部可导入。
- 无 stop/start、迁移/准入锁、hook 改写、外部凭据 getter 或文件写入；V1 数据机制保留。
- 错误及返回不含密钥和原始配置；真实服务结果与构造快照明确区分。
- 源/home 递归清单与字节不变；缺准入锁不拒绝。
- diff 无真实 id、密钥、本机路径；独立审查待总管（#436），作者自审不冒充独立审查。
