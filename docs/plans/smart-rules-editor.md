# 智能判断规则：单一编辑框

## 做什么

owner 2026-10-23 确认：判断规则使用一个有默认正文的输入框；“什么时候回应”“什么时候不回应”“消息在群主区时”“消息已经在话题里时”作为正文内可改名、可删除的小标题气泡。删除标题保留正文，支持完全重写。

## 范围和当前代码

基于当前桌面界面的 `dev`。`GroupDesignSettings` 当前分别编辑 `respond` / `newTopic`；协议已共享默认规则，`handle-message` 已传递群规则。Jev 选项仍包含固定回应偏好，空规则会被 `resolveSmartRules` 替换为默认值。

## 怎么改

- 一个编辑面，沿用设置保存、放弃、冲突处理。标题用 Markdown 二级标题保存为纯文本，界面呈现气泡；名称不作为业务分支。粘贴只取文本，复制排除删除按钮。
- 保留现有协议形状，统一正文保存到 `respond`，`newTopic` 清空。旧两段先无损合并；只升级精确匹配的历史内置默认值，不覆盖自定义内容。
- 默认值、恢复默认、新群初始化和运行时使用同一份正文。显式空规则保留为空。固定输出格式和话题内回复限制仍由程序附加。
- Jev 选项仅定义“不回／主区／新话题／话题内回复”动作，回应偏好从用户规则读取。

## 测试与本地自测

Mac 隔离数据目录，使用合成 Bot 和群，不发送飞书消息。运行定向协议、daemon、UI 检查；用 Codex 内置浏览器检查默认四个气泡、标题改名、删除保留正文、全选重写、纯文本粘贴、撤销、恢复默认、保存重开和清空保存。检查保存的规则文本及判断请求。真实模型效果不以合成测试代替。

## 文档与验收

更新 `docs/product.md` 判断规则说明及 `docs/v1-plan.md` 默认值说明。验收时核对以上交互、旧自定义规则完整保留、话题内路由仍受程序限制，以及 diff 不含真实 id、凭据或本机路径。

## 风险和行数

主要风险是富文本编辑的光标、输入法、换行和撤销，以及默认值迁移误覆盖自定义内容。预计改动约 600 行；不改判断调度和执行权限。
