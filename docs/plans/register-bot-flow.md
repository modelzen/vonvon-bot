# 注册 Bot 弹窗整理

## 做什么与范围

2026-10-25 owner 认可「注册 Bot」交互预览，并明确要求实现、合入远端 dev、跳过 CI、更新本机 App。本片按 product.md 3.1 整理扫码、权限及恢复入口，复用已有注册任务和配置检查，不改飞书权限清单、注册协议或 Bot 数据模型。

## 现在的代码

`App.tsx` 发起注册或凭据刷新并持有任务弹窗；通用 `JobPanel` 展示二维码和任务结果；`setup/GrantStep.tsx` 在首次注册成功后轮询权限。旧注册弹窗重复说明、常驻完整链接，二维码过期需要关闭重来，权限页有重复的离开入口。

## 怎么改

- 注册专用弹窗显示「扫码注册 → 开通权限」两步。扫码区只保留二维码、有效期、打开链接及复制入口，完整 URL 按需展开；打开或复制失败就地提示。
- 二维码过期、任务失败或取消后，在同一弹窗重新获取。重试先停止旧任务，再读取最新任务和 Bot 列表，与本次流程开始时的 Bot 基线核对。已成功注册就接回该 Bot；结果无法确认或有歧义时保留弹窗和错误提示，不直接再发注册命令。
- 刷新凭据始终保存发起时的 Bot id，重试使用同一目标，不随页面当前选中项变化，也不降级为新建 Bot。请求期间阻止重复提交；旧弹窗、旧任务的迟到响应不能覆盖新状态。
- 权限区改为紧凑标题、缺少数量和可展开的权限 ID。无法确认、读取失败和可选加群权限警告继续显示；检测失败提供重新检测图标。最近一次检测失败时，即使缓存过成功状态也不能显示就绪。
- 保留现有权限轮询，开权限后就近提示创建版本并发布。弹窗底部统一显示「Bot 已注册」「稍后配置」「检查连接」；必需权限及可选加群警告全部处理后，才把「检查连接」作为主要按钮。权限未完成时仍能打开检查清单。
- `GrantStep` 只提供权限内容和 `onReadyChange`，弹窗持有页脚。Bot 设置里的权限入口和已有轮询语义保持一致。

## 测试

- 未扫码时展开完整链接，复制及打开失败不丢二维码；过期、失败、取消分别可以就地恢复。
- 重试必须先取消旧任务并读取最新状态；旧任务已成功、Bot 已新增、任务消失但结果不明、取消或查询失败时不能重复创建 Bot。
- 连续点击、关闭后重开、迟到响应及刷新期间切换当前 Bot，不会重启错误任务或改错凭据目标。
- 权限缺项折叠显示；未知状态和可选加群权限警告保留。成功缓存后的最新检测失败显示异常，重新检测立即发起且旧请求不能覆盖新结果。
- 权限就绪前后都能检查连接；离开权限页不会取消已完成的注册。
