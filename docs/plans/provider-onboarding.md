# Provider 引导卡片落地

Owner 已于 2026-10-22 选择「引导卡片」并授权按设计直接实现。继承 `docs/research/2026-10-22-provider-design/report.md`，不引入通用 API 网关或新账号系统。

## 用户可见行为

- 首次使用按 Provider → 创建 Bot → 连接群进行。安装、认证与本次原生模型发现全部满足后才能继续。认证未知、模型发现失败或静态回退不能通过。
- 沿用本机 Codex / Claude 原生配置；新用户可安装托管运行组件并进入原生授权流程。Claude 需要命令行授权且本机没有 CLI 时，按需安装后再授权。
- Bridge 检测、完整导入与回滚入口独立保留；后台服务移至原有应用与启动设置。
- 设置中单列 Provider；飞书 CLI / MCP 仍在工具与连接。Provider 详情承接版本、安装位置、更新、托管卸载、重连与 Claude 命令行维护。
- 首次连接群携带明确选择的 Provider。其他新建/绑定群按当前快照选择可用工具；Claude-only 不再默认 Codex，用户手动选择优先。

## 后端契约

- 无 Bot 的 `collaboration.providerModels` 每次创建新后端，doctor + 原生模型发现；只有成功填充本实例 peekModels 才返回 ready。Claude 补齐与 Codex 相同的成功缓存观察能力。
- `environment.backendInstallStatus` 只读查询安装当前状态/终态；`cancelBackendInstall` 按 operationId 中止准确任务。不会通过重复 install 查询状态。
- 账号状态和模型发现联合用于引导，模型列表不是一次真实推理或真实飞书任务的验收证明。
- 前端抛弃过期回包，重连恢复操作，安装期间可取消，轮询不重复扫描 npm 版本。

## 验证

类型检查、协议/daemon 定向测试、UI 全量测试、desktop 测试；实际构建页面通过 Codex 浏览器验证 560/390px、Provider 门槛、切换与独立设置入口。签名 app 后核对实际进程与页面，记录在验收包说明。真实登录与飞书扫码由 owner 验收，不把模拟测试当作真实账号端到端成功。

## 2026-10-22 本地验收修订（0.7.3）

- 桌面窗口默认 1000 × 800，最小 760 × 640。设置页使用正常桌面内容宽度；飞书检查行使用独立文字/状态列，560px 网页回归也不能把标题挤成竖排。
- 使用 Provider 的群表单只允许安装兼容且已认证的 Provider；首次 Provider 引导卡片仍允许选择待安装项目。手选后失效时保留选择并阻止提交。
- Owner 最新决定：建群默认沿用推荐决策模型，可展开修改。优先可用小模型，使用模型支持的最低思考等级；Claude 默认关闭思考。默认目录必须经过本次原生发现，不拿静态回退冒充就绪；若目录与离线默认不同，建群请求显式带上实际展示的推荐值。未修改且默认一致时不写群 override。新建和绑定后端均支持继承默认。
- 新建/绑定成功后等匹配的 Bot + 群绑定出现在快照中，跳入该群设置；已绑定后的飞书连接页不再显示首次进度条。跳往 Provider 设置并返回时保留建群草稿。
- 设置中常驻“导入 Bridge”，搜索也可找到。未发现旧目录时显示检测路径和重试；首次引导仅发现时显示。预检、执行、完成回执、失败回滚沿用真实事务接口。旧 Bridge 目录被之前的清洁安装流程移入备份；2026-10-22 经 owner 明确授权，已复制回原目录并校验 12 个核心文件，保留完整备份，不启动旧服务、不执行真实迁移。成功与回滚已用隔离 fixture 验证，真实旧数据仍需在 App 预检后由 owner 决定导入。

## 2026-10-22 图标与管理入口修订（0.7.4）

- macOS 托盘从原始 256px 图片改为 18pt 模板图标，附带 2x Retina 表示；Dock 启动时使用当前包内的品牌图标，避免复用旧 Electron 图标。
- Bot 管理入口明确可见，当前页面正确高亮；Bot 管理、Provider 与飞书连接共用页面内容宽度。
