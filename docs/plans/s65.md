# s65：本地 universal 分发、签名和更新产物

## 1. 做什么

按 owner 2026-10-20 的新决定，让同一产品版本生成 Apple Silicon/Intel 通用 dmg 与更新 zip，显式 hardened runtime、最窄 entitlements，并用已有 Developer ID 签名。本片无代码前置，基线 bfc22ccd6af5c2d23fab44816c3f39c40fa8841e；与 s38a/s39a/检查任务仅协调共享资源。

## 2. 范围

本地构建、签名验证、版本统一、第一方 UNLICENSED、更新 manifest/feed。下载与更新 URL 是发布前配置，不硬编码。此次不公证、不配置公证凭据、不公开上传、不安装 owner app；s67 的干净用户从零安装、真实飞书与公开更新验收保留。s66 不做，owner 去向 Anthropic 要确认，不自动转做 API-only 构建。

## 3. 现在的代码

- packages/desktop/electron-builder.yml 未指定 universal，electronDist 固定本机 Electron；extraResources 保留 daemon/npm/ui 布局。
- packages/desktop/build.mjs 把 stage app 写成 0.1.0；desktop package 是 0.1.0，daemon 是 0.7.0。app.getVersion、更新比较读 app 元数据，npm 分发读 daemon 版本。
- scripts/stage-daemon.mjs 打包纯 JS Core 和依赖，保留 LICENSE.bridge、LICENSE.paseo、NOTICE、PROVENANCE；package-tools 验证 npm 包且拒绝 .node。
- DesktopUpdater 严格消费 {version,feedURL}，native Electron autoUpdater 负责下载/签名/安装。desktop-update.json={} 时安全不可用。

## 4. 怎么改

1. 以现有 daemon package 的 0.7.0 为产品版本来源：desktop package 同步、build 时校验并从源生成 stage app/Core 版本，npm 路径复用此源；protocol/client/ui 的独立 API 版本不改。第一方 package license 统一 UNLICENSED，保留所有第三方许可文件。
2. 保留 Apple Silicon preview 配置，另加正式 universal 配置/入口：electron-builder 26.15.3 官方双架构 doPack→@electron/universal 合并→签名机制。正式配置不固定 electronDist，使 builder 获取对应架构 Electron 44.4.5。禁止用改名或相同 host runtime 冒充双架构。
3. 显式 hardenedRuntime、entitlements 与继承文件；仅 allow-jit 起步，实际原生启动证据决定是否需要其他项。不加设备、网络绕过、unsigned executable memory 或 disable-library-validation 的宽泛授权。forceCodeSigning、Developer ID 身份和不公证配置必须使失败显式退出。
4. 沿 stage-daemon/npm 布局，不改应用/daemon 启动协议。打包前后检查实际 Mach-O 依赖/主程序/helper/runtime 架构，所有随包 Mach-O 必须含 arm64+x86_64；单架构依赖使发布失败，不静默豁免。
5. 本地更新产物脚本读取明确的发布配置：manifest/feed/zip 均为 HTTPS、无凭据、同源；生成严格 {version,feedURL} manifest 和 Electron/Squirrel.Mac 默认服务端协议的 {url,name,notes,pub_date} feed，zip 来自同一签名 universal app。不得把 latest-mac.yml 当该 feed。
6. 没有发布 URL 时生成不可用的配置待办/模板，保持 app 配置 {}；不产生可被误认为发布的有效 manifest。已配置则核版本、文件名和附件存在性，输出哈希/体积的本地 inventory，不改原生验签、HTTPS 与同源限制。
7. 错误直接失败，不上报已签名/已发布。构建与输出均本地；停止/卸载仅本任务有归属证据的 PID、挂载。

## 5. 测试

- main 必败：stage app/Core/desktop/npm 产品版本一致，修改版本源后产物正确或不一致明确拒绝。
- main 必败：universal 构建配置双架构、强制 Developer ID、hardened runtime 与最小 entitlements；不存在 host electronDist 误用。
- main 必败：本地产物对应现有 updater manifest 和 Squirrel zip feed，缺/非法配置不生成可用源，缺附件或版本不一致失败。
- 保留更新检查、下载、签名失败和 beforeInstall 契约；假响应覆盖安装前准备失败不调用 quitAndInstall，原生错误不报告下载成功。
- npm/app 包包含第三方声明，第一方 license 为 UNLICENSED；私有配置不进入 stage。

## 6. Codex 的自测

Mac #322，任务独立 mktemp worktree/数据。无 bot/群，不发飞书消息。root 授予共享重资源前仅静态阅读/改代码；之后缓存 npm ci、完整 build/typecheck/lint 与受影响测试，禁止全仓套件。

本地 universal 构建后 codesign --verify --deep --strict 分开验证 app/dmg；核 Developer ID/TeamIdentifier、hardened runtime、entitlements 和每个 Mach-O 架构。仅运行临时 app，通过源码既有 VONVON_DESKTOP_TEST_HOME/隔离 userData 与 VONVON_HOME 入口启动，不安装 /Applications、不触默认 launchd/bridge。Apple Silicon 原生和已有 Rosetta x86_64 分别验证；Rosetta 不可用则明确未验，不安装系统组件。

不访问 owner settings 或登录，不导出私钥/改钥匙串，不公证/stapler。源外及配置不变。公开下载与完整旧版更新安装保留发布前验证，不用本地假响应代替。

## 8. 验收要点

- 产品版本真实消费点一致，第一方 license 和第三方归属正确；没有真实 id、密钥、本机私人路径。
- 两架构为实际二进制，签名有效、失败不冒充成功；hardened runtime 和最小 entitlements 有产物证据。
- 更新清单/附件适配既有 native driver，HTTPS、同源和 Developer ID 检查没有弱化。
- 未配置地址保持不可用，不宣称已公开发布、公证或从零安装通过。
- 独立审查待总管；不加标签、不合入、不上传，不改 owner app。

## 9. 风险和行数
