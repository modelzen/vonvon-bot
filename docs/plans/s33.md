## 1. 做什么

群里有一张选项卡在等人回答时，能回答的人在同一个位置直接发一条消息，这条消息就是答案，不再被当成插话或排队的新输入。agent 问的问题可以没有选项（要人打字），卡上有输入框；选项题可以带"其他（直接打字）"。

确认卡和权限卡（完全访问下 Claude 自己要问的那几类）只认按钮：等这两种卡时，能回答的人在同一位置打的字照普通消息处理，不吞、不当答案（owner 2026-10-19，第 2 节"2026-10-19 定下来的"）。

产品依据：`docs/product.md` 3.8"卡片"第 2 条（`docs/product.md:519`，"回复这张卡片，等于用你的话回答。能回答的人在同一个位置直接发新消息，也算回答"；owner 2026-10-19 把它限在选项卡和打字题上，第 7 节写进 product.md）、第 3 条（`:520`，"每种结局都改卡"）、"谁能点"的表和 `:532`、第 11 节第 15 条（`:842`）；`docs/v1-plan.md` M6 切片表 s33 那一行（`docs/v1-plan.md:1029`），M6"给 owner 什么"的"直接打字回复也算回答"（`:209`）。

## 3. 现在的代码

### 3.1 协议（`D/agent/types.ts`）

- `askQuestionSchema`（`:128-134`）：`id`、`title`、`detail`、`selection: 'single' | 'multiple'`、`options` 至少一个，`.strict()`。没有"打字题"。

## 4. 怎么改

### 4.1 协议：`D/agent/types.ts`

把 `askQuestionSchema`（`:128-134`）改成按 `selection` 区分的 union：

```ts
const askChoiceQuestion = z.object({
  id: askText, title: askText, detail: z.string(),
  selection: z.enum(['single', 'multiple']),
  options: z.tuple([askOptionSchema]).rest(askOptionSchema),
  /** 允许在选项之外打字作答（Codex 的 isOther）。缺省 false。 */
  other: z.boolean().default(false),
}).strict();
const askTextQuestion = z.object({
  id: askText, title: askText, detail: z.string(),
  selection: z.literal('text'),
  /** 密码这类敏感信息：群里不显示输入框，去私聊答（s33b 才用）。缺省 false。 */
  sensitive: z.boolean().default(false),
}).strict();
const askQuestionSchema = z.discriminatedUnion('selection', [askChoiceQuestion, askTextQuestion]);
```

- `superRefine`（`:147-159`）：选项查重只对有 `options` 的题做。
- 新增 `export function isSensitiveAsk(request: AskRequest): boolean`：`kind === 'choices' && questions.some(q => q.selection === 'text' && q.sensitive)`。本片就加上，s33b 才有人传 `sensitive: true`。
- `AskAnswer`（`:163-166`）改成：

```ts
export type AskChoiceAnswer = { questionId: string; selected: [string, ...string[]] } | { questionId: string; text: string };
export type AskAnswer =
  | { kind: 'choices'; answers: [AskChoiceAnswer, ...AskChoiceAnswer[]] }
  /** 用自己的话回答整个选项请求：选项卡在等时，同一位置发的消息。只用于 kind: 'choices' 的请求；
   *  确认卡、权限卡只认按钮（owner 2026-10-19），不会收到它。 */
  | { kind: 'text'; text: string }
  | { kind: 'confirmation'; decision: 'proceed' | 'explain' }
  | { kind: 'permission'; decision: 'allow-once' | 'deny' };
```

- 每题的 `text` 是 `trim` 后非空、不超过 1000 字（和飞书输入框上限一致）；请求级的 `text` 是 `trim` 后非空、不超过 4000 字（消息正文），超过的截到 4000（协调器截，4.4）。
- `AskResolution` 不改。
- 给 s31 的映射（本片不做，写在这里让 s31 照抄）：AskUserQuestion 的 `questions[i].options[]` 映成 `selection: single | multiple`（按 `multiSelect`），`other: true`（Claude 的 AskUserQuestion 总是允许"Other"）；答案 `kind: 'choices'` 每题取 label 或 text 写进 `updatedInput.answers[question.question]`；`kind: 'text'` 时每题都写这段文字。ExitPlanMode 是确认卡，只认按钮，收不到 `kind: 'text'`（协调器对非选项请求不收打字，4.4；`answerSummary` 也会抛，4.3）。AskUserQuestion 没有敏感标记，`sensitive` 只有 Codex 会传。

### 4.2 Codex：`D/agent/codex-appserver/server-requests.ts`

`userInputRequest`（`:107-154`）：

1. `:114` 的判断去掉 `!q.options?.length` 一项。`q.isSecret` 那一项留着（s33b 去掉），加一句注释"s33b 映成 sensitive"。线程不对、题 id 重复的退回也留着。
2. 映题：

```ts
questions: input.questions.map((q, qi) => q.options?.length && !q.isSecret
  ? { id: `q${qi}`, title: q.header, detail: q.question, selection: 'single', other: q.isOther,
      options: q.options.map((option, oi) => ({ id: `o${oi}`, label: option.label, description: option.description })) }
  : { id: `q${qi}`, title: q.header, detail: q.question, selection: 'text', sensitive: q.isSecret }),
```

   `isSecret` 的题即使带选项也映成打字题：Codex 的 `isSecret` 说的是答案是密文，选项没有意义。本片里 `isSecret` 的题在上一条已退回，走不到这里；s33b 去掉退回后才走到。
3. 标题：有打字题时 `title: 'Codex 需要你回答'`，否则照旧 `'Codex 需要你的选择'`。
4. `settle`（`:134-149`）改成：

```ts
if (resolution?.kind === 'answered') {
  const texts = answerTexts(input.questions, resolution.answer); // Map<原题 id, string[]> | undefined
  if (!texts) { resolve(unavailable()); return; }
  for (const [id, list] of texts) answers.set(id, { answers: list });
}
```

   `answerTexts`（新，同文件）：
   - `answer.kind === 'text'`：每道原题都得到 `[answer.text]`。一段文字答整个请求，模型从哪个键读都读得到全文。
   - `answer.kind === 'choices'`：按 `q<序号>` 找到每题的答案；`selected` 的换回 `label`（今天的做法），`text` 的交给下面的 `otherAnswer`；少一题、多一题、选项 id 对不上都返回 `undefined`。
   - 其他 `kind`：`undefined`。
   - 文字怎么交给 Codex，只在一个函数里定：`function otherAnswer(question, text): string[]`（同文件，不导出），今天返回 `[text]`。上面两种文字（整段 `text` 和每题的 `text`）都经过它。Codex 收不收选项以外的文字还没验（6.3），6.4 的结果要改写法时只改这一处。
5. 答案文字不进日志。本文件没有日志，`D/provider/transport/jsonrpc.ts` 也不记发出的帧（`:303`、`:314` 只记非 JSON 行和 stderr），保持。

### 4.4 协调器：打字回答（`D/bot/ask-coordinator.ts`）

新增：

```ts
export interface TypedInput { chatId: string; place: string; senderId: string; senderKind: 'user' | 'bot' | 'unknown'; text: string; createTime?: number }

```

`EntryState` 的 `visible`（`:23`）加 `shownAt: number`：`promote` 里置 `visible` 时（`:125`）记 `Date.now()`。

按下面的顺序判断，前面的不满足就回 `'none'`：

- 找轮：`place` 就是会话键（3.5）。`const turn = this.turns.get(input.place)`；没有、`turn.placement.chatId !== input.chatId`、`!turn.open` → `'none'`。
- 队首可见：`const entry = turn.queue[0]`；没有或 `entry.state.kind !== 'visible'` → `'none'`。队列里还没发出的卡，人看不到，不算在等。
- 时间：`!input.createTime || input.createTime < entry.state.shownAt` → `'none'`。卡出现以前发的消息不是答案。飞书会晚几分钟重推、也不保证顺序（`:1382-1386` 的注释），所以卡出现前发、事件却晚到的消息，和重投的触发消息，都靠这一条挡住。`shownAt` 是本机时间、`createTime` 是飞书的时间，差个一两秒只影响卡出现前后一两秒内发的消息，人读卡要更久，接受。
  - 为什么不在入口先 `await alreadySeen`：`alreadySeen` 挡的是已经收进会话的消息。这样的消息要么在卡出现前收的（`createTime` 早于 `shownAt`，上一条挡住），要么在卡可见时第一次到、已经过了一次 `typed`：当时收成答案的，卡已收尾，重投时看到的是下一张卡（`shownAt` 更晚）或没有卡；当时回 `'none'` 的，原因（不在名单、不是文字、不是选项卡）重投时还在。所以时间这一条够用，不用在每条消息上多读一次盘。
- 真人：`input.senderKind !== 'user'` → `'none'`。bot 的消息不是答案（bot 之间对话由 s27a 管）。
- 选项请求：`entry.request.kind !== 'choices'` → `'none'`。确认卡、权限卡只认按钮（owner 2026-10-19）：消息照常走插话或排队，不提示，卡不动。
- 名单：和 `submit`（`:147`）同一个判断：`isAdmin(cfg, senderId)`，或者 `turn.initiator.kind === 'user' && senderId === turn.initiator.openId`（走到这里的都是选项请求，没有权限卡的例外）。不在名单 → `'none'`，消息照常走插话或排队，不提示（product.md 3.8 的小注只针对点击）。
- 敏感：`isSensitiveAsk(entry.request)` → `'sensitive'`。本片里永远不会真（4.2 第 1 条），分支先写上，入口当 `'none'`；s33b 在入口给它加提示。
- 其余：`text = input.text.trim()`；空 → `'none'`；超过 4000 截断。`this.settle(turn, entry, { kind: 'answered', answer: { kind: 'text', text } }, { actor })`，`actor` 和 `submit` 一样取名字。返回 `'answered'`。
- 日志：`log.info('card', 'ask-typed', { len: text.length, kind: entry.request.kind })`。不记正文、不记 id。
- 和点击的关系：`settle` 已经保证只占定一次；点击、打字、超时、停止同一刻到，先到的赢，后到的 `entry.state.kind === 'settled'` 直接返回。打字落后于点击时 `typed` 看到的 `queue[0]` 已经是下一张或没有 → `'none'`，这条消息照常进会话。

`submit` 本片不改（`'foreign'` 和自愈在 s33c）。

## 8. 验收要点

1. `askQuestionSchema` 是按 `selection` 的 `discriminatedUnion`，`text` 题不带 `options`，`other`、`sensitive` 有缺省；`superRefine` 对打字题不查选项。`isSensitiveAsk` 导出。
2. `AskAnswer` 有 `kind: 'text'`（注释写明只用于选项请求），`choices` 的每题可以是 `text`；`AskResolution` 没改。
3. `userInputRequest`：没选项的题映成 `text`，`isOther` 映成 `other`，`isSecret` 仍退 `unavailable()`；`answerTexts` 对 `text` 答案每题都给，对不上回空答案表；标题按有没有打字题取。文字的拼法只在 `otherAnswer` 一处。
4. 卡：打字题 `input` 是 `multiline_text`、`max_length` 1000；`other` 题有 `q<序号>_other`；`form` 和两处 `actions` 带 `element_id: 'ask-controls'`；`cards.ts` 的 `form` 多了可选的 `elementId`。
5. `parseAskSubmission`：字段名白名单含 `_other`；文字优先于选项；空、超长、全打字题的提示文案如 4.3。
6. `answerSummary`：`kind: 'text'` 只放行选项请求，确认卡、权限卡都抛；`choices` 里的 `text` 项按题重建成 `q<序号>` 或 `q<序号>_other` 再过 `parseAskSubmission`，`other` 为假的选项题收到文字抛；不再在 `text` 项上读 `item.selected`；`decisionLabel` 的参数类型排除 `text`；显示截 200 字。
7. `typed` 的顺序：找轮 → 核 chatId → 队首可见 → `createTime` 不早于 `shownAt` → 真人 → 选项请求（确认卡、权限卡回 `'none'`）→ 名单 → 非敏感 → 非空 → 截 4000 → `settle`。日志只有 `len`、`kind`。
