# s27b3：智能群完成提醒和按钮

任务 98，依 #436 第 5.4 节，计划和代码同 PR 审查。基线为 #450 合入的 `754fdef`。承接 s27b2 4.5、5.4、5.5 的 39—42/44 和旧提醒断言迁移、6.2 的 6/7、8.7。

## 1. 做什么

智能群正常完成时不再按 completion 设置补发提醒。真人发起的运行出错、超时或最终卡更新失败时保留 post 兜底。智能群的排队卡、运行卡和管理页不提供完成提醒按钮。

依赖 s27b2（#450），保留 s27b（#446）的交接发送协议与安全限制。产品依据为 product.md 3.8“完成提醒”和 v1-plan 的 s27b3 行。

## 2. 范围

本片统一提醒策略和四处按钮资格，迁移旧测试，补完整拒绝矩阵和起跑模式快照。

不改 b2 已实现的真人 @、名单分页、说明行、收件人匹配、预算和注入过滤。不改 known-partial 闸门、sent/failed/unknown、脚注、发送次数和关闭生命周期。规则群与私聊四种模式保持原行为，goal 仍不提醒。

- `launchGoalRun` 仍独立收尾，不调用提醒。

## 4. 怎么改

在 completion-reminder 导出 `reminderButtonOffered(cfg, run)`，run 带可选 requesterKind 和 smart。只有 manual、非 bot、非智能返回 true。goal 和 owner/发起人授权继续由调用方检查。

输入增加 `smart?: boolean`。先保留 bot、无收件人、停止及取消的提前拒绝。smart 为 true 时，仅 requesterKind 为 user 且 outcome 为 error、idle_timeout 或 cardUpdated 为 false 才发送；不读 completion 设置或手动请求。非智能执行原四种模式和最终卡失败兜底。

四处统一调用纯函数：卡片 view、飞书旧按钮资格、管理页 canRemind、管理页写入。保留错误文字、owner/发起人授权及 goal 检查。

ActiveState 保存起跑模式。预订时写入当前 project 的 smart，避免准备期间管理页短暂允许写入；launchRun 在 acquireRunSlot 前写 `opts.smart === true`，与同一运行循环的交接保持一致。排队续轮更新发起人但不随群设置变化改本轮模式，插话保持原发起人。

发送调用传 `smart: opts.smart === true`。日志成功和失败都仅追加 smart 布尔字段，不记录正文、姓名或完整 id。去重在发送前，失败不重试；发送 wrapper 先查 shuttingDown，终态 I/O 迟到不在停机后启动新提醒请求。已发出请求不重试。
