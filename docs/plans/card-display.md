# 消息卡片统一自定义

owner 在 Mac 本地逐轮调整交互，要求完成 UI、CLI、聊天和 App 接线。2026-11-08 最新要求：先在 App 实现并自测，等待 owner 本地验收通过后再合入 dev；当前停止合入，不发布。

## 范围与做法

1. 在 protocol 定义带版本的严格配置和纯 JSON 布局编译器。组件只使用原生卡片允许的固定槽位；正文、引用、子 Agent、附件和原生控制回调保持原语义。
2. 群聊和私聊的 `presentation.cardDisplay` 独立保存，不提供 Bot 级卡片入口或继承关系，`null` 明确表示旧版固定默认展示。历史 Bot 和会话显示设置一次性迁入已有会话；新会话直接记录 `null`，无效或未来版本配置不能被当作历史缺失重新继承。卡片迁移不冻结原来继承的语音或提醒设置。配置写入仍使用现有修订检查、串行写入和原子文件替换；保存前先检查配置和各运行阶段的原生卡片。
3. UI 使用真实 `buildRunCard` 生成的演示数据与同一布局编译器。可点、拖、隐藏，拖动有跟随、目标高亮和落位动效；上下文详情预览值不持久化。配置页沿用 App 现有内容宽度、边距、分组圆角和按钮样式；预览使用真实 Bot 头像，不显示飞书引用，不缩放字号或卡片宽度，展开内容自然增加高度，拖动到预览边缘时可滚动。示例回答 Vonvon Bot 的功能、优势与产品愿景。工具、模型和完成提醒统一在消息卡片页设置，同一次修订保存；仅改布局不改未编辑的提醒。工具关闭或完成后输出时隐藏子 Agent 过程；完成后输出不显示运行按钮。桌面默认窗口按 owner 当前验收窗口设为 910 × 808。
4. 既有配置 Skill 通过 CLI 读取、检查和保存，不增加对话解析器。脚本只在运行开始和终态采样，检查时不执行；超时、取消、输出越界或错误不能中断正常回复。停机使用现有子进程所有权机制。

## 验证与验收

- protocol 配置边界、颜色开关和模板变量；原生布局的槽位、状态、流式锚点、工具/思考过滤及回调保护。
- daemon 无效配置不落盘、不替换 live 设置；旧配置迁移、会话独立、固定默认、修订冲突；脚本语法不执行、JSON 边界、取消、超时和子进程清理。
- UI 点击、拖动、隐藏、恢复、用量滑块、保存失败保留草稿和入口搜索。
- Mac 专用隔离测试环境中的测试 Bot、测试群与管理员私聊验证 CLI/聊天修改；用真实网页和 Electron 观察同样配置。测试数据不写入仓库，不修改正式安装或默认数据目录。
- 构建所有包，运行变更包的类型检查、自动化测试及仓库脚本测试；独立模型按配置/执行与布局/UI 两部分审查。先交 owner 验收 App；得到此次认可后才继续 CI 和合入流程，CI 按累积 diff 自动选择平台。

## 风险与审查拆分

跨 protocol、daemon、UI 的改动按模块审查，另查公共配置一致性；脚本涉及子进程与错误路径，单独审查清理和失败降级。生成的运行卡演示数据不计手写代码行数。真实飞书视觉差异、聊天模型理解与桌面候选验收分别记录，不能用单元测试代替。

## 本地验收补充：完成提醒

- 回复行为中的「完成后收起过程」直接展示，不再使用只有一项的「更多」。
- 提醒模板中的「用时」及结果说明为可编辑中文，`{{statusIcon}}` 表达成功、失败、超时的状态图标；兼容旧变量。未自定义时保留原有按结果变化的默认说明。
- 手动提醒按钮支持六个原生槽位和包含 emoji 的文案；固定高度、不能隐藏。点击后的真实确认跟随同一位置。
- 自动演示中，「每次」在终态追加真实格式的提醒；「手动」必须先点按钮，本轮结束后才追加提醒，下轮重置；长任务按演示的 9 秒耗时判断，不虚构达到分钟阈值。
- owner 要求仍在本地 App 验收，尚不合入。

### 本地细节验收补充

左侧「提醒设置」统一编辑按钮点击前文案、点击后文案（`requestedTemplate`）及完成提醒正文；卡片组件入口打开同一弹窗。点击后按钮留在同一槽位，保持原生中号尺寸，宽度随当前文案自然撑开，保留用户输入的前后空格，禁用二次回调。成员与管理员选择共用搜索和列表组件，移除 Open ID 手动添加入口与搜索引导。演示先调用工具，再逐个出现两位子 Agent，随后连续流式显示正文；仅更新文字，不随每次输出重挂载整张卡片。

手动提醒说明采用「点击卡片中的按钮开启提醒后，本轮任务结束时会 @ 提问者发送提醒。」；按钮文案使用「未开启提醒时 / 已开启提醒时」，提醒正文预览标记为「@提问者」。
