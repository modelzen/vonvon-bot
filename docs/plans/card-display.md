# 消息卡片统一自定义

owner 在 Mac 本地逐轮确认了交互，并于 2026-11-08 要求完成 UI、CLI、聊天和 App 接线，自测后合入 dev；不发布。

## 范围与做法

1. 在 protocol 定义带版本的严格配置和纯 JSON 布局编译器。组件只使用原生卡片允许的固定槽位；正文、引用、子 Agent、附件和原生控制回调保持原语义。
2. Bot 的 `cards` 与群的 `presentation` 使用相同配置。群未覆盖时继承 Bot，`null` 清除覆盖。配置写入仍使用现有修订检查、串行写入和原子文件替换；保存前先检查配置和各运行阶段的原生卡片。
3. UI 使用真实 `buildRunCard` 生成的演示数据与同一布局编译器。可点、拖、隐藏；上下文详情预览值不持久化。配置页沿用 App 现有内容宽度、边距、分组圆角和按钮样式；预览不显示飞书引用，不缩放字号或卡片宽度，展开内容自然增加高度，拖动到预览边缘时可滚动。示例回答 Vonvon Bot 的功能、优势与产品愿景。合并原分散的工具和模型显示入口，并邻接完成提醒。
4. 既有配置 Skill 通过 CLI 读取、检查和保存，不增加对话解析器。脚本只在运行开始和终态采样，检查时不执行；超时、取消、输出越界或错误不能中断正常回复。停机使用现有子进程所有权机制。

## 验证与验收

- protocol 配置边界、颜色开关和模板变量；原生布局的槽位、状态、流式锚点、工具/思考过滤及回调保护。
- daemon 无效配置不落盘、不替换 live 设置；继承、清除、修订冲突；脚本语法不执行、JSON 边界、取消、超时和子进程清理。
- UI 点击、拖动、隐藏、恢复、用量滑块、保存失败保留草稿和入口搜索。
- Mac 专用隔离测试环境中的测试 Bot、测试群与管理员私聊验证 CLI/聊天修改；用真实网页和 Electron 观察同样配置。测试数据不写入仓库，不修改正式安装或默认数据目录。
- 构建所有包，运行变更包的类型检查、自动化测试及仓库脚本测试；独立模型按配置/执行与布局/UI 两部分审查。CI 按累积 diff 自动选择平台，准确 head 通过后合入 dev。

## 风险与审查拆分

跨 protocol、daemon、UI 的改动按模块审查，另查公共配置一致性；脚本涉及子进程与错误路径，单独审查清理和失败降级。生成的运行卡演示数据不计手写代码行数。真实飞书视觉差异、聊天模型理解与桌面候选验收分别记录，不能用单元测试代替。
