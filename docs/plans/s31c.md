# s31c 计划：权限三档按 provider 展开，联网并进档位

行号按 `dev` 的 `9b113b6`，以后会漂，按函数名找。路径缩写：`D/` = `packages/daemon/src/`，`T/` = `packages/daemon/test/`，`P/` = `packages/protocol/src/`，`U/` = `packages/ui/src/`。

设计依据：`docs/research/2026-10-23-permissions/report.md` 第 1 节（owner 2026-10-23 的决定）和 `docs/product.md` 3.8"权限"（本计划的文档 PR 已改）。这一片是四片里的第一片：s31c（本片）→ s31d（高级设置）；s31e（Linux 上的 Codex）、s31b（Claude 挡配置文件、限读，已按 owner 2026-10-23 的决定改过计划）都在本片之后。

## 1. 做什么

用户能看到的变化：

- 群详情「工作区」页的"工作目录权限"换成"权限"。三档的名字、说明随这个群的 provider 变：
  ```
  权限   ( ) 只读          能看工作区，不改文件，不联网。
                           Claude：Manual（default 模式），命令在沙箱里
         (•) 工作区可写    能改工作区里的文件，能联网。
                           Claude：Edit automatically（acceptEdits 模式），命令在沙箱里
         ( ) 完全访问      不限制，你这个账号能做的它都能做。
                           Claude：Bypass permissions（bypassPermissions）
         能挡到什么：命令在系统沙箱里跑，改不了工作区以外的文件；工作区以外的文件读得到，包括别的群的记忆。
  ```
- "允许网络访问"开关去掉：只读不联网，工作区可写联网，完全访问不限制。
- provider 做不到的档置灰，下面写一句原因。今天只有 Linux 上的 Codex：只读、工作区可写置灰（s31e 放开）。
- 旧的群（product.md 3.8"已有的群"）：
  - 只读加关网、读写加开网：档不变，读写改叫工作区可写。
  - 只读加开网、读写加关网：显示"自定义"，下面一行写等价的原生设置，例如"沙箱模式：只读（read-only）；网络：开"，并注明"从旧版的联网开关转来"。行为和今天一样。点任一档，就回到那一档。
- 私聊"项目设置 → 🔐 权限"卡：同样三档，名字和说明随 provider，没有联网下拉；自定义的群在卡上写"现在是自定义：…"。
- 命令行：`permission.mode=qa|write|full` 照旧，设档时清掉自定义；`permission.network=…` 报错并说明联网已经并进档位；`permission.custom=<JSON>` 能写这一家的原生设置（编辑界面在 s31d）；`vonvon settings get` 打出档名，或者"自定义"加说明。
- agent 被拒时收到的话换成新叫法，例如"这个群的权限是工作区可写，只能写工作区里的文件……"。

依赖：s31（#443）已合入。

## 2. 范围

做：

1. 每个 provider 一张权限表（新目录 `D/agent/permission/`）：三档的名字、说明、原名、做不到时的原因，"能挡到什么"那一行；这一家"自定义"原生设置的校验、描述、等价的档和网络。Codex、Claude 各一张，其余后端用通用表。
2. 群的数据：加 `custom`；网络由档推出来；旧数据里和档不一致的网络读出来算"自定义"（4.2）。
3. 执行参数：`ResolvedExecution.permission`、`network` 改成由权限表推出的"效果"；两家后端的启动参数照旧吃 `(mode, network)`，后端代码不改（4.3）。
4. 设置协议、保存、网页和桌面的权限编辑器、私聊权限卡、命令行、RPC `setPermission`、绑定和新建项目卡上的权限说明。
5. 群换 provider 时清掉自定义，档保留（4.5）。
6. 档用不了时的拒绝（今天的 `refuseFullOnly`）改成按权限表判断，文字换成新叫法；Claude 回调里的拒绝文字换成新叫法。

不做：

- Claude 挡配置文件、限读：s31b。"能挡到什么"那一行本片照今天的实际写，s31b 合入时改。
- 私聊、云文档评论的档：私聊今天按完全访问跑（`turnPerm` 没有群时不给档），等 s49；评论设置今天没有档，等加评论档的那一片。bot 默认里的 `network` 本片只是不再读。
- 改设置的回执和［撤销］：s55（本 PR 已在 v1-plan 的 s55 行写明：升档、设成自定义算扩大能力的改动）。

## 4. 怎么改

### 4.1 权限表（`D/agent/permission/`，新）

`types.ts`：

```ts
import type { PermissionMode } from '../types';

export type Tier = PermissionMode;
/** 效果一样的档用同一个名字（product.md 3.8）。 */
export const TIER_NAMES: Record<Tier, string> = { qa: '只读', write: '工作区可写', full: '完全访问' };
export const TIER_SUMMARY: Record<Tier, string> = {
  qa: '能看工作区，不改文件，不联网。',
  write: '能改工作区里的文件，能联网。',
  full: '不限制，你这个账号能做的它都能做。',
};
/** 联网并进档位：只读不联网，工作区可写联网，完全访问不限制。 */
export const TIER_NETWORK: Record<Tier, boolean> = { qa: false, write: true, full: true };

export interface TierInfo {
  tier: Tier;
  /** 中文，最多 5 个字。 */
  name: string;
  summary: string;
  /** 这一家的原名，例如 "Codex：Read Only（read-only 沙箱）"。通用表留空。 */
  native: string;
  /** 有就置灰，写原因，一句中文。 */
  unavailable?: string;
}
/** vonvon 自己的功能（发文件、取远程图片、拒绝文字、档能不能用）只看这个，不看原生设置的细节。 */
export interface PermissionEffect { mode: Tier; network: boolean }
export interface TableEnv {
  platform: NodeJS.Platform;
  /** AgentBackend.fullAccessOnly()（Linux 上的 Codex）。 */
  fullOnly?: string;
  /** AgentBackend.supportedModes；undefined 是三档都有。 */
  supportedModes?: readonly Tier[];
}
export class PermissionInputError extends Error {}   // 中文，设置那边转成 SettingsInputError
export interface PermissionTable {
  backend: string;
  tiers(env: TableEnv): readonly [TierInfo, TierInfo, TierInfo];   // 顺序固定 qa、write、full
  /** "能挡到什么"那一行。 */
  strength(env: TableEnv): string;
  /** 校验"自定义"的原生设置，补默认值，返回新对象；不合法抛 PermissionInputError。没有自定义的表一律抛。 */
  parseCustom(raw: unknown): Record<string, unknown>;
  /** 原生设置恰好等于某一档展开的结果时返回那一档，存成档，不存自定义。 */
  matchTier(settings: Record<string, unknown>): Tier | undefined;
  effect(settings: Record<string, unknown>): PermissionEffect;
  /** 一行中文，名字后面带原名，例如 "沙箱模式：只读（read-only）；网络：开"。 */
  describe(settings: Record<string, unknown>): string;
  /** 旧的"档 + 联网开关"换成这一家的原生设置；这一家没有自定义时返回 undefined。 */
  fromLegacy(mode: Exclude<Tier, 'full'>, network: boolean): Record<string, unknown> | undefined;
}
```

三张表。`tiers()` 的 `unavailable` 共同规则：档不在 `env.supportedModes` 里 → "这个 provider 没有这一档。"；`env.fullOnly` 有值、档不是 `full` → `env.fullOnly`。

`codex.ts`（`backend: 'codex-appserver'`）：

| 档 | name | native |
|---|---|---|
| qa | 只读 | `Codex：Read Only（read-only 沙箱）` |
| write | 工作区可写 | `Codex：Default（workspace-write），比 Codex 自带的多开了网络` |
| full | 完全访问 | `Codex：Full Access（danger-full-access）` |

- `strength`：`fullOnly` 没值时 "系统沙箱管住命令的读、写和联网：工作区以外的文件读不到，也改不了。"；有值时 "Linux 上的 Codex 暂时只能用完全访问，没有沙箱。"
- 自定义：`z.object({ sandbox: z.enum(['read-only', 'workspace-write', 'danger-full-access']), network: z.boolean().default(false) }).strict()`。
- `matchTier`：`read-only` 加 `false` → qa；`workspace-write` 加 `true` → write；`danger-full-access` → full（不看 network）。
- `effect`：`sandbox` 对应 qa、write、full；`network` 是 `danger-full-access ? true : network`。
- `describe`：`沙箱模式：只读（read-only）` / `工作区可写（workspace-write）` / `完全访问（danger-full-access）`；不是完全访问时加 `；网络：开` 或 `关`。
- `fromLegacy(mode, network)`：`{ sandbox: mode === 'qa' ? 'read-only' : 'workspace-write', network }`。

`claude.ts`（`backend: 'claude-agent'`）：

| 档 | name | native |
|---|---|---|
| qa | 只读 | `Claude：Manual（default 模式），命令在沙箱里` |
| write | 工作区可写 | `Claude：Edit automatically（acceptEdits 模式），命令在沙箱里` |
| full | 完全访问 | `Claude：Bypass permissions（bypassPermissions）` |

- `strength`："命令在系统沙箱里跑，改不了工作区以外的文件；工作区以外的文件读得到，包括别的群的记忆。"（今天的实际；s31b 合入时改成那时的实际。）
- 自定义（本片的值域，s31d 扩）：`z.object({ permissionMode: z.enum(['default', 'acceptEdits', 'bypassPermissions']), network: z.enum(['off', 'all']).default('off') }).strict()`。
- `matchTier`：`default` 加 `off` → qa；`acceptEdits` 加 `all` → write；`bypassPermissions` → full。
- `effect`：`default` → qa，`acceptEdits` → write，`bypassPermissions` → full；`network` 是 `bypassPermissions || network === 'all'`。
- `describe`：`权限模式：手动确认（default）` / `自动接受编辑（acceptEdits）` / `跳过权限检查（bypassPermissions）`；不是跳过权限检查时加 `；网络：全部` 或 `关`。
- `fromLegacy(mode, network)`：`{ permissionMode: mode === 'qa' ? 'default' : 'acceptEdits', network: network ? 'all' : 'off' }`。

`generic.ts`：`genericTable(backend)`，名字和说明用 `TIER_NAMES`、`TIER_SUMMARY`，`native` 空，`strength` "这个 provider 没有说明它能挡到什么程度。"，`parseCustom` 抛 "这个 provider 没有高级设置。"，`fromLegacy` 返回 `undefined`。

`index.ts`：

```ts
export function permissionTable(backendId: string): PermissionTable;   // codex-appserver、claude-agent 各自的表，其余 genericTable
export function tableEnv(backend: Pick<AgentBackend, 'supportedModes' | 'fullAccessOnly'>, platform = process.platform): TableEnv;
export function tierInfo(table: PermissionTable, env: TableEnv, tier: Tier): TierInfo;
```

以后接新的 provider，就是在这里加一张表（product.md 3.8"以后接的 provider"）。表里的字符串都是中文，名字不超过 5 个字，用测试卡住（5.1）。

### 4.2 群的权限从哪来（`D/project/registry.ts`、`D/config/execution.ts`）

`Project` 加一项，`network` 改注释：

```ts
/** 高级设置（s31c）：这个群 provider 的原生设置。backend 和群现在的后端不同时不算（4.5 换后端时会清掉）。 */
custom?: { backend: string; settings: Record<string, unknown> };
/** s31c 起由档推出来，写的时候和档一致（TIER_NETWORK）。旧数据里和档不一致的读成"自定义"，见 groupPermission。 */
network?: boolean;
```

`D/config/execution.ts` 加：

```ts
export interface GroupPermission {
  tier: Tier;                          // 存的档，effectiveMode
  custom?: Record<string, unknown>;    // 生效的自定义（已过 parseCustom）
  legacy?: true;                       // 这个自定义是从旧的联网开关推出来的
  invalid?: true;                      // 存的自定义读不出来，按只读跑
  effect: PermissionEffect;
}
export function groupPermission(group: Pick<Project, 'mode' | 'network' | 'custom' | 'backend' | 'modelAccess'>): GroupPermission;
```

按顺序：

1. `tier = effectiveMode(group)`，存的值不是 qa、write、full 之一时按 qa（今天 `effectiveMode` 原样返回垃圾值，到这里收紧，不让它走到 `fromLegacy` 变成工作区可写）；`backendId = groupBackendId(group)`，`table = permissionTable(backendId)`。
2. `group.custom` 有值、`custom.backend === backendId`：`parseCustom(custom.settings)`。
   - 过了：`{ tier, custom: settings, effect: table.effect(settings) }`。
   - 没过（数据坏了，或者从较新版本降级回来）：按只读跑，返回 `{ tier: 'qa', invalid: true, effect: { mode: 'qa', network: false } }`，日志 `permission custom-invalid`，同一个群一个进程里只记一次。宁可收紧，不按存的档放宽。视图照 `invalid` 显示（4.4、4.7），不显示成存的那一档。
3. `tier !== 'full'`，`(group.network ?? false) !== TIER_NETWORK[tier]`：旧数据里网络和档不一致。`settings = table.fromLegacy(tier, group.network ?? false)`。
   - 有值：`{ tier, custom: settings, legacy: true, effect: table.effect(settings) }`。
   - `undefined`（通用表）：`{ tier, effect: { mode: tier, network: group.network ?? false } }`，行为不变，界面上不显示自定义。
   - `group.network` 缺省按关算，和今天 `group.network ?? false` 一样，行为不变。所以本片以后凡是写档的地方都把 `network` 写成 `TIER_NETWORK[tier]`（4.4、4.6），新写的行不会被读成自定义。
4. 其余：`{ tier, effect: { mode: tier, network: TIER_NETWORK[tier] } }`。

完全访问的旧群（建群默认 `mode: 'full'`、`network: false`）：效果的 `network` 是 true，agent 不受影响（两家后端在完全访问下本来就不看网络），但 daemon 替 agent 取回答里的远程图片（`fetchRemoteImage`）会从不取变成取。这是接受的变化，不另做兼容：完全访问的说明就是"不限制"，取图只是把 agent 已经给出的图片链接发进群。写进 v1-plan 第 5 节（第 7 节）。

`resolveExecution`：有群时 `permission = groupPermission(group).effect.mode`、`network = ...effect.network`；`sources.network` 跟 `sources.permission` 走（自定义时写 `'group'`）。没群时 `permission = defaults.permission`、`network = TIER_NETWORK[defaults.permission]`。`executionSessionProfile` 不改（它读的 `permission` 已经是效果）。

`D/config/defaults.ts`：`BotDefaultsSchema.network` 留着可选，免得旧文件解析失败，注释写明 s31c 起不读；`resolveBotDefaults().network` 改成 `TIER_NETWORK[permission]`。`D/config/store.ts:44` 跟着写推出来的值。

`D/import/bridge/conversion.ts`：导入时 `network` 写 bridge 原来的值 `rest.network ?? false`，不写 `resolved.network`（后者现在是推出来的，会把旧的不一致抹掉）。导入以后由 `groupPermission` 读成自定义，和 product.md 3.8"已有的群"一致。
