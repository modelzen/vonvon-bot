# 群组新记忆引导与导图内操作

## 做什么与范围

owner 已确认交互预览：群列表每个群只留一个新记忆入口；点击直达本群的记忆 Tab，展开、选中并定位真实的新条目。选中记忆的确认、编辑、删除、来源与撤销都在该节点内完成。目标为 `dev` 和 Mac 本地验收版本。

不改记忆存储、信任规则、Provider 或飞书消息处理，不发布安装包或修改 stable。

## 现在的代码与做法

- `LocalShell` 的数字注明新记忆；`GroupDirectory` 使用当前项目计数，只在群行放一个按钮，不增加顶部横幅或 Bot 子行提醒。同一项目的群共用项目计数。
- `App` 将群内 Bot 绑定、记忆 Tab 和一次性定位请求一起设置；`GroupWorkspace` 保留群和 Bot 身份，并把请求传至 `ProjectMemoryMap`、`MemoryMap`。
- `MemoryMap` 收到请求后按真实新条目选择目标，展开分支。超过默认八条的选中项也显示。`MindMapCanvas` 只响应一次性定位，不在轮询时反复移动视野。
- `MapNode.footer` 承载节点下方操作行，不替换记忆文本，不把操作误判为编辑器。键盘进入操作行不触发导图的快捷键。
- “仅作参考”表示已经保存；“设为可信”沿用原有确认 RPC。编辑不自动设为可信，删除沿用归档。撤销只选择产生该条目准确 revision 的事件，由 daemon 再核对冲突。
- 编辑器进入自己的保存、取消工具栏时保留草稿；取消和 Esc 不提交，正常跨节点与页面导航仍先保存。
- 来源按需展开。错误保留在可见节点或导图提示内；归档条目的错误不能因没有操作行而消失。

## 测试与 Mac 自测

- 定向测试：群入口、Tab 提示、八条以外的定位、确认及准确事件撤销、软删除、归档失败提示、既有草稿保护。
- UI typecheck、UI 测试、生产构建。
- 使用独立数据目录和停用的模拟 Bot／群，通过真实 MemoryStore 生成新记忆，不复制正式凭据、不发送飞书消息。
- 在真实网页 UI 验证计数消除、节点定位、确认／撤销、原地编辑／取消、删除／撤销和来源。
- 构建独立 Mac 测试 App，由 owner 验收；正式 App、默认 daemon、Bridge 与其数据不修改。

## 文档、验收要点与风险

`docs/product.md` 记录本次 owner 确认的引导和节点交互。验收要求群／Bot／Tab／条目身份明确，无重复内容或右侧详情框；错误和撤销不隐藏；diff 不包含真实 id、密钥或本机路径。

预估变更不超过 1,500 行。风险集中在导图视野、键盘焦点和异步撤销，均使用现有 RPC 和 revision 冲突保护，不修改数据格式。
