# 桌面账号与私聊草稿同步

## 做什么

作者选中 Bot 和已绑定群，核对群来源并让 Bot 联系已经关联的本人。飞书确认后，桌面原账号把准确候选授权给原设备，云回执给出同一私人草稿的 ID 和修订。

## 范围

本片实现 Electron Main、preload 的有限操作接口和恢复记录。双向关联、飞书可信事件及候选冻结由目标 daemon 实现，账号与草稿事务复用云端 authoring API。创作中心使用这组操作。发布仍由作者在 App 单独确认。

## 现在的代码

账号会话提供随退出、换号或离线撤销的 lease 与认证请求。桌面设备视图记录当前客户端、连接代次和已配对设备公钥。云端已实现登记、阶段授权、设备持有证明和终态查询。

## 怎么改

Main 验证原账号在线和所选设备的身份后打开有期限的 Bot 会话。Renderer 只取得不透明 handle。来源、关联证据和草稿修订均与用户看到的选择配对。启动或重开时通过原认证设备取回操作列表，再以原账号查询云状态。有明确相同绑定的操作才可复用。

授权对同一操作分为派发和保存。Main 先核对登记回执，再把派发票据交给原设备。收到可信私聊的确切候选确认后，Main 独立计算摘要，解析类型化补丁，核对草稿 ID、原修订和服务器阶段，再交付保存票据。设备负责投递和以私钥证明持有，不向设备转发账号凭据。

持久记录固定账号、设备视图与密钥、Bot、来源、操作、公钥、nonce 承诺及取消意向。敏感票据、候选内容、nonce 和账号令牌均留在其原本边界。离开页面时 renderer 交还 handle。已有操作在 Main 中继续，直到用户明确暂停、退出 App、切换账号或设备、原连接失效，或 30 分钟未操作。状态查询和心跳不延长空闲期限。重新打开时检查原设备和账号。取消请求由云行锁裁决，迟到的请求读取获胜回执。

局部改写只读取指令点名的公开字段。daemon 给本次指令分配临时请求号。Main 核对该操作的云登记或完成回执，用原账号读取同一 draftId 的确切修订，把通过隐私筛查的单个字段返回原会话。解析后再次核对修订和字段，确认保存仍检查云端修订。字段值不写入本地操作记录。

聊天上下文暂停时，已投递的原卡不能确认。App 区分聊天暂停与云操作到期；用户在原操作点「重新核验并继续」才更新原卡的动作引用，不重复发卡。

原账号重新打开或刷新时，Main 检查已投递卡片是否还有待更新的内容。即使草稿已经保存，仍能补更新同一张私聊卡片；失败时 App 保留真实草稿回执，并单独说明卡片尚未同步。

更换飞书收件人或移除管理员后，原账号在原设备、Bot 上仍可取回已撤销操作的登记信息。它们不进入可读候选或可重发的操作列表。Main 先核对云登记，再按准确 operationId 向云取消；若提交已经成功，则取回原 draftId 和修订。离线时只显示待同步，重新打开会继续仲裁。该恢复通道不要求重新关联飞书。

若登记从未到达云端，五分钟后对该 ID 的普通读取、取消都可能返回 410。Main 只接受原账号 JWT 对固定 `GET /v1/authoring/:id/recovery` 的明确结果。该端点与登记、接受及取消持同一账号锁，锁后按登记规则检查 UUIDv7：有记录就返回真实状态，旧 ID 已无记录才确认它无法再写入。此时本地状态是“已到期，之前是否保存未知”，不产生取消回执或虚构状态修订。创作中心仍可查看已经保存的草稿。离线或单独的 410 不结束跟踪；本地已知的完成回执不被替换。

daemon 保留未仲裁的确认或取消，即使离线经过八天。只有确认终态才释放活跃名额；本机的终态记录再保留七天。正常删除 Bot 之前，在原注册身份下检查是否仍有活跃草稿操作；新建与删除都按 Bot 注册表、草稿记录的顺序取锁。

## 测试

正式 IPC 拒绝任意请求、额外参数及不可信来源。预加载门面验证响应，关联确认必须匹配先前展示的证据。检查同账号重新登录、远端设备切换后旧 handle、云登记丢包、保存回执丢失后重启、取消与接受的两种顺序。每次均以固定操作和实际云草稿核对。

## Codex 自测

Mac 用临时 userData 和测试 Bot 目录启动本机 PostgreSQL 15 与正式配方 HTTP 服务。身份来自本机签名 issuer。测试飞书传输捕获真实生成的卡片、动作与发件对象，校验本人双向关联、来源群、草稿正文、聊天操作与回执。桌面 UI 和真实外部平台另由整波验收统一记录。

## 文档

私聊确认和私人草稿以 accounts-recipes 中的 PRD、chat-drafts 与 authoring-operations 为依据。资源预算沿用 limits。等集成所有切片后再在整波 implementation-status 记录实际覆盖。

## 验收要点

- Shell 展示原账号、Bot 和群的标识与名称。换群、改来源或改候选使先前确认失效。
- 先登记、再派发。先拿到云草稿回执、再显示保存的草稿和修订。
- 已取得授权但回执丢失时，恢复原操作。云服务不可用时不把取消标作成功。
- 没有通用云端 fetch、token getter、聊天发布入口。差异中仅使用合成数据。

## 风险和行数

预计约 1,200 行。并发、停机与回执错误分别通过原账号 lease、串行操作队列、立即关闭及幂等云操作覆盖。分别审查 IPC、云状态解析、原设备会话和端到端崩溃恢复。
