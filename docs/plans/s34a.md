## 4. 怎么改

### 4.1 事件和接口（`D/agent/types.ts`）

在 `AgentEvent` 联合（`174-217`）加三种，都带稳定的行 id：

```ts
| { type: 'subagent_start'; id: string; parentId?: string; name: string; task: string; stoppable: boolean }
| { type: 'subagent_step'; id: string; stepId: string; title: string; status: 'running' | 'done' | 'failed' }
| { type: 'subagent_status'; id: string; status: 'running' | 'completed' | 'failed' | 'stopped'; result?: string }
```

- `id`：Codex 用子线程的 `threadId`，Claude 用 `task_id`（子消息的 `agent_id` 就是它）。同一个子 agent 的所有事件同一个 id，这就是 3.9 要的"身份稳定"。
- `parentId`：嵌套时填上一层（Codex `thread_spawn.parent_thread_id` 不等于主线程时；Claude `parent_task_id`），顶层不填。s35 画行时可以缩进，也可以不管。
- `name`：Codex 用 `agent_nickname`，没有就 `agent_role`，再没有就"子 agent"；Claude 用 `subagent_type`，没有就"子 agent"。`task` 截到 120 字。
- `stepId`：一步的身份，Codex 用 item 的 `id`，Claude 用 `tool_use` 块的 `id`。`done`/`failed` 按 `stepId` 配对，不按标题：Codex 的 `mapItemComplete`（`event-map.ts:128-169`）和 Claude 的 `tool_result`（`170-176`）都只带 id 不带标题，而且并行的两个"读取 x"按标题会配错。
- `subagent_status {status:'running'}`：子 agent 再开一个回合时发（Codex 子线程的 `turn/started`，Claude 带新 `run_id` 的 `task_started`），行从 `completed` 回到 `running`。
- `stoppable`：一律 `true`。停不了的时候 s34b 的 `stopSubagent` 拒绝并给出原因。
- `AgentRun`（`246-257`）加 `stopSubagent?(id: string): Promise<void>`，只加类型，这一片两个后端都不实现（s34b 实现）。约定写进注释：解析成功表示已经发出停止请求，不等子 agent 真停；拒绝带中文原因（"这个子 agent 已经结束"、"这个子 agent 还没开始回合"）。
- 主过程区的那一行留着：Codex 的 `collabAgentToolCall`（tool 为 spawnAgent、sendInput、resumeAgent）映射成主过程的 `tool_use`，标题"子 agent：<prompt 前 40 字>"，`wait`、`closeAgent` 也是普通 `tool_use`（标题"等子 agent"、"关子 agent"）；Claude 父进程的 `Agent` 工具块是"子任务：…"（4.3 改 `toolTitle`）。子 agent 内部的步骤都在 `subagent_step`，不再进主过程。
