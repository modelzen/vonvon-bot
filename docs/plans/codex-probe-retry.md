# Codex 检测清理失败后的重试

## 做什么和范围

修复已确认子进程树退出、但清理报告错误后，后续 Codex 检测和设置操作永久被拒绝的问题。保留本次错误；不改变账户或安装策略。

## 现在的代码和实现

`OwnedProviderProcess.stop` 的错误目前无法统一区分进程树已退出与清理未确认。增加 `ProviderProcessStoppedError`，现有 `ProviderProcessExitError` 继承它。POSIX 仅在直接子进程退出且进程组消失后产生此类；Windows 使用已有 containment 确认状态。

`CodexSetupService` 只将未确认退出的错误留在阻断集合。已退出进程的检测仍向调用方返回原错误，设置任务仍保存失败快照；后续检测、设置和关闭不再被历史错误阻断。未确认退出的失败仍阻断新操作和关闭。

## 测试和自测

Mac 隔离临时目录中的 Node CLI fixture 覆盖非零退出、忽略 SIGTERM 后 SIGKILL 两条真实子进程路径：首次检测失败，进程死亡后重试检测、登录和关闭成功（旧实现必败）。确定性生命周期测试覆盖直接子进程已退出但进程组仍活着时重复检测不启动新子进程。未知清理错误继续阻断检测、设置和关闭。失败任务快照在重试后保留。

运行定向 daemon 测试及 typecheck；不使用 owner 数据、飞书、桌面或服务，不做全量测试。产品范围和 v1 清单不变。

## 验收与风险

- 仅整棵进程树确认退出才能解除阻断，不能只看 leader exit。
- 首次错误不被吞掉，成功重试后可正常退出。
- diff 不含真实 id、密钥或本机路径。
- 风险涉及子进程和关闭路径，需独立审查；预计约 100 行。
