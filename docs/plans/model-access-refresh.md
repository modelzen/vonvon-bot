# 群模型设置与原生能力目录

## 做什么

按 owner 2026-11-02 第三版预览及后续意见，合并模型权限、默认值和加速权限的编辑交互；删除空的可用模型行和话题模型展开列表。使用“可用模型”“可用思考强度”两个入口，无“完成”按钮。产品定义见 `docs/product.md` 3.2。

## 范围

共享 Web UI、protocol、daemon、飞书 `/model` 的能力过滤与执行校验。跨平台共用实现；不更换已安装 App、不发布。

## 现在的代码

`CompactModelSelection` 原先用两个全局多选枚举；`Catalog` 独立渲染空目录行；`ProjectModelAccess` 仅全局模型/强度数组。默认模型保存在 project，速度继承会绕过群模型设置。

## 怎么改

- 原生目录以 provider 成功返回的 model/list 能力为准；通用协议、缓存、传输保留未来 effort 字符串。Claude SDK 专有边界保留其实际支持的有限集合。
- 保留旧 `efforts` 兼容字段；增加 `modelEfforts`、`modelServiceTiers`、`defaultModel`、`defaultEffort`。同一 modelAccess 保存使用现有 revision 检查并同时更新 project 默认字段。前后端清除已取消模型的策略残留，切换 Provider 清空其旧策略和默认。前后端校验错误按字段定位，选择框标红并说明具体原因。
- UI 按能力集合分组，模型菜单放星标和加速入口，强度菜单放允许范围与默认强度。最后一个可用选项不能取消；默认取消后补选并提示。只读和失败状态不擅自清理旧选择。
- Fast/UltraFast 权限默认关闭；不提供新话题默认加速选项。只对明确支持的模型开放；曾保存而失效的权限保留清理入口。
- 群模型目录、设置保存和最终运行均执行同一权限限制；旧卡片不能改出不支持的组合。无新后台任务或退出清理逻辑。

## 测试

覆盖原生未知强度、不同能力模型分组、旧全局并集收窄、默认项取消、最小允许集、原子保存、无强度模型、刷新失败与 loading 竞态、失效项清理、速度默认关闭及旧卡片权限。原来的枚举与独立默认配置无法通过这些用例。

## Codex 自测

Mac 隔离 worktree 构建、类型检查和定向测试；Codex 浏览器验证正式组件的同能力/混合能力目录、复选框、星标、嵌套加速菜单、保存与 Escape 收起。演示目录明确标记模拟；不发送飞书消息、不操作生产 Bot。真实 Windows/macOS 打包与真实飞书交互未由组件预览替代。

## 验收要点

无空目录行、无完成按钮、默认开启的速度均为普通；实时目录只决定原生可选项；默认在允许范围内；已有话题默认值不被批量改写；失效选择可清理；diff 无真实账号 id、密钥或本机绝对路径。

## 风险和行数

通用 Effort 类型与群设置持久化的兼容风险，需要跨模块审查及相关回归；预计 1,500 行以内。若超出，按现行 AGENTS 按模块审查，不按行数拆分功能。
