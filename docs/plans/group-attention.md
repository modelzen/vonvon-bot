# 统一群注意力

## 做什么

owner 2026-11-06 确认每个 Bot 每个群共用注意力，主区和话题统一降温与合批节奏。工牌、详情、诊断和 CLI 同源，用户文案改为“注意力”，最低档采用 10“低度留意”。规则见 product.md 3.4。

## 实现

- Attention 继续由调用方注入时间，在内存保留受限的群状态和位置上下文。真人智能消息通过落地检查进入会话才刷新参与时间。模型的回复意图、skip、错误、Bot 互相唤醒、后台恢复和工具心跳不刷新。
- 参与后 2/10/20/30 分钟分别退为 75/50/25/10，之前为 100。一个既有定时器负责阶段和预算截止，关闭后清理并忽略迟到回调。
- 100 分普通消息也用 5 秒短批，其余间隔为 1/3/5/5 分钟。全群静默 5 分钟后的首批等待安静 20 秒，持续流量有首批截止。各位置保留自己的上下文和最长等待，群查看后重新计算待看批次。
- 普通消息数量不突破群冷却间隔。每次最多选最近 10 分钟内 10 条消息。
- 真人落地后产生 2 分钟的一次接续机会。话题中下一条真人普通消息可以使用，主区只限同一人；新开话题与主区共享票据。过期、消费或预算限制后失效。历史话题不恢复永久专注。
- GroupAttention 增加可选 group 字段（score、intervalMs、updatedAt）。后台广告 attention.group 能力，新客户端在 snapshot.get 单独请求新格式；WS/安全连接统一投影，旧客户端默认收到剥离 group 和 attentionModel 标记的兼容快照，覆盖事件和命令附带的快照。已有 admin.negotiate 保留给设备能力与权限。当前 UI 使用群数据及格式标记辨认旧后台，正常空记录按最低档显示。预算暂停独立显示原因，保持自然分数。
- UI 复用同一读取函数，工牌提示支持悬停、点击和键盘。最低10分对应第一段/圆弧40%填充。

## 验证

- 单元回归覆盖阶段边界、无人发言自动更新、持续无关消息不续热、群共享间隔、冷启动、短期接续、历史话题、LRU、预算与时钟倒退。
- 入站集成回归覆盖真实调度入口、合批上下文、优先消息与预算、落地和关闭。
- 协议和 UI 覆盖合法分数、旧后台、预算状态、断线/停用、异 Bot/群，以及工牌和详情同值。
- 使用隔离 HOME 构建和检查，通过浏览器查看假数据组件的工牌、详情和提示。假数据检查不作为真实飞书验收。
- 本次没有指定真实测试群，不发送飞书消息。生产数据和已安装应用保持由 owner 使用。
- PR 面向 dev，累计差异包含 protocol 和 daemon，CI 自动选择全部包与 Linux、macOS、Windows。准确 head 的 CI gate 通过后按 owner 本轮授权合入 dev。

## 风险

队列重排、定时器和异步落地需要独立审查及第二轮多角度检查。静默后无明确引用的老话题续聊，按普通批次处理，会比原永久专注稍晚。阶段时间为本轮讨论确定的初始参数，实际群体验后可调。
