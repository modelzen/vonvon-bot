# s37 会话 profile 与原生记忆关闭

## 1. 做什么
统一两家 bot 会话的启动/恢复参数，关闭原生自动记忆，避免同仓库或全局记忆串入 bot。基线为任务 108 指定 main；依赖 e04/e05 已合入实验。

## 2. 范围
本片负责 profile、后端能力报告、指令和环境映射、原生记忆关闭、Codex 主工作区会话级 trusted。不实现 s38 的个性/记忆拼装与热更新，不实现 s39 多根/能力包及 s44 个人能力隔离。预留的根/包/MCP 非空请求必须明确拒绝，不静默忽略。连接器照旧保留。

## 3. 现在的代码
`agent/types.ts` 的 StartThreadOptions 只有 cwd/model/effort/mode/network。Codex backend.startThread/resumeThread 分别拼参数，start 失败未关闭客户端。Claude backend 分别传固定指令与进程环境，thread.ts 单独传 AUTO_COMPACT_SETTINGS。两家目前没有关闭原生记忆。

## 4. 怎么改
新增 agent/session-profile.ts：后端通用的 SessionProfile、唯一默认 builder、能力说明和未支持字段检查。保留既有 StartThreadOptions 调用方式，profile 可选；backend 每次生成完整 profile，固定约定在自定义指令之前，环境沿用 daemon 环境传递策略。默认 VONVON_SESSION=1，后续 s46 可传会话令牌。

Codex 适配集中生成 start/resume 参数：保留 sandboxParams 的权限 config，合并 features.memories=false、memories.use_memories=false、generate_memories=false、projects[主 cwd].trust_level=trusted、shell_environment_policy.set。只信任主 cwd，不写 config.toml，不关闭 apps。失败关闭本次客户端，保持既有 writer-conflict 语义。标题辅助会话同样关闭记忆并传会话级 trust；预热线程关闭记忆，并对中性目录显式 untrusted，避免回写临时目录信任；Claude 标题/判断等 helper 同样关闭记忆，保留原工具与设置来源隔离。

Claude 适配把 profile 指令/env/native settings 交 SDK，保留 settingSources、现有权限和自动压缩设置。settings.autoMemoryEnabled=false 与 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 在最高优先级环境与设置 env 中共同传递，用户/项目设置不能重新开启。恢复每次重传，但原生保存的开场指令不会被替换；更新归 s38。

能力报告独立于 UI 功能 capability：说明两家指令通道、恢复时不能替换指令、哪些字段需重传；本片额外根、按路径权限、能力包、显式 MCP 尚不支持。profile 非空的未支持项在启动进程前拒绝。

实际 profile 的显式 developerInstructions 沿用既有行为，按原生优先级覆盖项目 developer_instructions；不把任务 79 未传显式字段时的项目指令快照结论冒称本片注入该项目字段。AGENTS、项目 MCP 和 exec policy 照常加载。

项目 hooks 不自动信任新定义，不写用户 hooks.state。按任务 79 原生定义哈希机制执行；workspace trusted 不代表 hooks 已获信任，hooks/list 为空不能代替实际执行证据。

## 5. 测试
main 必败：两家 start/resume 实际请求关闭原生记忆，Codex 每次主 cwd trusted 且不标其他根，shell env 覆盖用户值并带 VONVON_SESSION，Claude 保留压缩/权限并压住重新开启记忆的设置。自定义指令不替换固定约定；默认调用同样关闭记忆。非空未支持请求在 spawn/query 前拒绝。Codex start/resume 失败释放客户端并保留冲突错误。检查相邻 provider 回归。

## 6. Codex 的自测
JP-VPS 实现。不发飞书，不用测试 bot 或 accept daemon：本片 profile 可用假工作区、隔离 HOME/原生配置和 provider 适配直接验证。复用 e05 与 multi-workspace 的真实二进制/本地模型替身，分别验证正对照、关闭原生记忆 start/resume 和合成配置不回写；再用本机已登录 provider 做短集成，不复制凭据、不改个人配置和记忆。实际观察和未验边界写 PR。

任务 79 Mac 证据已先读取，其本机指针在 VPS 不存在，不声称复跑。Mac 平台差异、两版原始证据及哈希复核、Mac 真实 Codex 记忆隔离交总管短检查。项目 AGENTS/MCP/exec policy 的前置证据与本片最终实现验收分开记录。

## 8. 验收要点
- 普通 start/resume 入口都消费同一个完整 profile，未支持项不能静默忽略。
- Codex 权限 config 与 trust/env/memories 同时存在，不破坏权限档。
- 两家记忆关闭有真实原生进程证据与阴性对照；不把替身模型称远端集成。
- 不自动信任 hooks，不改用户配置，不改变权限、连接器与个人 skill/MCP 策略。
- diff 无真实 id、密钥、本机路径；Mac 未验项逐项保留。

## 9. 风险和行数
预计 700–1100 行，最多 1500（不含 lockfile）。风险为原生配置优先级、resume 原生快照、失败进程泄漏。profile 不接受任意原生配置透传；两家适配在入口集中施加固定隔离开关。超过上限先拆，不扩大到 s38/s39/s44。
