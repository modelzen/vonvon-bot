## 1. 做什么

- `D/bot/smart-intake.ts` 的 `SmartLanes`：每条 lane 一个定时器，把没点名的消息攒成"待看"，到点整批判断、标 `glance`；硬信号读待看当上下文、不带走；同一位置要进会话的落地一次一个；`prune` 移出已被别的一轮带走的；撤回、停机拆定时器。

## 4. 怎么改

### 4.1 类型：`D/bot/smart-intake.ts`

```ts
/** 一条 lane 项是哪一种 */
export type LaneKind =
  | 'named'   // 真人 @ 我、引用我：马上判，比它晚、要进会话的等它落地（H1）
  | 'aside'   // 别的 bot @ 我、叫我名字：马上判，谁也不等它
  | 'chat';   // 没点名：进待看，由 due 定什么时候判

export interface LaneEntry {
  id: string;
  /** 主区是 chat id，话题是话题 id */
  place: string;
  kind: LaneKind;
}

/** 待看里的一条 */
export interface Waiting<E> {
  entry: E;
  /** lane 收到它的时间（deps.now()） */
  at: number;
}

export interface LaneDeps<E extends LaneEntry, V> {
  /** 判 batch 里最新一条，其余是上下文。glance 为真是到点整批扫一眼。不抛 */
  judge(batch: E[], signal: AbortSignal, glance: boolean): Promise<V>;
  /** 结论要进这个位置的会话 */
  ordered(verdict: V): boolean;
  /** 落地。resolve 时这条消息已进会话的入口或已作废。不抛 */
  land(batch: E[], verdict: V, glance: boolean): Promise<void>;
  /**
   * 这个位置的待看什么时候看。undefined：马上判、不是扫一眼（今天的做法）。
   * 数：扫一眼的时间，不早于 now 的话就是马上。纯函数，不抛。
   */
  due(place: string, waiting: readonly Waiting<E>[], now: number): number | undefined;
  /** 待看超过 LANE_WAITING_MAX，最旧的被丢 */
  overflow?(dropped: E[]): void;
  fail(error: unknown): void;
  track(task: Promise<unknown>): void;
  now(): number;
  setTimer(fn: () => void, ms: number): unknown;
  clearTimer(handle: unknown): void;
}

/** 一个位置最多攒多少待看，和 RECENT_PER_PLACE 一样 */
export const LANE_WAITING_MAX = 40;
```

- `LaneEntry` 的 `named`、`aside` 两个布尔删掉，只留 `kind`。`SmartItem.wake?: true`（s27a 留着它给 `judgeSmart` 分路）不动，它不在 `LaneEntry` 上。s27a 合入后的字段名要是和这里写的不同，只改 `submitSmart`、`submitWake` 两处对应关系，写进 PR 描述。
- `Item<E>` 加 `at: number`，`Waiting<E>` 就是它去掉 `seq` 的样子；内部直接用 `Item`，`due` 收 `Item[]` 也行（结构兼容）。
- `Slot` 的 `named: boolean` 换成 `kind: LaneKind`，加 `glance: boolean`。
- `Lane` 加 `timer?: { handle: unknown; at: number }`。
- `submit(entry, verdict?)` 的第二个参数删掉。超了上限的被 @ 消息不再存在（4.5）。

### 4.2 `SmartLanes`：定时器和待看

不变式，每个公开方法返回时都成立：**有定时器 ⇔ 这条 lane 有待看、没有 `chat` 批在判、`due` 算出来的时间还没到。** 到点了而因为硬信号在判（4.3）没起跑的，没有定时器。

```ts
submit(entry: E): boolean
```
1. `closed` 回 `false`。
2. 取或建 lane，`item = { entry, seq: ++this.seq, at: deps.now() }`。
3. `kind` 是 `named` 或 `aside`：`start(lane, [item], kind, false)`，马上判。不碰 `waiting`，不碰定时器。
4. `kind` 是 `chat`：推进 `waiting`。超过 `LANE_WAITING_MAX` 就从前面丢，丢掉的一次性交给 `deps.overflow`。`lane.judging` 有值就到此为止（不设定时器）；没有就 `arm(lane)`。
5. 回 `true`。

```ts
private arm(lane): void   // 前提：lane.judging 为空
```
1. 有定时器先 `clearTimer`，`lane.timer = undefined`。
2. `waiting` 空：返回。
3. `now = deps.now()`，`t = deps.due(place, lane.waiting, now)`。`due` 抛了：`deps.fail(error)`，`t` 按 `undefined`。
4. `t === undefined`：`startWaiting(lane, false)`。
5. `t <= now`：lane 里有活着的硬信号 slot（`slots.some((s) => s.kind !== 'chat' && !s.dead)`）就返回，不设定时器，等它走了再来（4.3）；没有就 `startWaiting(lane, true)`。
6. `t > now`：`handle = deps.setTimer(() => this.fire(place, lane), t - now)`，`lane.timer = { handle, at: t }`。

```ts
private fire(place, lane): void
```
`lane.timer = undefined`；`this.lanes.get(place) !== lane` 或 `closed` 就返回；`lane.judging` 有值就返回（不该发生，防御）；否则 `arm(lane)`。重新算 `due`：额度不够时 s25g 的 `due` 会回一个更晚的时间（`freeAt`），这里就是"重设定时器"，不轮询。

```ts
private startWaiting(lane, glance): void
```
`start(lane, lane.waiting.splice(0), 'chat', glance)`。

```ts
private start(lane, items, kind, glance): void
```
照今天，加两处：slot 记 `kind`、`glance`；`kind === 'chat'` 记 `lane.judging`。`judge(entries, signal, glance)`。`finally`：`judging === slot` 就归空，然后 `settle(lane)`（取代今天的 `next`），再 `flush`、`tidy`。

```ts
private settle(lane): void
```
`!lane.judging && lane.waiting.length && !lane.timer` 时 `arm(lane)`。三处调：`start` 的 `finally`、`flush` 落地结束的 `finally`、`abort` 移走硬信号 slot 之后。这就是"硬信号落地以后，顺延的扫一眼接着来"。

```ts
dueAt(place: string): number | undefined
```
这条 lane 定时器的时间；没有定时器是 `undefined`。给测试核不变式，s25g 的日志也用。

```ts
prune(place: string, taken: (entry: E) => boolean): E[]
```
从 `waiting` 移出 `taken` 为真的，按先后返回。移出后 `!lane.judging` 就 `arm(lane)`（重算；空了就只剩拆定时器），再 `tidy`。没有这条 lane 回 `[]`。本片没有调用方；s25g 在起跑登记"已带走到"之后调它，移出不晚于那个时间的待看。

`next` 删掉。`tidy` 多一个条件 `!lane.timer`。

### 4.3 硬信号和待看

- `named`、`aside` 的批只有它自己一条（4.2 第 3 步）。待看留在 `waiting`，它们本来就在 `recent` 环里，判断读得到。这就是"读待看当上下文但不带走"。
- 硬信号判成不回、出错、超时：`waiting` 没动过，定时器照旧，到点照常扫一眼。等于"放回"，不用做。
- 硬信号说回并起跑：带走了哪几条由 s25g 的落地登记，再调 `prune`。本片只保证 `prune` 以后不变式成立。
- 硬信号在判或在落地（slot 还在 `slots` 里、没死）时到点：`arm` 第 5 步不起跑、不设定时器。它一走（`start` 的 reject 分支、`flush` 的 `finally`、`abort`）就 `settle`，`arm` 重算 `due` 再起跑。`due` 回 `undefined` 的（今天的做法、专注逐条）不顺延，照今天和硬信号并行判。

### 4.4 落地按位置串行

`flush(lane)` 对每个有结论、没在落地、没死的 slot：

```ts
const verdict = slot.verdict.value;
if (this.deps.ordered(verdict)) {
  if (lane.slots.some((other) => this.holds(other, slot))) continue;                       // H1：更早的真人 @ 先进
  if (lane.slots.some((other) => other.landing && other.verdict && this.deps.ordered(other.verdict.value))) continue;  // 串行：一次只走一个
}
slot.landing = true;
… land(entries, verdict, slot.glance) … finally：移出、flush、settle、tidy
```

- 要进会话的落地（`ordered`）一次只有一个在 `land()` 里。后一个等前一个的 `land` 结束，不管前一个是哪一种。两个同时有结论的，按 `slots` 的先后（到达顺序）。
- 不回、开话题的照今天马上落地，不等、不被等（H1 不变）。开话题的互相不撞靠今天的 `openingUnder`（`anchorLine` 查和占之间没有 `await`）。
- `holds`：`other.kind === 'named'`，其余照今天。
- 这一条让 s25g 的"后落地的认出已被带走"成立：前一个 `land()` 结束时起跑登记已经写下，后一个再查。最多多等一次落地（查锚点最多 3 秒）。

### 4.5 `pending`、`abort`、`shutdown`

`pending(): E[]`：只返回 `kind === 'named'`、没死的 slot 里的条目，按 `seq`。`aside` 和待看不返回：停机时 bot 的消息不进 dropped 文件（s27a），待看直接丢、不记诊断（v1-plan"s25 做法（关机，M7）"）。

`abort(id)` 四种情形：
1. 在 `waiting`：移出。`!lane.judging` 就 `arm(lane)`（空了就只剩拆定时器）。`tidy`。
2. 是某个批里的最新一条、还没结论、没在落地：slot 死、`ctl.abort()`、从 `slots` 移出。`judging === slot`：`judging` 归空，其余几条按原来的 `at` 塞回 `waiting` 前面，`arm(lane)`（`due` 定它们是马上判还是等）。不是 `judging`（硬信号）：`flush`、`settle`。`tidy`。
3. 只是批里的上下文：从批里移出，判断不停。定时器不动。
4. 有结论或在落地的：不动，落地前 `recalledSkip` 照旧。

`shutdown()`：`closed = true`；每条 lane 先 `clearTimer` 并清 `timer`，再把所有 slot 置死、`ctl.abort()`；清 `lanes`。顺序照今天 handle-message 的 `shutdown`：`collectLost`（读 `pending`）→ 对 `pending()` 逐个 `dropAck` → `smartLanes.shutdown()` → `onStop` → `judge.shutdown()`。定时器在 `smartLanes.shutdown()` 里拆，拆完 `fire` 不会再跑；已经在栈上的 `fire` 看到 `closed` 直接返回。

### 4.6 `JudgeBudget`

```ts
export const JUDGE_BUDGET = 60;
export const JUDGE_BUDGET_WINDOW_MS = 60 * 60_000;
/** 扫一眼用到这个数就不再扫（3.4 关注度和成本） */
export const JUDGE_GLANCE_CAP = 45;

/** 一次判断是哪一种，决定占不占、能用到几 */
export type JudgeKind =
  | 'named'   // 真人 @ 我、引用我：不占、不记、一律放行
  | 'bot'     // 别的 bot @ 我：算进 60，没有子上限（owner 2026-10-19）
  | 'name'    // 叫我名字：算进 60（s25e 起才有）
  | 'focus'   // 专注逐条，今天没点名的每条都判也是它：算进 60
  | 'glance'; // 扫一眼：用到 45 不放行

export class JudgeBudget {
  constructor(limit = JUDGE_BUDGET, windowMs = JUDGE_BUDGET_WINDOW_MS, glanceCap = JUDGE_GLANCE_CAP);
  take(chatId: string, now: number, kind: JudgeKind): boolean;
  used(chatId: string, now: number): number;
  freeAt(chatId: string, now: number, below: number): number;
}
```

- `used`：过滤窗口后的条数。过滤结果写回（和 `take` 一样，空了删键）。
- `freeAt(chatId, now, below)`：窗口里的次数降到 `below` 以下的时刻。`below` 小于 1 按 1 算。`used < below` 回 `now`。否则回 `kept[used - below] + windowMs`（`kept` 按时间升序，就是第 (used − below + 1) 早的那次满一小时的时刻）。例：47 次、`below` 45，要过期 3 次，回第 3 早的那次加一小时。
- `calls` 的结构不变：`Map<chatId, number[]>`，按 bot 进程、按群，重启清零。
- 不分 `place`：上限是每群的。

### 4.8 并发、出错、停机

| 场景 | 结果 | 怎么保证 |
|---|---|---|
| 待看有定时器，又来一条 `chat` | 拆旧的、按新的待看重算、设新的 | `submit` → `arm` 先 `clearTimer` |
| 待看有定时器，来一条硬信号 | 硬信号马上判，待看和定时器不动 | `submit` 第 3 步不碰 `waiting`、`timer` |
| 定时器到点，硬信号还在判或在落地 | 不起跑、不设定时器；硬信号一走就起跑 | `arm` 第 5 步；三处 `settle` |
| 定时器到点，`due` 回更晚的时间（额度不够） | 重设到那个时间，不轮询 | `fire` → `arm` 第 6 步 |
| `chat` 批在判，又来几条 | 进待看，不设定时器；判完 `arm` | `submit` 第 4 步；`start` 的 `finally` → `settle` |
| 两个结论都要进会话（硬信号加扫一眼，或两个硬信号） | 一次只有一个在 `land()`，后一个等前一个结束 | `flush` 的串行条件 |
| 要进会话的在落地，另一个判成不回或开话题 | 马上落地，不等 | 串行只对 `ordered` |
| 待看里的被撤回 | 移出；空了拆定时器；没空重算 | `abort` 第 1 种 |
| 扫一眼在判，批里最新一条被撤回 | 放弃判断，其余塞回待看，按 `due` 等或马上判 | `abort` 第 2 种 |
| 扫一眼在判，上下文那条被撤回 | 从批里移出，判断不停 | `abort` 第 3 种 |
| 硬信号自己被撤回 | 放弃它的判断；待看没被拿走，不用放回；顺延的扫一眼接着来 | `abort` 第 2 种的非 `judging` 分支 → `settle` |
| `prune` 把待看清空 | 拆定时器，lane 可能被 `tidy` | `prune` → `arm` → 第 1、2 步 |
| `prune` 时 `chat` 批在判 | 只移出，不设定时器；判完 `arm` | `prune` 看 `judging` |
| 待看超过 40 条 | 丢最旧的，一次 `overflow` | `submit` 第 4 步 |
| 停机 | 先 `collectLost` 读 `pending`（只有 `named`），`dropAck`，再拆所有定时器、abort 所有判断；之后 `fire` 不跑、`submit` 回 `false` | `shutdown` 的顺序；`fire` 查 `closed` |
| `due` 抛错 | 记 `fail`，这批按"马上判"起跑 | `arm` 第 3 步 |
| `judge` reject | 照今天：记 `fail`、slot 死、移出；是 `chat` 批就 `settle` | `start` 的 reject 分支 |
| `land` reject | 照今天：记 `fail`，下一个照常落地 | `flush` 的 `catch` |
| 时钟倒退（`now` 比 `at` 小） | `due` 的事；lane 只比较 `t` 和 `now`，`t <= now` 马上判 | 不处理 |

不漏、不重：
- 一条 `chat` 消息在 lane 里只在一个地方：`waiting`，或某个 slot 的 `items`。`startWaiting` 用 `splice(0)`，`abort` 塞回用原来的 `Item`。
- `arm` 不会被重入：它是同步的，只在 `submit`、`fire`、`settle`、`prune`、`abort` 里调，这些都不在 `arm` 里面。
- `fire` 是定时器回调，和别的方法不会交错（单线程）。拆了定时器就不会再 `fire`；`fire` 开头清 `timer`，所以不会出现两个定时器。
