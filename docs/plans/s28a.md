## 4. 怎么改

### 4.1 `U/settings/judgeChoice.ts`（新，纯函数，s41 也用）

```ts
export type JudgeChoiceOption = { value: string; label: string; selection?: JudgeSelection; disabled?: boolean };
export function judgeChoiceOptions(input: {
  value: JudgeSelectionView;                     // 草稿
  catalog: ModelCatalog | undefined;             // 这个后端的模型列表（purpose: 'judge'）
  decisionModels: DecisionModelsView | undefined;
  followLabel: string;                           // 群这一层传"跟着 Bot 默认"
  allowCustom: boolean;
}): { follow: JudgeChoiceOption; language: JudgeChoiceOption[]; decision: JudgeChoiceOption[]; unknown?: JudgeChoiceOption; selected: string };
export function judgeEffortChoices(value: Extract<JudgeSelection, { kind: 'llm' }>, catalog: ModelCatalog | undefined, backend: string): { value: string; label: string }[];
export function judgeLabel(selection: JudgeSelectionView, decisionModels?: DecisionModelsView): string;
export function judgeKeyNotice(selection: JudgeSelectionView | undefined, decisionModels?: DecisionModelsView): { title: string; text: string } | undefined;
```

规则：
- 先过 `isKnownJudgeSelection`（`P/settings.ts:324`）再读字段：兜底分支的 `kind: string` 只比 `kind` 收窄不了。
- 每个选项带它对应的 `selection`。`<select>` 的 value 用固定字和位置编号：`follow`、`custom`、`unknown`、`lm:<序号>`、`dm:<序号>`。选中后按 value 找回选项，不从字符串里解析模型 id（id 里可能有冒号）。
- `follow`：label 是 `followLabel`，selection `{kind:'default'}`。
- `language`：
  - 模型列表里不 `hidden` 的，label `"${displayName} · ${id}"`，selection `{kind:'llm', model:id}`，不带 effort（判断时按 `resolveJudgeModel` 取默认档）；
  - 草稿是语言模型、不是手填、又不在列表里：加一项，选中它。label 分两种：
    - 目录读到了（`catalog` 不是 undefined、`state` 不是 `unavailable`、不 `hidden` 的模型至少一个）：`"${model}（已保存，当前目录里没有）"`；
    - 否则（还在读、读失败、目录不可用或是空的）：只写 `model`。目录读不到时 daemon 也照存不核对（`D/admin/settings.ts:379`，`validateJudgeSelection` 里列表空就原样存），不能说它不在目录里。
    - `catalog: ModelCatalog | undefined` 已经分得开"还没读到"（undefined）和"读到了"；不另加字段。`ModelChoice` 的同一处（524 行的"已保存，当前目录不可用"）不照抄，也不在这一片改它。
  - `allowCustom` 时最后一项"手填模型 id…"，value `custom`。
- `decision`：`decisionModels` 每个服务的每个模型一项，label `"${displayName} 的 ${模型 displayName}"`，例如"TypeSafe 的 Jev"；`keyUnreadable` 时后面加"（读不了密钥库）"，否则 `keySet` 为 false 时加"（还没填 key）"。没填 key 照样能选（product.md 3.4）。草稿是决策模型、列表里没有（比如命令行手填的 `jev-1.13.0`）：加一项 `"${服务 displayName ?? provider} 的 ${model}"`。`decisionModels` 是 undefined（s23f 之前的 daemon）时这一组为空。
- `unknown`：草稿是不认识的 kind 时加这一项，label"这个版本不认识的设置，判断时当没设"，`disabled`，选中它。
- 选到和草稿同一个模型时，沿用草稿整项（带着 effort、backend），不算改动。
- `judgeEffortChoices`：第一项 value 空串，label Codex 写"默认（最低一档）"，Claude（`claude-agent`）写"默认（关思考）"；后面是列表里这个模型的 `supportedEfforts`；手填的用 `catalog.titleEfforts`；都没有时只有默认。
- `judgeLabel`：
  - 语言模型 `"${model}"`，有 effort 时加"（推理强度 ${effort}）"；
  - 决策模型 `"${服务 displayName} 的 ${模型 displayName}"`，查不到用原值；
  - `default` 写"各后端的默认小模型"；不认识的写"这个版本的网页不认识的设置"。
- `judgeKeyNotice`：只看决策模型。找不到这个服务返回 undefined。
  - `keyUnreadable`：title"读不了密钥库"，text `"看不出填没填 ${displayName} 的 key，读得了之前${MEANWHILE}。"`；
  - `keySet` 为 false：title"还没填 key"，text `"还没填 ${displayName} 的 key，填之前${MEANWHILE}。在密钥页填，或者在终端运行 vonvon secrets set ${keyId}，按提示粘贴。"`；
  - 填了返回 undefined。
  - `MEANWHILE` 从 `../management/secretsModel` import。

### 4.2 `U/settings/JudgeModelChoice.tsx`（新）

```tsx
export function JudgeModelChoice(props: {
  value: JudgeSelectionView;
  onChange: (next: JudgeSelection) => void;
  backend: string;
  catalog: ModelCatalog | undefined;
  decisionModels: DecisionModelsView | undefined;
  /** 这一层现在实际用的（视图的 judge.effective.selection），只用来写"现在判断用"；草稿改没改都照传 */
  effective?: JudgeSelectionView;
  /** 存着的和草稿都是"跟着上一层"时为 true：key 那一行看 effective，不看草稿 */
  showInheritedKey: boolean;
  disabled: boolean;
  followLabel: string;
  allowCustom?: boolean;
  onOpenSecrets?: () => void;
}): JSX.Element
```

依次出几行，都用 `SettingsRow`：
1. "判断模型"：`<select aria-label="判断模型">`。第一项 follow；`<optgroup label="语言模型">`；`<optgroup label="决策模型">`（空就不出）；unknown 那一项。有 `effective` 时描述写 `现在判断用：${judgeLabel(effective)}`，没有就不写这一句；不拿草稿 `value` 来写（草稿还没存，不是现在在用的）。`catalog.state` 是 `unavailable` 时描述再加一句 `catalog.error`，决策模型、手填和跟着 Bot 默认照样能选。
2. 手填模式："手填模型 id"，一个文本框（用 `Text`），描述"列表里没有的模型，比如网关的。不核对，填错了判断会出错，5 分钟内不再试。"。组件自己持有 `const [typing, setTyping] = useState(false)`，规则照 `ModelChoice`（第 3.1 节）：
   - 显示条件：`allowCustom && (草稿是 llm 且 custom: true || typing)`；这时下拉的 value 是 `custom`。
   - 选"手填模型 id…"：`setTyping(true)`；草稿是语言模型就 `onChange({...value, custom: true})`，从原来的 id 接着改；别的草稿不动，文本框是空的。
   - 选别的项：`setTyping(false)`，再 `onChange`。
   - `useEffect`：草稿变成不手填的 `llm` 或 `decision` 时 `setTyping(false)`（比如放弃修改、别处改了重读）。草稿是 `default` 时不动。
   - 文本框改成空：`onChange({kind:'default'})`，`typing` 还是 true，文本框还在，接着能输。
   - 文本框非空：`onChange({kind:'llm', model: 文本, custom: true})`；原来草稿是 llm、它的 effort 在 `catalog?.titleEfforts` 里就带上，否则不带 effort。
3. 草稿是语言模型："推理强度"，`<select aria-label="判断的推理强度">`，选项是 `judgeEffortChoices`；选默认就删掉 effort。
4. key 那一行：`judgeKeyNotice(showInheritedKey ? effective : value)` 有结果时出。title、description 照它，trailing 在有 `onOpenSecrets` 时是 `<Button size="sm" onClick={onOpenSecrets}>去密钥页</Button>`。

描述和 key 那一行是两件事：
- 描述永远写这一层现在实际用的（`effective`）。用户在下拉里选了 Jev 还没保存，描述照旧写原来的。存完 `save` 先 `refresh()`（第 3.1 节），视图里的 effective 就是新的。
- key 那一行看要不要出：
  - 草稿是决策模型：看草稿，用户正在选的这个要不要先填 key；
  - 存着的和草稿都是 `default`（`showInheritedKey`）：看 `effective`，跟着 Bot 默认用 Jev、又没填 key 的群，也要看到这一行；
  - 草稿刚改成"跟着 Bot 默认"、还没存：存完会用什么现在不知道，不出。

组件里不写"群"字，s41 的 Bot 页传自己的 `followLabel`（比如"各后端的默认小模型"）。用原生 `<select>`：`SettingsPanel.tsx` 的 `Select` 没导出，也不支持 optgroup。
