# s31d 计划：权限的高级设置

行号按 `dev` 的 `9b113b6`，以后会漂，按函数名找。路径缩写：`D/` = `packages/daemon/src/`，`T/` = `packages/daemon/test/`，`P/` = `packages/protocol/src/`，`U/` = `packages/ui/src/`。

依赖 s31c（`docs/plans/s31c.md`）：权限表、`groupPermission`、`custom` 字段、补丁语义、"自定义"的显示都在那一片。本片在它上面加编辑界面，并把 Claude 的高级设置扩到 plan、auto、沙箱开关和网站名单。设计依据：`docs/product.md` 3.8"高级设置"（本计划的文档 PR 已改）。

## 1. 做什么

用户能看到的变化：

- 群详情「工作区」→「权限」下面多一个"高级设置 ›"。展开后是这个 provider 自己支持的设置，名字是中文，后面跟原名，例如：
  ```
  高级设置（Claude）
    权限模式（permission mode）  ( ) 手动确认（default）
                                 (•) 自动接受编辑（acceptEdits）
                                 ( ) 先出方案（plan）
                                 ( ) 自动判断（auto）            ← 第 0 步过了才有
                                 ( ) 跳过权限检查（bypassPermissions）
    命令沙箱（sandbox）           [开]
    网络（network）               ( ) 关  ( ) 全部  (•) 只允许这些网站
    允许的网站（allowedDomains）  github.com
                                  registry.npmjs.org
    [保存]
  ```
  打开时预填：自定义的群填现在的自定义，按档的群填这一档展开后的值。保存后，和某一档一样的存成那一档；不一样的，档位一栏显示"自定义"。点任一档回到那一档（s31c）。
- Codex 的高级设置：沙箱模式（sandbox）三选一，网络（network）开关（选完全访问时不显示）。
- 群里没人确认，"要确认"的操作一律拒绝，所以高级设置里没有"问不问"这类设置（Codex 的审批策略、Claude 的 dontAsk 都不列），也没有"总是允许"。这一句写在高级设置的说明里。
- 私聊里能改：对 bot 说"把测试群的 Claude 改成先出方案"，bot 经设置工具写 `permission.custom`。私聊的权限卡上写"高级设置在网页端改，或者直接跟我说"。
- 命令行：`vonvon settings get --group X` 在权限下面列出能改的项和可选值；`permission.custom='<JSON>'` 照 s31c。
- Claude 的新行为：
  - 先出方案（plan）：每一轮都先出方案，发确认卡；主人或管理员点［按这个方案做］后，这一轮按自动接受编辑动手。下一轮又从先出方案开始。
  - 只允许这些网站：命令（curl 这类）和 WebFetch 只能连名单里的网站，别的被拒，原因回给 agent；WebSearch 不能用。
  - 命令沙箱关：除了跳过权限检查，命令一律不能用（群里没人确认），拒绝并说明。由 PreToolUse 钩子拒，用户或工作区设置里的 allow 规则放不过去。
  - 跳过权限检查加命令沙箱开：不问权限，但命令仍在沙箱里跑（沙箱外写不进）。
  - 自动判断（auto）：看第 0 步。

改设置的回执和［撤销］在 s55（设成自定义算扩大能力的改动）。

## 2. 范围

做：

1. 权限表加两样：`fields(env)`（高级设置有哪些项、怎么显示）和 `expand(tier)`（一档展开成原生设置，用来预填）。Claude 表的自定义值域扩到 plan、auto（第 0 步定）、沙箱开关、网站名单。
2. 自定义的原生设置传到 Claude 后端（`StartThreadOptions.native`），换算成 SDK 的选项和回调的判断。Codex 不用传：它的自定义只有沙箱模式和网络，s31c 已经换成 `(mode, network)`。
3. 网页和桌面的高级设置编辑器；私聊卡的一句说明；命令行列出能改的项；设置工具的说明。

不做：

- 回执和［撤销］：s55。
- 别的 provider 的表：接它们的那一片。
- Linux 上的 Codex：s31e。
- Claude 挡配置文件、限读：s31b。s31b 的名单对所有不是"跳过权限检查加沙箱关"的组合都生效，本片不碰。

### 4.1 权限表

`types.ts`：

```ts
export interface NativeChoice { value: string; label: string; native: string; hint?: string }
export interface NativeField {
  key: string;
  /** 中文名 */
  label: string;
  /** 原名，例如 "sandbox"、"permission mode"、"allowedDomains" */
  native: string;
  kind: 'choice' | 'switch' | 'domains';
  choices?: NativeChoice[];
  hint?: string;
  /** 另一项取这些值时才显示 */
  showWhen?: { key: string; in: Array<string | boolean> };
}
// PermissionTable 加：
fields(env: TableEnv): NativeField[];
expand(tier: Tier): Record<string, unknown>;
```

`P/settings.ts`：`permissionFieldSchema`（照上面的形状，`.strict()`），`permissionOptionsSchema` 加 `fields: z.array(permissionFieldSchema)` 和 `expanded: z.object({ qa: z.record(z.string(), z.unknown()), write: …, full: … })`。视图在 s31c 的 `options` 里补这两项。

Codex（`codex.ts`）：

- `fields`：
  - `sandbox`，沙箱模式（sandbox），choice：只读（read-only）、工作区可写（workspace-write）、完全访问（danger-full-access），`hint` 用三档的 `summary` 去掉联网那半句。
  - `network`，网络（network），switch，`showWhen: { key: 'sandbox', in: ['read-only', 'workspace-write'] }`。
- `expand`：qa `{ sandbox: 'read-only', network: false }`，write `{ sandbox: 'workspace-write', network: true }`，full `{ sandbox: 'danger-full-access', network: true }`。
- Linux 上 `fullOnly` 有值时，`sandbox` 的前两个选项带 `hint` 写原因，保存时照 s31c 拒。

Claude（`claude.ts`），自定义的值域扩成：

```ts
const DOMAIN = /^(\*\.)?([a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?\.)+[a-z]{2,63}$/;
z.object({
  permissionMode: z.enum(['default', 'acceptEdits', 'plan', 'auto', 'bypassPermissions']),   // 'auto' 看 4.0 E，不过就去掉
  sandbox: z.boolean().optional(),                // 缺省：permissionMode !== 'bypassPermissions'（s31c 存的旧形状照样读得通）
  network: z.enum(['off', 'all', 'domains']).default('off'),
  domains: z.array(z.string().trim().toLowerCase().max(253).regex(DOMAIN)).max(50).default([]),
}).strict()
```

- 解析后补齐 `sandbox`；`network !== 'domains'` 时 `domains` 置空；`domains` 去重，保留顺序；`network === 'domains'` 而 `domains` 空：抛"只允许这些网站时，至少写一个网站。"
- `matchTier`：`default`、沙箱开、`off` → qa；`acceptEdits`、沙箱开、`all` → write；`bypassPermissions`、沙箱关 → full（不看网络）。其余 undefined。
- `effect`：`default` → qa；`acceptEdits`、`plan`、`auto` → write；`bypassPermissions` → full。`network`：`bypassPermissions` 一律 true（这时网络那一项不显示，4.0 F 记下沙箱开时实际连不连得上）；其余 `network !== 'off'`。
- `describe`：`权限模式：先出方案（plan）；命令沙箱：开；网络：只允许 github.com 等 2 个网站`。
- `fields`：
  - `permissionMode`，权限模式（permission mode），choice：手动确认（default，hint "要确认的操作在群里没人确认，一律拒绝"）、自动接受编辑（acceptEdits）、先出方案（plan，hint "每一轮先出方案，主人或管理员在卡片上确认后，按自动接受编辑动手"）、自动判断（auto，hint "Claude 自己的分类器判断能不能做，不问人"，4.0 E 过了才列）、跳过权限检查（bypassPermissions）。
  - `sandbox`，命令沙箱（sandbox），switch，hint "关掉以后命令不在沙箱里跑；除了跳过权限检查，命令一律不能用（群里没人确认）。"
  - `network`，网络（network），choice：关（off）、全部（all）、只允许这些网站（allowedDomains），`showWhen: { key: 'permissionMode', in: ['default', 'acceptEdits', 'plan', 'auto'] }`。
  - `domains`，允许的网站（allowedDomains），domains，hint "一行一个，例如 github.com、*.npmjs.org"，`showWhen: { key: 'network', in: ['domains'] }`。
- `expand`：qa `{ permissionMode: 'default', sandbox: true, network: 'off', domains: [] }`，write `{ permissionMode: 'acceptEdits', sandbox: true, network: 'all', domains: [] }`，full `{ permissionMode: 'bypassPermissions', sandbox: false, network: 'all', domains: [] }`。

通用表：`fields` 空，`expand` 返回 `{}`。界面上没有字段时不显示"高级设置"。

测试卡住：每张表 `parseCustom(expand(t))` 过，`matchTier(expand(t)) === t`；每个 `fields` 的 `key` 都在自定义的 schema 里；`label` 是中文。

### 4.2 传到 Claude 后端

- `D/config/execution.ts`：`ResolvedExecution` 加 `custom?: Record<string, unknown>`（`groupPermission(group).custom`）。
- `D/agent/types.ts`：`StartThreadOptions` 加
  ```ts

  native?: Readonly<Record<string, unknown>>;
  ```
- `D/bot/handle-message.ts`：`TurnPerm` 加 `native?`；`turnPerm` 有自定义时带上；3 节列的每一处传了 `mode`、`network` 的都再传 `native: perm.native`。`resolveThread` 的 `perm` 参数类型跟着加。
- `D/agent/claude-agent/permission.ts`：

  ```ts
  export interface ClaudeNative { permissionMode: 'default' | 'acceptEdits' | 'plan' | 'auto' | 'bypassPermissions'; sandbox: boolean; network: 'off' | 'all' | 'domains'; domains: string[] }
  // ClaudeAccess 加 native?: ClaudeNative
  export function claudeAccess(mode, network, cwd, realCwd, additionalRoots?, native?: Readonly<Record<string, unknown>>): ClaudeAccess;
  ```

  `claudeAccess` 用 Claude 表的 `parseCustom` 再解析一次 `native`；解析失败按只读跑（`mode: 'qa'`、`network: false`、不带 native），日志 `claude-native invalid`。`mode`、`network` 照旧是效果。

- `permissionOptions(access)`，有 `native` 时：
  - `permissionMode = native.permissionMode`（没有 native 照旧 `tierMode(access.mode)`）。
  - `native.sandbox` 假：不给 `sandbox`。`access.mode === 'full'` 照今天直接返回 `base`。
  - `native.sandbox` 真：`sandbox` 照今天（`enabled`、`failIfUnavailable`、`autoAllowBashIfSandboxed`、`allowUnsandboxedCommands: false`、filesystem 名单）。`access.mode === 'full'`（跳过权限检查加沙箱开）只给 `enabled` 那几项，不给 filesystem 名单。
  - 网络：`off` 照今天 `disallowedTools: NETWORK_TOOLS`；`all` 照今天 `allowedTools: NETWORK_TOOLS`；`domains`：`sandbox.network.allowedDomains = native.domains`，`allowedTools = native.domains.map(d => \`WebFetch(domain:${d})\`)`，`disallowedTools = ['WebSearch']`（4.0 A、B 定下的写法为准）。
  - vonvon 自己的工具：4.0 G 要求时，`allowedTools` 一律带 `mcp__vonvon_bot`，和网络那几项合并，不互相覆盖。
  - 钩子：写文件的照旧（按 `access.mode`）。`native.sandbox` 假、`access.mode !== 'full'` 时再加一个 `matcher: 'Bash'` 的 PreToolUse 钩子，一律 deny，原因见下。钩子的 deny 在 allow 规则之前生效（4.0 D 验证），这样用户或工作区设置里的 `Bash(...)` allow 规则放不过去；agent 在工作区可写档里自己往 `.claude/settings.json` 加 allow 规则（s31b 合入前还写得进）也没用。
- `decide()`，有 `native` 时多三条，放在今天的网络判断那一段：
  - `network === 'domains'`：`SandboxNetworkAccess` 的 `host`、WebFetch 的 `url` 的主机名，命中名单（相等，或者名单项是 `*.x` 而主机以 `.x` 结尾）→ allow；否则 deny："这个群只允许访问这些网站：{前 5 个}{等 N 个}，连不上 {host}。换个办法，或者停下来说明。" WebSearch → deny："这个群只允许访问指定的网站，不能搜索。"
  - `native.sandbox === false`、`access.mode !== 'full'` 的 Bash，钩子和回调两处都 deny（回调是兜底，不分 `decisionReasonType`）："这个群关了命令沙箱，命令要人确认，群里没人确认，这一步不做。换个办法，或者停下来说明。"
  - auto（4.0 E 过了才有）：照 E 测到的进回调的样子处理；拒绝文字照今天"超出这一档"的写法。

### 4.6 并发、出错

- 自定义在会话开始时定；改了以后照 s31c 驱逐会话，下一轮按新的起。
- 一轮里 plan 被确认后切到 acceptEdits，只对这一轮和这条会话后面没回到 plan 之前生效；下一轮开头切回 plan（4.2）。`setPermissionMode` 失败只记日志，这一轮按 SDK 当时的模式跑，不会比 acceptEdits 更宽。
- 坏的 native：后端按只读跑（4.2），执行层按只读跑（s31c 4.2），两边一致。
- 网站名单最多 50 个；`*.x` 只匹配子域，不匹配 `x` 本身（要两个都写）。
- 降级：s31c 存自定义时把 `mode`、`network` 写成效果，降级到 s31c 以前的版本时旧版本按它们跑（s31c 4.8）。本片加的组合，照效果写会变宽，所以 Claude 表加
  ```ts
  /** 存盘用的档和网络，只给降级到 s31c 以前的版本看；不比这个自定义宽。 */
  stored?(settings: Record<string, unknown>): { mode: Tier; network: boolean };
  ```
  plan → qa（确认前是只读）；跳过权限检查加沙箱开 → write（旧版本的完全访问没有沙箱，更宽）；`network === 'domains'` → `network: false`；其余等于效果。s31c 的保存改成 `table.stored?.(settings) ?? effect`。`groupPermission` 不看存的 `mode`、`network`（有自定义时按自定义），所以只影响降级。

### 规矩（原样照做）

- 临时目录只用 `T=$(mktemp -d)` 建，只用 `rm -rf -- "${T:?}"` 删，或者删刚在 `/tmp/` 下建的字面路径。
- 不对 `$HOME`、`~`、`$PWD`、`$VONVON_HOME` 或任何可能为空、未设置、指向真实 home 的变量拼出来的路径用 `rm`、`find -delete`、`find -exec rm` 或 `xargs rm`。
- 不在 shell 里给 `HOME`、`VONVON_HOME` 赋值或 export，只写在单条命令前面，例如 `HOME=$T/home VONVON_HOME=$T/vh npx vitest run`。
- 每次调用工具是新的 shell，`T` 不会留下来：建完把 `mktemp -d` 打出的路径记下，后面的命令在同一条命令里写 `T=<那个字面路径>` 再用 `$T`。
