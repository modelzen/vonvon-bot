# Vonvon Bot UI / UX 优化方案

日期：2026-10-24。状态：owner 已认可模型与权限设计稿并要求尽快实现；首批 F09、F04 的局部恢复入口、F03 的紧凑页头已实施，待本地验收。其余发现保留为后续方案。

## 1. 评估对象与结论

以本机正在运行的 communication-a54ee41 验收 App 和对应源码 a54ee419323b93ea02e61802be8627c3e06a2323 为准。主 checkout 的 main 仍为 cf5ec97d，不能拿它代表当前界面。

实际查看：概览、Bot 列表与详情、Bot 记忆与角色编辑、群组树、群内模型与权限、能力、沟通方式、项目记忆、设置首页、Provider 列表与 Codex 详情。实际窗口为 1000 × 800。对真实界面仅做导航、查看、滚动与关闭本轮产生的建议草稿，没有保存配置、切换权限或聊天方式、发送飞书消息、安装工具或连接第三方服务。进入记忆页会触发产品已有的已读标记逻辑。

当前界面已有一致的 macOS 字体、紧凑控件、克制的白色分组和清楚的主导航。优先收益来自让编辑及时出现、减少页面顶部占用、明确状态与恢复动作。无需先更换视觉风格或组件库。

owner 补充重点：模型全部展开的长列表显得松散，类似控件级细节也必须优化。把 F09 的紧凑模型选择列为第一批重点，连同 Effort、Provider、权限摘要、重复标题和禁用态一起设计，不能只做流程梳理。

### 开发与合入基线

owner 明确要求：修改从 `dev` 创建分支，最终 PR 目标也是 `dev`。本次实施从 `origin/dev@212cd51d5a5005d5bd18a87ad3f1b38c498e3c2a` 创建分支，限于已认可的模型与权限页及紧凑页头；未整合另一验收分支的导航、记忆和滑轨改动。

核对结果：模型全量列表、独立 Effort 多选、Provider 提示、初始草稿 dirty 逻辑在 dev 中仍存在；技能列表和最近对话的目标代码未变化。记忆面板的 dev 布局与 App 不同（dev 默认横排、900px 以下纵排），F02 的具体 1200px 阈值问题只适用于 a54ee419。F03、F07 依赖群导航和滑轨方案进入 dev 后再落实。权限细节必须保留 dev 已有的原生高级设置与保存行为。

本轮没有验证首次扫码、真实消息往返、键盘全流程、深色模式、宽窄窗口和大规模数据。相关内容只列后续验收标准，不作为已发现缺陷。

## 2. 保留的已定方向

- 主导航继续为“概览、Bot、群组”，搜索和设置留在工具栏。
- 群组继续采用“群 → Bot”的树，群行负责展开，Bot 行进入本群设置。
- 本群设置顺序继续为“模型与权限 → 能力 → 沟通方式 → 记忆”。
- 记忆继续用导图呈现，点击节点后编辑；项目自身记忆可编辑，来自 Bot 的角色和记忆只读。
- 沟通方式继续采用“独立话题、连续交谈、智能”的三档滑轨，保留用户选定的滑块与刻度表现。
- 健康空闲的关注度继续显示 0 / 100、待互动；不可用继续与零值区分。
- 模型和 Effort 继续独立多选，不改为单一默认模型选择。
- 不借这轮设计调整权限语义、记忆继承规则或 Provider 行为。

## 3. 具体发现与修正方案

优先级：P1 是影响操作理解或效率、应先处理的事项；P2 是后续打磨。本轮没有把审美偏好当成必须修复的缺陷。

### F09 · P1 · 首批重点：模型列表与 Effort 不应长期全部展开

owner 截图与实机一致：七个模型各占一整行，宽行里只有名称和复选框；“可用模型”作为外部标题和内部图例出现两次。单个 Provider 仍占一个选择区，随后是整排 Effort，权限内容被推到下面。这既影响精致度，也让常用页面承担了偶尔编辑时才需要的信息量。

推荐默认页面采用一组紧凑设置行：

| 设置 | 默认显示 | 点击后 |
| --- | --- | --- |
| Provider | Codex + 准确状态 | 多个 Provider 时才出现选择入口；单个时显示静态名称，检查入口独立 |
| 允许的模型 | 前 1–2 个已选名称 + 其余数量；右侧“选择模型” | 打开有搜索的复选列表；已选数量始终可见，保留多选 |
| 思考强度（Effort） | 已选项的短摘要；右侧“选择强度” | 独立的多选面板，只展示当前目录支持的选项；提示模型兼容性 |
| 权限 | 当前档位 + 一句实际范围；右侧“修改” | 展开三档完整对比后再选择，保留现有权限提交逻辑与后果说明 |
| 高级权限 | 收起的“高级设置” | 保留 dev 原生字段、当前值、校验和独立保存动作 |

具体规则：

- 模型摘要最多两行，名称过长省略并可查看完整值；超出部分用“另 N 个”表示，不把所有已选项再次铺成长墙。全部已选时写“全部 N 个模型”，同时保留查看入口。
- 选项保持目录的稳定顺序；勾选时不跳动。搜索隐藏某些行时仍保留那些模型的选择，不以可见项覆盖全部集合；无结果时明确提示。
- 弹层内“完成”仅更新该区草稿并关闭，“取消”丢弃本次弹层修改。页面显示“未保存”与“保存更改 / 放弃”，沿用 modelAccess 一次提交 Provider、模型和 Effort 的现有 revision 检查；不做隐式自动保存。修改模型后可继续调整 Effort，避免中间组合被提前持久化。
- 零选择、未被当前目录列出、模型与 Effort 不兼容均沿用实际校验；“已保存但当前未列出”的模型可读、可追溯，不能自动删掉。群内可选 Effort 仍由模型实际支持集合决定。
- Provider 不可用时只出现一条就近的状态说明与恢复入口；保存的模型和 Effort 摘要保持可读，查看列表也可达，修改依照现有可用性约束禁用。不要用整块低透明度处理名称和说明。
- 标题统一为“执行模型”，其内部行名不再重复“可用模型”。选中模型不再给整条 800px 宽行染蓝；摘要用中性色文字，选择弹层中用复选框与轻选中底色表达。

验收：1000 × 800 下不滚动就能看到 Provider、已选模型、Effort 和权限摘要；1、7、30 个模型时页面主区域高度基本稳定；勾选多项、搜索后勾选、取消、完成、保存和失败均不丢数据；模型和 Effort 保持独立多选；键盘可打开、搜索、勾选、关闭并返回触发按钮。默认页面短，并不以缩小字体和点击区域实现。

源码：GroupDesignSettings.tsx 的 ModelAccessFields、ModelAccessChoices；此处模型选择的主体实现与最新 dev 一致。

### F01 · P1：未输入内容，也会被提示有未保存修改

实机确认：打开一个空角色设定的“身份与职责”，导图显示 0 / 500 字，编辑器自动填入一段建议文字；没有输入任何内容，点击关闭就出现“有未保存的修改”。已重复查看，均通过“放弃并离开”关闭，没有保存。

源码原因：GroupDesignSettings.tsx:294 将 roleInfo.draft 传入 Editor.initialDraft；SettingsPanel.tsx:131、153 按 draft 中是否有字段判断 dirty，而不是按用户是否实际修改。

建议：空值继续为空；建议文字作为占位提示，或通过明确的“采用建议”动作放进输入区。只打开、聚焦或关闭不应产生离开确认。用户采用建议或实际修改后，继续保留现有保存、放弃、冲突保护。导图上的字数只计已保存内容，编辑器里的草稿字数加“未保存”标记。

验收：打开空节点 → 不输入 → 关闭，不出现确认；输入后离开出现确认；保存失败留住输入；成功后导图字数与持久化值一致。

### F02 · P1：记忆详情在默认窗口下被放到导图下方

实机确认：点击 Bot 的角色节点后，详情面板排在导图下面；1000 × 800 窗口中只看到面板开头，主要输入和保存动作在视野以下。

源码确认：MemoryMap.tsx:200–205 顺序排列画布和详情；mind-map.css:57 默认单列，仅在容器至少 1200px 时并排。today.css:6、28 的常规内容宽度为 840px，这个阈值在当前页面约束下通常无法达到。单纯把窗口拉大也未必解决。

建议：1000px 默认窗口点击节点时打开约 320px 宽的右侧覆盖式检视面板，不把整张导图和页头向上推。面板标题固定，保存动作固定在面板底部；关闭回到原节点。宽窗口且画布与面板都能正常阅读时再并排，同时为记忆页解除通用 840px 上限。窄窗口使用覆盖面板，保证输入和关闭可达。

统一角色编辑和记忆正文编辑的入口：节点用于选择和短预览，编辑放在检视面板，避免一种节点在图上展开 textarea、另一种节点在整图下方编辑。可写节点、只读继承节点要在面板标题直接标明；只读详情提供“打开 Bot 记忆”的明确入口。

验收：1000 × 800 下点击任意可编辑节点，一次点击即可看到输入区；无需滚动整页寻找保存；Esc 和关闭回到触发节点；切换节点不丢草稿；长文、长来源和失败反馈不把按钮推出可操作范围。

### F03 · P1：群设置顶部占用过多，当前对象与操作范围不够集中

实机确认：群名、本群 Bot、项目入口、四个标签页分别占一行并留有较大间隔；内容约从窗口 y=400 开始。记忆树因此只展示上半段，模型列表把权限推到很下方。

建议布局：

1. 第一行：返回群组；群名与“飞书打开 / 更多”。
2. 第二行：Bot 头像和名称 + “在本群使用”开关；项目名称和次级入口与它相邻。
3. 第三行：四个设置标签页。
4. 随后直接进入内容。目标是在默认窗口中释放约 100–130px 垂直空间，以实际截图验收，不以像素目标替代可读性。

只有一个 Bot 时，用明确的当前 Bot 身份行；多个 Bot 时保留可切换控件。项目入口继续保留；“换到别的项目”收进项目入口的次级操作，确认时仍明确记忆、工作区和会话影响。滚动长内容时，保持一个紧凑的“群名 · Bot / 当前标签”上下文。

验收：长群名与多个 Bot 不遮挡开关；进入页面立即能确认“我正在修改哪个 Bot 在哪个群里的设置”；默认窗口第一屏能够看到实际设置内容。

### F04 · P1：Provider 不可用时，页面缺少直接恢复路径

实机确认：群模型页显示 Codex 当前不可用、模型和 Effort 灰掉，说明只说完成安装与登录。跳到 Provider 详情后，又同时看到上方“安装 / 待检测”和下方安装位置“本机已有”。Bot 的飞书连接状态仍是“已连接”。

这不是证明登录失效或 Provider 后端有故障；本轮未做诊断或修复。问题是 UI 没说明“飞书连接”和“模型执行准备”属于不同状态，也没清楚区分未检测、未安装、未登录和目录读取失败。

建议：在模型页放一个局部状态区，包含“当前已知状态 + 下一步”。无法确定原因就诚实写“尚未验证”，不要推断“未安装”。提供“检查 Provider”和适用时的“重试模型读取”，处理后返回原群、原 Bot、原标签。保留已存选择并标注“已保存，当前不可验证”。禁用态仍需能读清内容。

Provider 页把安装、账号、模型读取分开表达；已确认安装位置后，不继续用含糊的“待检测 / 安装”作为主动作。准确动作随真实状态变化，不仅更换图标颜色。

验收：未安装、未登录、读取失败、未检查四种状态各有准确文案；任何入口都不把“飞书已连接”解释成“执行模型可用”；返回恢复原上下文；不误报告检查成功。

### F05 · P1：技能列表同名项无法辨别，摘要以 Agent 指令为主

实机确认：能力页中两个 anysearch 条目同名、同描述，列表中看不到来源；agent-reach 的说明以 MUST USE 和触发词列表开头。现有列表已经截断说明，问题不是没有截断，而是截断后仍缺少面向用户的用途摘要。

源码确认：GroupDesignSettings.tsx:243–248，列表只显示 name、description 和开关，来源与完整路径在详情弹窗里。

建议每行：名称 + 一句用途摘要 + 来源标记 + 开关。来源使用已有的“本群工作区 / 用户目录 / Provider”；同名时进一步显示安全的短路径或来源包名。完整原始说明和绝对路径留在详情中。增加来源和启用状态筛选，搜索继续覆盖名称与说明。若需要中文摘要，先采用受控摘要字段或明确标记的展示摘要，不改原 Skill 说明与加载含义。

文案用“配置为启用 / 在下一轮加载”等与真实合同一致的状态，不能因开关开启就写“已验证可调用”。工具授权和安装继续由“工具与连接”管理。

验收：两份同名技能不用逐个开详情也能区分；长名称与中英文混排不挤压开关；筛选不改变实际启用配置；完整说明仍可查看。

### F06 · P2：最近对话的时间和点击目标不清楚

实机确认：多条最近对话具有相同群名，缺少时间；整行主体跳飞书，右侧常见的向右箭头却进入群设置，容易让用户误判两个点击区域是同一动作。

源码确认：TodayHome.tsx:32–34 的两个动作目的地不同；protocol/domain.ts:261 已有 updatedAt，UI 未显示。

建议：主题摘要作为主要文字，群名和 Bot 作为次要信息，右侧显示“刚刚 / 昨天 / 日期”；没有摘要才用群名兜底。主体明确表达“在飞书继续”，尾部设置入口改用设置图标与可访问名称，必要时在行菜单显示文字。不同会话即便摘要相同，也保留独立记录，用时间区分，不擅自去重。

Bot 列表保留为轻量管理入口，不填充虚构运行指标；概览继续服务“继续最近工作”，不增加装饰性 KPI。

验收：用户能识别两个相同群名条目发生在何时；行主体与设置操作目的清楚；没有时间或摘要时有正常降级。

### F07 · P2：沟通方式名称在不同页面不一致

源码确认：群内三档叫“独立话题 / 连续交谈 / 智能”，GroupDirectory.tsx:75 的列表摘要仍使用“多会话 / 单会话 / 智能”。本次真实数据只展示了智能，没有把前两种实际渲染声称为已测。

建议：日常 UI 统一为用户已选定的三档名称，内部枚举和历史文档保持兼容。滑轨下保留当前档的一句解释；智能模式下沿用关注度组件，把决策模型作为紧邻的配置区，完整判断规则可通过“查看与编辑判断规则”展开。不要用折叠改变规则正文或保存语义。

验收：列表、设置、绑定流程和群内说明叫法一致；已有规则群和智能群语义不变；鼠标和键盘都能获取各档介绍；不把关注度零值标成异常。

### F08 · P1：页面间的滚动位置缺少明确归属

实机观察：首次从已滚动的群设置切到概览，概览标题与部分 Bot 行在视野上方，需要主动滚回顶部；独立重演需在长页完成加载后滚动，避免在“正在读取”空页上测试。

源码佐证：LocalShell.tsx 复用同一个 settings-content-scroll；App.tsx 的 openPage、openList 等导航没有常规路由滚动复位。搜索定位的 scrollIntoView 是另一条逻辑，不应被复位覆盖。

建议：主导航进入新页面默认到顶部；从详情返回列表恢复这个列表自己的滚动、搜索和展开状态；设置捷径返回原群保留其位置；搜索结果跳转优先执行定位。记忆面板打开不应借整页滚动来露出编辑器。

验收：长群设置滚到底 → 概览，标题和首行可见；列表滚到中间 → 详情 → 返回，仍在原处；搜索跳转仍定位到目标；草稿保护仍先于导航执行。

## 4. Designeer 如何用于本轮

Designeer 的作用是提供经过筛选的参考入口。本方案中的缺陷来自本机实际界面与源码，不是资源目录自动给出的诊断。

| Designeer 收录方向 | 选用参考 | 在 Vonvon Bot 中落实 |
| --- | --- | --- |
| 产品流程与细节 | Mobbin、Details、60fps | 研究设置跳转后返回、检视面板、保存与错误反馈；每个问题挑少量相关案例，不借营销页面决定 App 布局 |
| 组件模式 | Component Gallery、Base UI、Radix | 比较表单、选择、弹窗和树结构的状态；实现优先复用项目已有 Base UI |
| 配色与可读性 | OKLCH、Color.review、Huetone | 检查现有灰阶、禁用态、选中态和警告态；以对比度验证为准，不仅凭肉眼调浅 |
| 动效 | Motion Primitives、NumberFlow、60fps | 借鉴面板和状态变化；项目已有 Motion，通常无需新增动效库 |

官方入口：[资源目录](https://designeer.xyz/resources)、[灵感目录](https://designeer.xyz/inspiration)、[网站介绍](https://designeer.xyz/info)。前轮已实际读到首页和介绍页，资源与灵感条目另由官网搜索收录内容核对；本轮继续直接访问受到 Cloudflare 限制。没有验证 Designeer WebMCP，也不把它作为落地前提。未假装已查看这些外部产品的全部付费案例。

实现参考：[Base UI Dialog](https://base-ui.com/react/components/dialog) 支持定位式面板和焦点管理；[Motion 无障碍说明](https://motion.dev/docs/react-accessibility) 给出 reduced motion 支持。这里只取设计模式，不复制外部品牌外观。

## 5. 视觉与交互规格建议

这轮按组件逐项打磨，不只改页面结构。下表为明确的检查与设计范围，其中未在实机复现的状态属于后续验收项。

| 细节 | 统一处理 |
| --- | --- |
| 多选 / 下拉 | 稀少且高频的选择可直接展示；较长模型集合采用摘要 + 可搜索多选；单选和多选外观与文案明确区分 |
| 标题与分组 | 每组一个主标题，行名只描述字段；去掉双重“可用模型”和不必要的卡片嵌套 |
| 对齐与留白 | 左侧名称、中间值、右侧动作；关键动作竖向对齐；间距分为组间与组内两级，避免每项都占等量大空白 |
| 权限选择 | 默认展示当前状态，编辑时再展开完整对比；不将高级权限或风险差异藏入不明显的悬浮提示 |
| 长名称与同名项 | 主要名称保留可识别部分，来源或路径用于区分；不靠用户逐个打开弹窗辨认 |
| 禁用 / 加载 / 失败 | 保留可读文字；禁用说明原因并给可行下一步；读取失败不伪装空列表或未安装 |
| 保存与反馈 | 需要组合校验的字段统一草稿、明确保存；现有即时开关不擅自混成批量提交；反馈紧邻触发动作 |
| 图标与菜单 | 图标与实际目的对应；跳外部、打开设置、展开内容不共用一个含糊的右箭头 |

- 字体继续用系统字体与苹方；保留现有 22 / 15 / 13 / 12 / 11px 字级。正文与可操作的关键说明用 13px，12px 放辅助说明，11px 仅放时间等次要信息。
- 蓝色用于选中、焦点和主操作；颜色必须配合文字或图形表达状态。来源和继承不各自增加一套鲜艳颜色。
- 分组表面继续白色与轻边线。列表主要靠排版、缩进与分隔组织，避免每行再嵌套卡片。
- 保留现有 28–32px 桌面控件；键盘焦点清楚可见。触摸场景再使用更大的热区，不把所有桌面行强行改为大按钮。
- 标签页切换即时；侧面板可用约 160–200ms 的进入退出；点击反馈约 90–140ms。反复键盘操作不排队播放动画；减少动态效果时取消位移。当前滑轨的行为沿用，不擅自替换。
- 保存反馈靠近操作区：保存中、已保存、失败保留输入、冲突可恢复分别表达。“已保存”与“下一轮生效”各自说明真实含义。
- 空记忆在导图内给一个可操作入口；空的只读继承支默认以简短摘要呈现，需要时展开，避免零条内容占掉大半张图。

## 7. 后续验收清单

1. 在隔离数据目录，从本轮选定的准确提交构建。真实用户配置仅做 owner 验收，自动测试不得改动。
2. 窗口检查：1000 × 800 为主，另查 1280 × 900 和 760 × 700；支持更窄网页时再验证其降级。此处是测试计划，未实测这些尺寸。
3. 数据检查：零记忆、接近项目 100 条、12 分支、长群名、多个 Bot、同名 Skill、很长中英文说明。
4. 状态检查：初次加载、未登录、未检查、目录读取失败、保存失败、并发修改、来源不可用。
5. 键盘检查：Tab、Shift+Tab、Enter、Esc、三档滑轨方向键、检视面板打开和关闭后的焦点。
6. 导航检查：主导航、返回列表、从群进入全局设置再返回、全局搜索定位和未保存保护。
7. 模型检查：界面允许的组合与实际 Provider 合同一致；已有配置不因视觉改动丢失；不把界面检查报告成真实飞书或模型行为验收。
