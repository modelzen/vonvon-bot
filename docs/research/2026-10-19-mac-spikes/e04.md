# e04（Codex）：沙箱里连本机、环境变量和 git 提交

2026-10-19 在 owner 的 Mac 上由 Mac 任务 45 实测。代码引用以 `main` 的 `84162db` 为准。本报告覆盖 `docs/product.md` 第 9 节第 2、4 项的 Codex 一半，对应 `docs/v1-plan.md` 4.1 的 e04，影响 s37、s39、s46、s47。

## 结论

1. **本机连接。** 当前 Codex 0.162.1 和最低版 0.156.1 的关网只读、关网读写档，curl 到本机 TCP 与 Unix socket 均未到服务端。当前版的开网只读档，以及当前版和最低版的开网读写档，curl 两路均到服务端且收到 pong。当前版完全访问档的 curl、Node、Electron 五路均到服务端。受限档的 Node 与 Electron 在连接前分别卡在 OpenSSL 配置文件和 dyld 框架读取，不能据此断言 Node 或 Electron 的网络权限。
2. **环境变量。** 两版本所有完整捕获轮次中，`FEISHU_CODEX_BRIDGE=1`、`VONVON_SESSION`、假 `E04_SESSION_TOKEN`、假 `E04_SESSION_TICKET` 以及 `shell_environment_policy.set` 注入的普通名与 `TOKEN` 名都按标签进入 shell。故本实验否定“变量名带 TOKEN 必被过滤”的绝对说法；未测真实凭据。四个代理变量均未设置。
3. **命令行替身。** 两版本的所有受限档中，所用 nvm Node 因 OpenSSL 配置读取被拒而不能启动；Electron 44.4.5 因 dyld 无法加载框架而不能启动。`/Applications/ChatGPT.app` 中 codex 的一字节读取与 `--version` 均成功，HOME 下包装脚本的一字节读取均被拒。完全访问档 Node、Electron、外部脚本与包装脚本一字节读取成功。打包版 Vonvon app 未测。
4. **Git。** 两版本的读写档都能写工作区和第二根，但 `git --version` 与 `git add` 已在读取 `/Users/<u>/.gitconfig` 时被拒，两个根没有实验提交。当前版两种显式放开 `.git` 的可选配置仍在同一步失败，因此没有证据认定 `.git` 只读是唯一原因，也没有试到 index.lock 写入。完全访问档两个根均有 `e04 cur-full` 提交。
5. **第二根与说明文件。** 两版本每轮的 `runtimeWorkspaceRoots` 回包均回显工作区与 repo2；读写档第二根写入落盘。`instructionSources` 只列全局 AGENTS.md 和工作区 AGENTS.md，没有 repo2 的 AGENTS.md。

## 怎么测

- 环境：macOS 26.7（25G229）、arm64；Node v24.14.1，`E04_NODE=/Users/<u>/.nvm/versions/node/v24.14.1/bin/node`。实验 Git 为 `/Applications/Xcode.app/Contents/Developer/usr/bin/git`，Apple Git 2.54.0（Apple Git-157）；受限档自身的 `git --version` 失败。
- 当前版：`/Users/<u>/.nvm/versions/node/v24.14.1/bin/codex`，0.162.1；最低版：`<R>/c156/node_modules/.bin/codex`，0.156.1；另有 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`，0.163.0-alpha.10.2，做了一轮可选只读关网。未发现 `/Applications/Codex.app` 作为所选 app 替身。
- Electron 44.4.5 装于 `<R>/el`，沙箱外 `ELECTRON_RUN_AS_NODE=1` 自检成功。所有被测会话模型为 `gpt-6-luna`。每轮模型只执行 `sh ./probe.sh`，普通 `/bin/zsh` shell 包装；探针各项失败仍继续。服务在沙箱外同时监听 `<回环地址>:<端口>` 与 `<R>/s/e04.sock`，用 `cfg` 和假会话值核对实际收件。
- 相对现有产品调用，试验额外传入 `runtimeWorkspaceRoots`、会话级 `projects.<根>.trust_level`、`shell_environment_policy.set`、`features.memories=false`、`ephemeral=true` 和一句实验限制 `developerInstructions`；父进程传给 app-server 前移除除 `CODEX_HOME` 外的 `CODEX_` 变量。未改 owner 的配置来设置项目信任。`approvalPolicy=never`；服务端无审批请求。
- 0.156.1 原先几轮的旧 app-server 通知只记录了命令执行的尾段。恢复轮记录 `commandExecution/outputDelta`，并在探针操作前等待 1 秒；探针操作、权限、环境、模型不变。使用 `*-observed` 轮次填完整结果；原轮单列记录，不把未捕获的开头当失败。
