# e04（Claude）：沙箱里连本机、环境变量、git 提交和附加目录

2026-10-19 在 owner 的 Mac 上由 Mac 任务 46 实测。代码引用按 `main` 的 `84162db`。对应 `docs/product.md` 第 9 节第 2 项的 Claude 一半，也回答 `docs/v1-plan.md` 4.1 的 e04；结果影响 s31、s37、s39、s46、s47。

## 结论

1. **连本机：** 六轮的 Bash 都能启动。没有网络放行时，`curl --noproxy '*'`、Node 和 Electron 的 TCP 直连均没有到达本机服务；Unix socket 也没有到达。今天的 `bypassPermissions` 两档通过沙箱注入的 HTTP 代理到达本机 TCP，且 `NET` 返回 200。因此今天的“关网”配置不能当作禁止 Bash 网络访问的证据。候选 `default` 档的代理请求被回调拒绝；候选 `acceptEdits` 档回调放行本机后，代理请求到达服务。给沙箱加 `network.allowUnixSockets` 后，Unix 的 curl、Node 都到达；同轮 `network.allowedDomains` 包含本机名称及地址，TCP 直连仍报 EPERM，代理请求到达。此实验不能把代理和域名配置各自的作用分开归因。
2. **环境变量：** 六轮 Bash 都看到 `FEISHU_CODEX_BRIDGE=1`、`VONVON_SESSION=e04sess-<配置>`、两个名字带 `TOKEN` / `TICKET` 的 SDK env 标记，以及 `settings.env` 的 `E04_SET_BY_CONFIG`、`E04_SET_TOKEN`。还看到沙箱给的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`、`TMPDIR`。Claude 这组配置没有按变量名过滤实验中的 `TOKEN`。
3. **命令行替身：** 系统 Node 能运行，且能读取并运行工作区外的脚本。同版本 Electron 以 `ELECTRON_RUN_AS_NODE=1` 能运行，TCP 直连被沙箱拒绝。探针成功只读包装脚本和 `/Applications` 下 ChatGPT 内的 codex 文件各一个字节。打包版 Vonvon app 的签名、路径和实际 CLI 没测。
4. **git 提交：** 真实 git 可在沙箱里启动。今天和候选的读写档均在 cwd 的测试仓库成功提交；有 `additionalDirectories` 的候选读写档还在第二根成功提交。写被拒的仓库都停在重定向写文件，未走到 `git add` 或 `git commit`。
5. **附加目录：** 只读候选若只把 cwd 列进 `denyWrite`，Bash 仍能写第二根并在其中提交。把 cwd 和第二根都列进 `denyWrite` 的条件加测，两根都写不进。候选读写档有 `additionalDirectories` 时第二根可写、可提交。六轮的 `out` 目录都写不进。

## 对 s31、s37、s39、s46、s47 的含义

- s31、s46：今天的只读和读写关网档仍可通过沙箱代理访问本机 TCP，且本次外网探针返回 200。候选回调能拒绝代理请求，允许本机代理请求；Unix socket 的显式放行有效。TCP 直连在这组配置里仍被 Seatbelt 拒绝。产品是否承诺哪个传输路径，待 owner 定。
- s37、s46：SDK env 与 `settings.env` 标记均传进 Bash，包括名字带 `TOKEN` 的实验变量。若命令行不应得到某类环境变量，需在传给 SDK 前处理；策略待 owner 定。
- s39：只读只挡 cwd 不足以覆盖附加根；显式 `denyWrite` 两根后，两根都被挡。读写候选给 `additionalDirectories` 后两根都可写，不需要本次的 `allowWrite` 条件加测。
- s47：系统 Node 和同版本 Electron 能在沙箱内启动，工作区外脚本可运行，测试仓库里的 git commit 可完成。真实打包 CLI 仍须另验。

## 没测的

未触碰 owner 在用的 `/Applications/Vonvon Bot.app`，所以没有实测打包版 app 的签名、路径或真实 `vonvon` CLI。只读包装脚本和 ChatGPT 内 codex 的各一个字节。Electron 是临时目录内同版本替身。`cand-write-off-allow` 没加跑，因为 CW 的第二根已能写。`cand-write-off-2` 没加跑，因为回调的 `input.host` 能被候选 `hostOf` 识别。所有轮次模型都执行了原命令，无重跑、无超时。首次后台启动测试服务没有保持运行，改用持续前台会话；Electron 预检曾额外执行一次未设 node 模式的 `--version`，随后按要求在 node 模式核验。这两点只涉及实验准备。服务端之外的真实 daemon、bridge、飞书和 GUI 均未测。没有把六轮中外网 HTTP 状态推断为所有目的地址的网络策略。
