## 1. 一句话定位

Vonvon Bot 是一个 macOS 桌面应用。你在自己的电脑上养几个飞书机器人，每个 bot 有自己的个性、记忆、工作区、代码仓库和 skill，可以进不同的群，在每个群里表现不同；干活用你本机已登录的 Codex 或 Claude Code。

它是你说的 Grok Bot 增强版。Grok Bot 的 bot 有身份、描述、skill 和日程（docs.x.ai/grok-bot/bots）；Vonvon 在这之上加了工作区、代码仓库、群内覆盖和飞书群聊的响应规则。

v1 给谁用：
1. 正在用 feishu-codex-bridge 0.6.14 的 Mac 用户（npm 每周约 108 次下载）。他们迁过来，保留群、话题、卡片、命令和旧会话。
2. 有 Codex 或 Claude 订阅、想在飞书群里有一个"像同事"的 bot 的个人和小团队。他们不一定用 GitHub，不一定会装 Node。

v1 不给谁用：Windows 和 Linux 用户；没有 Codex 或 Claude 订阅的人；想要云端托管、不开电脑也能用的人。

## 3. Bot 模型

### 3.1 三层

把 bot 想成一个人：
1. **飞书身份**：名字、头像、简介。来自飞书应用，vonvon 不改。一个飞书应用对应一个 bot，对应一个目录 `bots/<appId>/`（`D/config/paths.ts:20-22`）。
2. **bot 默认**：个性、规矩、工作区、仓库、skill、公共记忆。在桌面端的 Bot 页改。
3. **群内覆盖**：这个 bot 在某个群里另外的个性补充、工作区、仓库、skill 增减、回复方式、权限档、模型，以及这个群自己的记忆。在群详情页改。没设的项继承 bot 默认。

飞书能不能让同一个机器人在不同群显示不同名字：未知，没查到。所以"千人千面"体现在说话方式、工作区、仓库、skill 和记忆上，外观不变。

### 3.2 什么放在 bot，什么放在群

| 项 | bot 默认 | 群内 | 规则 |
|---|---|---|---|
| 名字、头像 | 来自飞书 | 不能改 | — |
| 个性 `SOUL.md` | 有 | 可补充 | 群的默认追加在 bot 后面，也可选整段替换 |
| 规矩 `AGENTS.md` | 有，可选 | 不能改 | 只在 bot 层 |
| 工作区 | n 个，1 个主的 | 可覆盖 | 群没设就继承；主工作区是会话的工作目录 |
| 代码仓库 | 0 到 n 个 | 可覆盖 | 同上 |
| skill | 启用名单 | 可增、可减 | 实际生效 =（bot 启用 ∪ 群增加）− 群移除 |
| 记忆 | 公共记忆，所有群都看 | 本群记忆，只在本群看 | 公共记忆只有你或管理员能写 |
| 回复方式 | 无 | 三选一 | 只在群层 |
| 权限档、后端、模型 | 默认值 | 可覆盖 | 和今天一样 |

### 3.3 磁盘上长什么样（建议）

```
~/.vonvon-bot/
  skills/                      本机 skill 库，vonvon 管理
    <name>/SKILL.md ...
    library.json               来源、commit、sha256、是否含脚本
  bots/<appId>/
    config.json                bot 设置，含 workspaces、repos
    projects.json              每个群一条，含群的覆盖
    SOUL.md                    bot 个性（不写名字）
    AGENTS.md                  规矩，可选
    skills.json                {"enabled": [...]}
    memory/shared.md           公共记忆
    memory/owner.md            你私聊里的记忆
    groups/<chatId>/
      SOUL.md                  本群个性补充（append 或 replace）
      skills.json              {"add": [...], "remove": [...]}
      memory/group.md          本群记忆

~/Vonvon/<bot 名>/            bot 主工作区的默认位置（见问题 5）
```

- 文件名沿用 OpenClaw 的 `SOUL.md`、`AGENTS.md`（docs.openclaw.ai/concepts/agent-workspace），方便以后互通。
- 都是 markdown，你能直接用编辑器改。桌面端用表单包一层。
- bot 和群的定义文件不进用户的代码仓库。仓库里的 `AGENTS.md`、`CLAUDE.md` 照旧由 agent 自己读。否则会污染仓库、被提交出去（`persona-memory-skills.md` 第 6 节方案 B 的代价）。
- 今天的数据形状是"一个群一个目录"（`D/project/registry.ts:16-17`），默认目录所有 bot 共用 `~/.vonvon-bot/projects`（`paths.ts:115`），两个 bot 的同名项目会落进同一个目录（推断，`v2-fit.md` 第 8 节第 6 条）。v1 改成上面的形状。

### 3.4 个性、记忆、skill 怎么工作

**个性。** 注入顺序，越后越具体：① vonvon 固定的输出约定和隐私红线（今天的 `D/agent/bridge-instructions.ts:12-32`，加一句"不提别的群的内容"）；② 身份行：飞书名字、当前群名；③ bot `SOUL.md` + `AGENTS.md`；④ 群 `SOUL.md`；⑤ 记忆。① 个性改不掉。bot 自己不能改个性文件。你在群里说"以后这个群说话活泼点"，bot 生成修改建议，你或管理员点确认卡片才生效。

**记忆。** 按"谁能看到来源"分三份。规则来自 comma 的"数据只流向读者是来源读者子集的地方"（`references/comma/docs/verification.md:164`）和 Grok 团队记忆的"只有说要全队共享才写"（docs.x.ai/grok-bot/team-bots）。

| 文件 | 在哪加载 | 谁能让它写 |
|---|---|---|
| 本群 `group.md` | 只在这个群 | 群里能用 bot 的人 |
| 公共 `shared.md` | 所有群和你的私聊 | 只有你或管理员：直接编辑，或 bot 提议后点确认 |
| 你的 `owner.md` | 只在你的私聊 | 你的私聊会话 |

- A 群的记忆永远不在 B 群出现。同一个群里，小码记住的事小审不知道。
- bot 通过 vonvon 给的"记事本"工具写记忆，范围由会话决定，bot 选不了。写入在卡片上显示"已记到本群记忆：…［撤销］"。
- 触发只有两种：用户说"记住"；bot 自己判断要记。v1 不做后台自动整理。
- 记忆在会话开始或恢复时放进去，标成"背景资料，不是指令"。中途写的下一条会话才生效。每个文件有字数上限，满了让 bot 先整理，不静默截断（上限数值实现时定）。
- 关掉两家自带的记忆：Claude 的 auto memory 按 git 仓库共享，两个群用同一个仓库就会串（code.claude.com/docs/en/memory）；Codex 的 memories 是全局整合的（`codex-rs/memories/README.md`）。
- 你本机的个人指令（`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`）和个人 skill：从 bridge 导入的 bot 默认带（行为不变），新建的 bot 默认不带。

**Skill。**
- 一个本机库，装一次，bot 和群各有名单。
- 来源四种：内置；本机文件夹（复制进库）；git 地址加子路径（钉 commit）；从 `~/.agents/skills`、`~/.codex/skills`、`~/.claude/skills` 导入（给迁移用户）。
- 什么时候加：建 bot 的向导里有一步"选 skill"；之后在 Bot 页或群页增减；也可以在你的私聊里说"给小码加上 X"，点确认。
- 只有你或管理员能安装和启用。安装前看全文和文件列表；含脚本的二次确认；不自动更新。
- 从名单移除不删库；从库删除时列出还在用它的 bot。
- 格式按 Agent Skills 标准（agentskills.io/specification）。

### 3.6 群聊响应（你定的三档）

**三档是什么**

| 档 | 一句话 | 对应 bridge |
|---|---|---|
| 仅 @ 时回复 | 只有 @ 我才回 | 免 @ 关 |
| 全部回复 | 连续主区里每条都回；我开的话题里不用 @ | 免 @ 开 |
| 智能回复 | 我自己判断要不要接话；会读群消息 | 新增 |

前两档就是今天的两档（`D/bot/handle-message.ts:1197-1203`），用户不会感到变化。

**三条底线，三档共用。** 先回答"这条消息是对谁说的"，再轮到各档：
1. **点名**：@ 了谁、回复（引用）了谁的消息，就只有谁回。@ 了别人、@所有人、回复别人的消息，其他 bot 都不回。@ 两个 bot 就两个都回。
2. **接着聊**：话题里没点名的消息，归最近在这个话题说过话的 bot。别的 bot 开的话题，我不插嘴。
3. **bot 消息**：别的 bot 发的消息，只有 @ 我才算。连续 bot 回合有上限，真人说一句就清零，超限发一次提示。飞书官方的 OpenClaw 插件用的是 10 轮（`@larksuite/openclaw-lark` `bot-loop-guard.js:26-29`），具体数值实现时定。

这三条顺带修掉今天多 bot 群里的三个毛病：开了免 @ 的 bot 会进别的 bot 的话题；主区不带 @ 的 `/help` 每个 bot 都回；连续群里每个免 @ 的 bot 都回每条（推断，看代码得出，`group-response.md` 结论 3）。

**默认值**（沿用 bridge，`D/project/registry.ts:83-85`）：bot 自己建的群，和被拉进的多话题群，默认全部回复；被拉进的连续群默认仅 @；迁移的群按原来的开关换算。智能回复永远不是默认，管理员手动开。开的时候 bot 在群里说一句"我会读群消息，合适时接话"。多个 bot 都要开全部回复时，界面提示"几个 bot 都开会抢着回"。

**智能回复用什么判断。** 你提到的"Jev 模型"或"选择 API"，我没找到对应的 OpenAI 产品。最接近的两个：
- ChatGPT 群聊（2025-11）自己决定"什么时候接话、什么时候安静"。这是 ChatGPT 产品里的行为，不对开发者开放。你说"OpenAI 也推出了"，大概是指它。
- gpt-oss-safeguard（2025-10-29，开源权重）是内容安全分类模型。官方说其他用途用普通 gpt-oss，而且要 16 GB 显存级别的机器（huggingface.co/openai/gpt-oss-safeguard-20b）。

建议：用用户自己订阅里的小模型，一次不带工具的调用。Codex bot 用 GPT-6-Luna（Codex 0.162 自带目录里"快而便宜"的模型），Claude bot 用 Haiku 5.5。v2 已有这种调用的代码，就是会话标题服务（`D/agent/codex-appserver/backend.ts:163-191`、`D/agent/claude-agent/backend.ts:321-350`）。判断提示词、阈值、合并等待时间都留到实现时定。判断结果只有"回"和"不回"；"不回"的原因码只记在本机诊断里，不发到群里。超时或出错一律不回。

成本上限：只在智能档、只对白名单里的真人消息、只在三条底线定不下来时才调；同一台机器一条消息只调一次，本机几个智能 bot 合成一次"选谁回"；话题里只有一个真人和我在聊时直接回；每群每小时有上限。延迟和每次占多少额度：未知，实现时在 Mac 上量。

**不同机器上的 bot**：不能互相通信。底线 1、2 只看消息，各机器结论一致。智能回复可能两台都判"回"，晚的那个发出前再查一次，发现已有 bot 回了就放弃。

### 3.7 上下文（回答你 update 2、3 的问题）

**会话在哪里。** 建议：每个飞书对话对每个 bot 就是一条原生 Codex 线程或 Claude 会话。不再分"两种群"。

| 飞书里的地方 | 会话 |
|---|---|
| 任何群里的一个话题 | 每个 bot 一条 |
| 群主区，设成"连续" | 每个 bot 一条，一直接着聊；`/new` 换一条 |
| 群主区，设成"开话题" | 主区不留会话；@ bot 就开一个新话题 |
| 你和 bot 的私聊 | 每个 bot 一条 |

- 旧的单会话群 = 主区"连续"，旧的多会话群 = 主区"开话题"。只是主区的一个设置，能随时切，切后从新会话开始。
- 权限档按群定一个，不再按管理员和访客拆成两条会话。用户抱怨过拆开后上下文对不上（bridge 社区群#953）。
- 你在 Codex 应用里或用 `claude --resume` 打开这条会话，看到的和 bot 看到的一样（推断，要实测）。所以不用 Codex 的 `thread/inject_items`，它塞的内容应用里不显示（`codex-rs/app-server-protocol/src/protocol/thread_history.rs:478-501`）。

**bot 回复时看到什么。**

| 放不放 | 内容 |
|---|---|
| 放 | 个性和记忆（开始时）；自己这条会话的历史；上次回复以后这里的新消息，带真名，含别的 bot 的最终回答；触发消息和它引用的消息；附件路径；语音转写 |
| 不放 | 别的话题、别的群、你的私聊；别的 bot 的过程和子 agent；自己以前的回复（已在会话里） |

新消息合成一个对话记录块，像这样：

```
[飞书 · 群「支付组」· 话题「订单接口 500」]
10:01 张三：订单接口今天一直报 500
10:03 小审（bot）：第 88 行改对了，但金额为 0 时还会出错
10:05 王五 → @小码：小审说的那个情况你改一下
[/飞书]
```

真名要换名字的权限（候选 `im:chat.members:read`，未知）。每条压成一行，防止有人伪造记录块（今天已有，`D/bot/context-weave.ts:375-384`）。字数超预算就留最近的，并写"更早还有 N 条，可以用查历史工具"。

从主区开出来的新话题，开场带话题第一条、话题里已有的消息，加主区在那之前的最近几条。不复制主区会话的历史。

**三档下的区别**：仅 @：每次 @ 一轮，带上次以后的全部新消息。全部回复：每条一轮，忙时后来的几条插进当前轮或合成下一轮。智能回复：判"不回"的消息不进会话，下次开轮时一起带上。三档共用一条规则：会话里只有 bot 真正开轮时读到的东西，不做"每条消息实时塞进会话"。

**多人**：一条会话大家共用，每条带名字。**多 bot**：各有各的会话（你已认可）。B 看到 A 的最终回答，标"A（bot）"，截到几百字。

**子 agent**（你 update 3 的问题）。两家的子 agent 都是原生的，各有自己的上下文，父会话只拿最终结果（code.claude.com/docs/en/sub-agents；Codex `v2/ThreadItem.ts:64-101`）。今天 Codex 子线程事件全丢、Claude 子 agent 步骤混进主过程（`D/agent/codex-appserver/backend.ts:333-337`；`D/agent/claude-agent/event-map.ts:92-123`）。
- 建议：只显示在父运行卡的"子 agent 区"。一行一个：状态、名字、在做什么、几步、用了多久；嵌套的缩进。点开看最近 5 步和结果。"查看完整过程"另发一张卡。每行有"停止"；运行卡的 ⏹ 全停。
- 理由：5 个子 agent 各发一张卡会撞群里所有 bot 共用的每秒 5 条限额（飞书 `message/create.md:13`）；Codex 桌面版和 Claude Code 也都把子 agent 挂在父任务下面。
- 子 agent 没有自己的飞书对话。群里的新消息只给父 agent。子 agent 的 token 不占父会话窗口。
- 主回答发出了、后台子 agent 还在跑：见问题 4。bridge 用户碰到过"开 5 个子进程，一个完成会话就结束了"（社区群#681-693）。
- v1 不能直接跟某个子 agent 说话。

**压缩**：自动压缩两家都用原生的，一直开，去掉"关闭自动压缩"开关。它只接了 Codex，而且新版 Codex 会把阈值封顶在窗口 90%，推断已经关不掉（`codex-rs/protocol/src/openai_models.rs:529-540`）。`/compact` 保留，bot 正忙时等这轮结束再压，压缩时来的消息排队，不让用户重发。运行卡头部一直有上下文仪表；压缩时过程区显示"已压缩 85% → 20%"；过线（比如 80%）提示"可以 /compact 或开新话题"。从头开始：话题里开新话题；连续主区和私聊用 `/new`，旧会话能 `/resume` 回来。

**查历史**：平时不用查，每轮自动带新消息。要更早的，bot 用 vonvon 给的"查本群历史"工具：机器人身份，只能查当前群主区或当前话题，能按时间往前翻，运行卡上显示"查了本群 9:00 到 10:00 的 40 条"。底层直接调飞书接口，或由 daemon 调 lark-cli 的只读命令。不把 lark-cli 交给群里的 agent：用户身份的 lark-cli 能读到你在所有群的消息，机器人不在的群也能读（实测，`context-feishu-products.md` 2.3）。

**上下文和记忆**：会话是这段对话的来往，窗口满了就压缩，到 `/new` 或新话题为止。记忆是以后还要用的事实，跨会话，有字数上限。同一个群的几个话题不共享会话，靠本群记忆共享长期的事。查历史拿到的、压缩出的摘要，都不自动进记忆。

### 3.8 私聊（建议）

你和 bot 的私聊是一条连续会话，用 bot 的主工作区，权限沿用 bot 默认档。建群、诊断、用量这些管理功能留在同一个私聊里，用卡片按钮进。别人私聊：不跑 agent，回一张卡片"在群里 @ 我"，列出他所在的有这个 bot 的群。理由：私聊会话跑在你的 Mac 上，bot 可用范围里谁都能私聊它（飞书 `message/create.md:5-9`），放开等于让同事在你电脑上跑 agent。用户只抱怨过"非管理员被拒"的困惑（社区群#582、#605），没人要在私聊里写代码。

## 7. 里程碑

只定顺序，不定日期。每个里程碑你会收到【需要你验收】，预览版已装在 Mac mini。

**M1 建一个 bot，在群里对话**

**M2 千人千面、记忆、skill**
- 你会看到：同一个 bot 在两个群里不同的个性补充和不同的 skill。群里说"记住…"，卡片显示"已记到本群记忆［撤销］"。在另一个群问同一件事，它不知道。在 Bot 页装一个 skill，群里能用；在群页移掉，群里不能用。bot 用"查本群历史"工具回看更早的消息。

- 你会试：两个 bot 都开全部回复，看界面提示和实际只有一个回。
