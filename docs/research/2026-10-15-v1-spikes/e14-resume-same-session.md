# e14：在终端里打开 bot 的会话

`docs/v1-plan.md` 第 4 节的 e14，对应 product.md 第 9 节第 8 项和第 17 项的前半。2026-10-15 UTC 22:52 到 22:59 在 JP-VPS 上实测：验收 daemon 跑 `main` 的 `5a37103`，用验收 bot、`claude` CLI（owner 的 Claude 登录）和 `codex-cli 0.162.1`（owner 的 ChatGPT 登录）。群里的消息用 lark-cli 以 owner 的身份发。

## 结论先行

| # | 问题 | 结论 |
|---|---|---|
| 1 | 用 `claude --resume <会话 id>` 打开 bot 的主区会话，看到的和 bot 是否一样 | **一样**。记录块里的消息、带两边会话 id 的〔话题〕引用行、bot 上一次的回答，原样都在 |
| 2 | 用 `codex exec resume <线程 id>` 打开 bot 的话题会话 | **一样**：记住的数字、最后一条飞书输入都在 |
| 3 | Claude：两边都写 | bot 用过一条会话以后，进程留着不关，最后一轮之后空闲 45 分钟才回收（`packages/daemon/src/bot/handle-message.ts` 的 `SESSION_REAP_IDLE_MS`，每 5 分钟查一次，所以实际是 45 到 50 分钟；Codex 线程也按这个回收）。这期间终端写进去的轮次和终端里的 `/compact`，bot 都看不到；bot 下一轮接着自己内存里的历史写进同一个文件，两边分叉。bot 是从文件重新接上的那一轮（daemon 重启后、空闲回收后），才看得到终端写的 |
| 4 | Codex：两边都写 | bot 占着线程时，终端的 resume 被拒：`thread-store conflict: thread … already has an active writer`（`-32600`），不会分叉。bot 放开以后，两边都看得到对方写的 |
| 5 | 手动 `/compact` 以后，摘要里还留不留引用行 | 这一次**留下了**：两条〔话题〕引用行原样进了摘要，话题 id 和会话 id 都在。摘要是模型写的，只有一个样本 |
| 6 | 终端里的压缩，vonvon 知不知道 | 不知道：bot 下一轮的 `record-block` 是 `table: 0`，没附话题表。bot 还在用压缩前的内存历史，自己说"看不出这段会话被压缩过"，上下文读数也没降（压缩前约 44k，压缩后 bot 那一轮 50k） |

## 怎么测的

### Claude（验收用的 Claude 群，整群连续会话，只读档）

1. 22:52：在 bot 的工作目录里，对主区会话跑 `claude -p --resume <会话 id> "…"`，让它不调用工具，只按历史回答三件事：最后两条飞书输入、有没有〔话题〕引用行、上一次回答的第一句。三件都答对了，引用行原样抄出：`22:27 〔话题〕<owner>在上面这条下开了话题「…」，你在那边另有一条会话，这里不用接。（话题 id：omt_…，会话 id：…）`。这时 daemon 刚重启过，这条会话从 22:31 起就没动过。
2. 22:53：在群里 @ bot，问"终端里刚才问了你什么"。bot 照原文答出那三问。日志里这一轮有 `resume-ok`：bot 是从文件接上的。
3. 22:54：在终端里跑 `claude -p --resume <会话 id> "/compact"`。会话文件多了一条 `compact_boundary` 和一条摘要。摘要里原样留着两条〔话题〕引用行，话题 id 和会话 id 都在。
4. 22:55：在群里 @ bot，问"会话压缩过吗、群里最近有哪些话题"。bot 答"看不出这段会话被压缩过（没有摘要，前面几轮都是原文）"，两个话题都说得出来。日志里这一轮没有 `resume-ok`，用的是 22:53 起的那个进程。卡上的上下文读数是 13%、50k。

### Codex（验收用的 Codex 群，按话题独立会话，完全访问）

1. 22:57 前：在 bot 的工作目录里，对一个 17:38 的话题会话跑 `codex exec --skip-git-repo-check resume <线程 id> "…"`。它答出了让它记住的数字 7 和最后一条飞书输入。
2. 22:57：在那个话题里 @ bot，问"终端里刚才问了你什么"。bot 照原文答出。日志有 `resume-ok`。
3. 22:58：bot 还占着线程时，在终端里再跑一次 `codex exec resume`，要它记住 42。被拒，报 `already has an active writer`。
4. 22:58：在话题里 @ bot，问"终端里让你记住的新数字是几"。bot 答"不知道"。

## 没测的

- Codex 应用（桌面端）里打开 bot 的线程。推测和终端一样，bot 占着时打不开，没验证。
- 空闲回收以后，Claude 从文件接上的是哪一支。推测是最新写的那一支：bot 后写的话就是 bot 的，终端里那次压缩就丢了。
- 两边同时开着一个回合。
