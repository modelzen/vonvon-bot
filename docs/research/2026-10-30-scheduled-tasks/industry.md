# 定时任务调研：业界做法（定时和事件触发）

2026-10-30 网上调研，两个方向各一个调研代理，再由另一个代理逐条打开来源核对。下面先是核对后的结论，再是逐条来源和核对结果。原文英文。

## 定时任务：创建、会话、错过、管理、权限、自己排

Sources checked 2026-10-30. All 85 claims match their sources. The corrections below fix product names and the researcher's summary wording.

1) Creation. Most products do both: the model creates tasks from chat through a tool, and a list or settings page also exists. This covers ChatGPT (web and the ChatGPT desktop app, where ChatGPT Work and Codex run; there is no separate 'Codex app'), Gemini 'Schedules', Claude Cowork, Claude Desktop, Claude `/schedule`, Slackbot, Cursor (`/automate`, Agents Window, cursor.com/automations, Marketplace templates), OpenClaw's automations tool and Manus. Microsoft Copilot schedules an existing prompt through a UI action ('Schedule this prompt').

Feishu aily has a 定时触发 trigger in its task builder: minimum 5 minutes, default timezone 东八区, optional end time. A Feishu article also lists '帮我创建一个每周五晚上 6 点的循环任务' as a common chat-mode input, so aily takes schedule requests in chat too.

How each product confirms before saving:
- Gemini replies with a summary of the schedule.
- Cowork shows the proposed name, schedule and instructions; you click Schedule.
- Slackbot shows a draft task before Create task.
- Claude `/schedule` confirms the absolute timestamp for one-offs.
- `/loop` confirms the cadence and job ID.
- OpenClaw restates the schedule in plain words. After you confirm, it creates the job enabled, runs it once as a visible test, and removes it if the test fails.

2) Sessions. There are two patterns.
- Fresh session per run: Claude Desktop local tasks, Claude cloud tasks, Cowork, ChatGPT standalone tasks, and OpenClaw isolated jobs (new transcript per run). Exception: inside a Claude project, a cloud run can continue a thread.
- Same thread: ChatGPT in-chat tasks, Gemini's per-schedule chat (changes asked there are saved for future runs), OpenClaw main and custom sessions, and Manus's 'continues in the same task' run option.

Fresh runs get context from three places:
- the saved prompt plus workspace files;
- per-job memory (Cursor memories, MEMORIES.md by default, on by default; OpenClaw scratch, capped at 256 KiB);
- a bounded tail of the creating chat (OpenClaw 'current').

3) Missed runs.
- Claude Desktop: runs only while the app is open and the machine awake. On start or wake it runs exactly one catch-up for the most recent slot missed in the last 7 days, discards older ones, and notifies.
- `/loop`: a fire that comes due while Claude is busy runs once when Claude is idle. Runs missed while the session wasn't running are never replayed.
- OpenClaw: catches up by default (cron.skipMissedJobs=false). At startup it reschedules overdue agent jobs instead of replaying them at once, and a waking Gateway coalesces missed ticks.
- launchd: StartCalendarInterval runs missed during sleep coalesce into one run on wake, but are skipped if the machine was off. StartInterval misses fires during sleep or while the job is still running.
- cron skips. anacron catches up per day. systemd Persistent= (OnCalendar only) triggers once after downtime.
- Claude cloud documents only two cases: with GitHub disconnected it skips runs for up to 72 h, then turns off; runs over 100/h wait.
- The ChatGPT, Gemini, Cowork and Copilot docs say nothing about missed runs. Gemini prepares output within the hour before delivery time.

4) Management and limits. Most products have pause, edit and delete, but not all:
- `/loop` only lists and cancels (CronList, CronDelete).
- In Claude Desktop, Claude can list, create, edit and pause tasks, but only the Delete button deletes.

Failure handling:
- OpenClaw sends an alert after 2 consecutive failures, with a 1-hour cooldown. This default applies only to jobs that have a failure route. For chat-created jobs, the first alert becomes a repair request in the creating conversation. A recurring job auto-disables after 10 consecutive failures. Errors back off 30s, 60s, 5m, 15m, 60m.
- Claude cloud marks runs Error or Cancelled, which reflects how the session ended, not whether the task got done.
- Claude Desktop history shows skipped runs with the reason.

Caps:
- ChatGPT, per IT Brief (a secondary source; help.openai.com still returns 403): Go 3, Plus 5, Business/Edu 10, Pro/Enterprise 15 active tasks, at most once per hour. OpenAI's current docs allow minute-based intervals for in-chat tasks, so the hourly limit is unresolved.
- Gemini: 10 active schedules.
- Copilot: 10 scheduled prompts.
- Slackbot: 3 runs per day per task, reset at 00:00.
- Claude cloud: 1-hour minimum interval; 100 scheduled runs per hour per account; 30 Run-now/API fires per hour per task.
- `/loop`: 50 tasks per session, 7-day expiry, 1-minute minimum.
- aily: 5-minute minimum.

5) Permissions.
- ChatGPT desktop app: tasks run with the default sandbox and approval_policy="never" when org policy allows; otherwise they fall back to the selected permission mode.
- Claude cloud: starts in auto mode (classifier), but still waits on ask rules and repeated blocks. The fired prompt cannot count as approval or consent, and API fire text arrives wrapped as untrusted data.
- Claude Desktop: each task has its own permission mode. In Manual mode a run stalls until someone approves it in the run's session. 'Always allow' choices carry over to later runs.
- Cursor: PR creation and computer use are on by default. Runs act as the user or a team service account.
- Slackbot sees only what the user can view.
- OpenClaw:
  - Runs use the owner session's current tool policy. An agent-created job is capped to the tools its creating turn had.
  - A scheduled run can inspect and remove only its own job.
  - Managing any automation from chat, whoever created it, needs an ownerAllowFrom sender or a Control UI operator.admin turn, with one-use 60-second grants. Ordinary caller ownership checks still apply.
  - Standing orders define what the agent may do; automations define when.

6) Self-scheduling: Claude ScheduleWakeup (1 min to 1 h, stop:true, about 20-minute fallback), Claude CronCreate, Desktop update_scheduled_task, OpenClaw next_check (clamped to pacing bounds) plus its owner-only /loop, and ChatGPT in-chat minute-based loops.

Waiting inside a session is a different mechanism. Claude's Monitor has a deadline of 5 min by default, 30 min at most, and 10 min in -p runs. Background Bash is limited only in unattended sessions (30 min by default, up to 2 h); interactive local sessions have no limit.

Not verified: help.openai.com returned 403. Manus docs returned 404, so Manus facts come from its blog only. No Codex CLI or app-server scheduling API was found; the CLI and IDE extension have no Scheduled UI. Slack doesn't document where task results go.

## 事件触发：谁有、怎么做、本机没公网时的办法、飞书

Do mainstream assistants mostly offer only time-based schedules? Their local or desktop versions do. Event triggers now exist, but almost only where the vendor runs the receiver in its cloud.

- Gemini Scheduled Actions are time-based only: daily, weekly or monthly, up to 10 active, content prepared within the hour before delivery.
- Claude Cowork tasks run hourly, daily, on weekdays, weekly, or manually. They run remotely even while the computer sleeps, except tasks that need local files or apps, which run only locally. No event triggers.
- ChatGPT scheduled tasks can start on Gmail, Slack or GitHub events on eligible plans, but only on web and mobile, not in the ChatGPT desktop app, Codex CLI or IDE extension. A task can't mix event triggers with a time schedule. Close-together events may be merged into one run.
- Claude Code cloud scheduled tasks (formerly routines) are in research preview. Besides schedules, they take API (/fire with a bearer token) and GitHub (pull request, release, issue) triggers. The Claude GitHub App is required. GitHub events have per-task and per-account hourly caps, and events over the cap are dropped.
- Cursor Automations, Devin, Manus and Copilot automations all run in the vendor's cloud. Cursor, Devin and Manus have broad event triggers (source control, Slack, webhooks, Linear, PagerDuty and more). Copilot's are limited to schedules and repository events, in eligible private and internal repositories.
- The local versions are schedule-only and need the machine on. Claude Desktop local tasks fire only while the app is open and the computer is awake. ChatGPT project-scoped tasks need the machine on and the desktop app running.
- Claude Desktop skips runs while the computer sleeps. On wake it starts exactly one catch-up run for the most recent miss in the last 7 days. The ChatGPT page says nothing about missed runs.
- OpenClaw is the local exception, with a cost. Its webhooks (/hooks/wake, /hooks/agent, mapped hooks) are off by default and need a dedicated hook token. The sender must be able to reach them, and the docs advise keeping them behind loopback, a tailnet or a trusted reverse proxy. Its Gmail Pub/Sub trigger needs an HTTPS push endpoint reachable by Pub/Sub (Tailscale Funnel by default). Its IMAP plugin needs neither Pub/Sub nor a public webhook.

Workflow platforms split triggers into instant (webhook push) and polling.

- Zapier polls every 15 min on Free, 2 min on Professional and 1 min on Team and Enterprise. It deduplicates by item ID. Triggers and polls never use tasks; only successful actions do.
- Make counts a trigger as 1 operation per check, however many bundles it returns. The official page doesn't say outright that empty 'check runs' are billed, though Make staff in the community say they use one operation.
- n8n bills per workflow execution, and each scheduled run counts.
- Copilot Studio counts every trigger payload as a billed message.
- Devin can skip events with a script or LLM preflight before the agent starts.

The common pattern: run a cheap deterministic check, and call the model only when something changed.

Heartbeat:

- In the 2026-08-25 doc (commit 6a1dedb), OpenClaw ran a heartbeat turn every 30 minutes (1 hour with Anthropic OAuth/token auth) and delivered to the owner's DM, never a group.
- NO_REPLY was already the main quiet reply. A legacy HEARTBEAT_OK at the start or end was dropped when the rest was 300 characters or less. An effectively empty checklist was skipped (reason=empty-heartbeat-file).
- The doc said isolatedSession cuts a run from about 100K to 2 to 5K tokens.
- A third-party guide (InsiderLLM) estimates 2 to 3M tokens and $1 to $3 a day on Sonnet ($5 on Opus) while idle.
- Correction on the timeline: HEARTBEAT.md was already gone from the runtime by July 2026 (#113131). By the August doc it had been imported into the heartbeat monitor job's database scratch. On 2026-10-21 (#179387), OpenClaw moved heartbeats into ordinary automation jobs. Setup now provisions one 'Proactive check' job every 30 minutes, and quiet checks reply NO_REPLY. On 2026-10-24, #182375 removed an extra ~512 KB uncached finalization request that quiet heartbeats had been making after a tool call.

Feishu:

- Long-connection mode needs only internet access, with no public IP, domain or tunnel. It is limited to enterprise self-built apps. Events must be handled within 3 seconds or they are re-pushed. Each event goes to one random client out of at most 50.
- Without an @, im:message.group_msg delivers only messages from users. im:message.group_msg.include_bot:read also delivers other bots' messages, never the bot's own.
- vonvon requires im:message.group_msg, requests the @ variant im:message.group_at_msg.include_bot:readonly as optional, and deliberately does not request group_msg.include_bot:read.
- A community report (nanobot #5929) confirms that another app bot's @-mention is delivered with sender_type=bot.
- Feishu's docs never say whether 自定义机器人 (custom webhook bot) messages reach other apps' im.message.receive_v1. Custom bots can only send into their own group, can't receive @ messages, and are limited to 100 per minute and 5 per second. This needs a live test before a group can serve as an event bus.
- Correction on a Feishu GitHub app: the Lark App Directory lists a 'GitHub Assistant' that a third-party project calls official and says is closed to new Feishu users. Its publisher isn't verified. Zapier and open-source bots are the usual routes.

Options with no public IP:

- GitHub conditional polling. An authorized 304 reply doesn't count against the primary rate limit. For the Notifications API, X-Poll-Interval sets the allowed poll interval, and only classic tokens work. Events API delay is 30 seconds to 6 hours, with at most 300 events from the past 30 days.
- The smee.io relay, which forwards over Server-Sent Events. GitHub's docs use it for local testing.
- Free ngrok: 1 auto-assigned dev domain that can't be customized, 3 endpoints, 20k requests and 1 GB a month.
- Tailscale Funnel: beta, needs MagicDNS, HTTPS certificates and a policy-file node attribute, and listens only on ports 443, 8443 and 10000.
