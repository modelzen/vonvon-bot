# 飞书建群去重合同

2026-10-18 核对，初始源码参照 `main` 的 `fae1c32`。用于 s36c2c4 的建群操作恢复设计，不代表已经完成真实飞书验收。

## 已核实的边界

[飞书官方创建群文档](https://open.feishu.cn/document/server-docs/group/chat/create)提供[同页 Markdown](https://open.feishu.cn/document/server-docs/group/chat/create.md)。查询参数表说明：

- 开发者可传入 `uuid` 去重，长度上限 50 字符。不传时，每个成功请求都会新建群。
- 去重键包括 `uuid`，指定 `owner_id` 时还包括它，保证窗口为 10 小时。
- 不指定 `owner_id` 时，创建群的机器人担任群主；邀请进群的操作者不是这个字段。
- 错误码 `232068` 表示群正在创建，不能据此认定远端没有产生群。

本机 `lark-cli schema im.chats.create` 的只读参数说明与去重窗口一致。没有调用建群 API。

## 不能据此推导的保证

该文档没有承诺重复请求一定返回原 `chat_id`，没有给出按 `uuid` 查询结果的恢复接口，也没有说明不同请求体复用同一去重键的处理合同。这里不把这些缺失说明当成可用能力，也不把 10 小时去重扩展为无限期恰好执行一次。

设计选择是：先持久保存操作身份与输入，再标记可能已经派发，成功响应的群号先于本地项目保存。已知群只继续本地提交；未知结果保留证据并要求明确恢复，不因超时、重启或窗口过期而再发建群请求。未知群不能按显示名称自动关联。这是本项目的保守策略，不是飞书新增的保证。

## SDK 检查

当前锁定 SDK 为 `@larksuiteoapi/node-sdk` 1.71.1。读取安装源码可见，生成的 `im.v1.chat.create` 调用一次 HTTP request 后直接返回或抛错；默认 Axios 实例没有显式超时。使用真实 SDK、关闭 token 获取、替换 HTTP 边界的本地探针实际记录到一次失败 POST，没有联网，`owner_id` 保持缺省。

通用的认证 `Client.request` 会转发 HTTP 选项，后续接线必须验证显式请求超时，保持操作锁的生命周期与实际请求一致；本报告没有把这个尚未接线的路径算作验收通过。升级 SDK 时重新核对。

原始官方文档、CLI schema、SDK 探针与结果保留在本轮私有开发证据中，公开记录不包含实际账号、群号或凭据。
