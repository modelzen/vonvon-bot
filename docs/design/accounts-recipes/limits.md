# 首版限额、留存与失败行为

**以下是首发产品预算。** 公测前用作者同意导出的脱敏配方检查哪些上限挡住了正常用法。服务端发布带版本的策略，客户端读取同一策略。调低限额后仍可读取、领取、安装及删减草稿。单份或草稿总量超额时，允许继续减量，回到额度内即可提交合规版本。历史版本数量或累计字节已经达到上限时，删减草稿无法释放历史额度，界面应指明具体维度及申请调额的方法。已发布版本和已安装群继续保留。

| 限制对象 | 初始上限 | 到达边界时 |
| --- | --- | --- |
| 一个不可变发布版本 | **1 MiB**，含公开元数据、私有配置、允许携带的技能文字/参考文本、清单和最终 Logo，不含后端生成的签名或存储索引 | 草稿详情和发布确认显示「占用／上限」及最大的三项；等于上限可发，超过 1 字节不可发。减去未必需的技能参考或记忆即可重试。 |
| Logo | 上传最多 **2 MiB**；PNG/JPEG/WebP 静态图，单边 ≤2048，解码 ≤4,194,304 像素。中心裁成 192×192，清元数据重编码；成品最多 **128 KiB**，计入总量 | 原文件和 base64 的传输长度不是配方体积；不能解码或成品超限保留旧图，可移除/不上传。禁止 URL 代传、SVG、动画、伪装和任意文件。 |
| 可读字段 | 发布必填；私人草稿可暂缺必填项但不能超长。名称 1–60 个 Unicode 码点，简介 1–240，版本标签 1–40，公开 Markdown ≤32 KiB，setup ≤32 KiB，单条群规则正文 ≤16 KiB | 超限标在对应字段。版本标签与服务器排序 revision 分离。Markdown 不执行 HTML/脚本，不自动载入远程图片/嵌入；公开链接只允许安全协议。 |
| 快照组成 | 最多 16 项技能、64 个安全 UTF-8 文本文件；每文件 ≤128 KiB。最多 32 项规则、32 项定时任务、64 条已选择记忆；每条记忆 ≤4 KiB。单份累计仍 ≤1 MiB | 多一项需手动取消选择；禁止二进制、压缩档、软链、硬链接越界和任意项目目录。仅 schema 白名单的文档与声明可移植；setup 不能随安装自动执行。 |
| 草稿与并发准备 | 每账号 20 份未发布草稿，总计 **10 MiB**，每份按相同版本上限。每账号至多 3 个进行中的准备请求，相同来源和目的复用原请求。每份草稿至多一个活跃写提案，其余须明确排队 | 过额时保留本地已选内容，允许减量或清理。草稿不静默过期。已选定草稿后，单条飞书编辑指令最多 2,000 个 Unicode 码点；超长保留原草稿，请作者在 App 一次编辑或分成独立确认的修改。不截断或自动拆分执行。普通私聊沿用现有处理。 |
| 作者作品与历史版本 | 每账号至多 20 个配方身份（普通撤下仍占一个），每配方至多 30 个已发布版本，账号全部历史版本**逻辑合计 25 MiB**。每个版本按独立包字节数计量，同一 Logo 跨版可物理去重 | 发布新版也占额。不得为腾空间静默删除旧版、领取权益或群内安装。读取或领取不会重复计入作者额度。 |
| 分享码 | 每次 1–100 枚，每版最多 500 枚同时可用。每账号每天最多签发 500 枚，**累计最多签发 5,000 枚**，包括发布时生成的首码及后续批次。按不同状态展示可用、已兑换和已停用的码 | 达到单版可用上限可减少批量或停用闲置码。达到日额显示下次可发时间。达到累计上限须申请调额，停用或兑换均不返还日额和累计额。码管理记录与已取得的版本授权各自保留。 |
| 频率与上传暂存 | 每账号每天最多发布 10 个新版本。日额统一按服务器 UTC 自然日计，界面按用户时区显示重置时间。建议起始试码上限为每账号每 10 分钟失败 10 次，结合 IP、版本限流。每账号最多 2 个并行上传，临时接收容量合计 **4 MiB** | 频率限制返回 429 与可重试时间。同一请求的回执重放不计入新操作。已过期上传票据不可提交成品，同一 NAT 的正常用户也不应因一个账号失败而全部被锁。 |
| 列表与后台流量 | 默认首页首屏单独返回 1 张精选或最新横幅，并返回最多 8 张其他配方卡。后续每次手动加载最多 8 张，按最近发布排序并去重。搜索独立查询全部公开配方，每次最多 8 张匹配卡，无横幅。公开详情按需加载，私有快照不走公共缓存 | 0 份显示空态，1 份只显示横幅。打开群或手动刷新时，在退避窗口检查更新；离线显示上次检查时间。 |

### 计算一次，三处一致

1. 导出生成逻辑包。令 `B = UTF8(canonical_manifest).length + Σ(raw_verified_part_bytes)`。manifest 含公开字段、schema、来源标记、每个条目的唯一标识/hash/size、最终 Logo 引用。嵌入 manifest 的文本只计入 manifest 一次，已拆成 part 的正文只按字节计入一次；同一版本内共享内容由同一 part 引用。采用稳定 JSON 规范化（明确键顺序、无无关空白、UTF-8、不要对作者内容做不透明的 Unicode 归并），用 golden 文件跨平台对比。MiB=1,048,576 字节，KiB=1024 字节，比较原始整数，不能四舍五入后放行。
2. 目标 daemon 预检，App 呈现估算；API 从实际已验证的字节再次计算并返回权威明细。草稿和上传票据有独立上限，不能只在最终发布拦。入口请求体按端点设置合理上限并限制解码后的总大小/CPU/时间；分片或多个并行请求不能规避逻辑包限制。原型未实现服务端限额。
3. 完整的规范化 manifest、快照正文和成品 Logo 存在受控对象存储。数据库仅存有尺寸上限的公开字段、对象引用、摘要、尺寸、访问控制与事务记录。已发布且可展示的 Logo 经公开资源路由交付，正文依版本逐次判权。草稿转历史时引用已验证对象，可跨版本物理去重。清理暂存与孤儿前必须检查所有草稿和历史版本引用。

### 额度如何随事务变更

| 写入操作 | 原子检查、结算与重试 |
| --- | --- |
| 注册准备请求、申请上传票据 | 数据库按固定顺序锁账号额度和操作记录，先查询同一幂等键，再为新请求占一个活跃名额。建立上传前预留一个上传名额及申报的最大字节数。服务按实际入站字节强制截流，超额立即终止流；不可凭一次票据任意覆写或扩容。准备完成、取消或过期只释放一次活跃名额。上传结束或过期后关闭写入并回收暂存，只有暂存已删除，且产物已由草稿占用或其他同额预留覆盖，才释放对应字节。无引用的 verified 孤儿也须保留预留直至清理；回收失败保留计量并重试。过期处理不得复活原操作。 |
| 创建、修改、删除草稿 | App 保存、飞书确认及准备请求转草稿都锁同一作者额度行，校验 owner、状态与预期 revision。创建同时扣 1 份和实际字节；修改按服务端复算的「新总量 − 旧总量」结算，可用余额含其他操作的预留；删除仅释放尚未发布的草稿一次。只在同一事务写入草稿、交接完成或新 revision、额度变更和幂等回执。若预留正向增量，提交时转为占用并退还差额，取消或过期释放；任一步失败不改旧稿。政策降低造成超额时只放行独立维度不增加占用的减量操作。 |
| 发布 | 锁作者额度、配方和草稿，校验所有预期 revision、作品与历史版本数、历史字节、发布日额。一个事务将草稿占用转为不可变版本占用，挂已验证的引用，更新当前版本及发布回执。凭码版本的首码同时占用版本可用数、作者签发日额及累计额。任一维度不足都回滚，草稿仍可编辑。 |
| 批量发码、兑换与停用 | 批次锁作者额度和版本可用数，一次检查、插码并累加本批数量，全部成功才计数。兑换或停用在同一事务内使一枚可用码转态并只减该版可用数，已获授权的幂等重放不消耗第二枚码。账号签发日额与累计额只随成功签发增加；撤下、停用、兑换、重放或删除展示记录均不能重置累计额。已兑授权另表保存。 |

所有写操作都先鉴权，同键同参可取原回执，同键异参报冲突。设固定的锁顺序，避免发布首码与批量签发相互等待。容量不足返回可识别的 `quota_exceeded` 和维度；日额或请求频率限制给出 429、可重试时间。请求体太大返回 413，字段或快照无效返回 422，版本或修订冲突返回 409。错误明细含 `field/item_id,actual,max,unit,retryable`，不回显秘密文本。仅在收到云回执后显示成功。调额记录策略版本与审计。

### 逻辑额度与项目成本

按账号计量的 25 MiB 只覆盖已发布逻辑包。实物预算单独监测数据库表、索引、审计和回执的字节，以及对象存储、备份和出站。即使逻辑包很小，分享码及索引仍会占用数据库空间，累计签发上限用于控制这部分增长。达到项目写入预算时，先限制新大对象和批量操作，保留读取、取消及幂等回执查询；按实际用量评估调额或升级。
