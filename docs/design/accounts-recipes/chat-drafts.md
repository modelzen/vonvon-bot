# 在飞书私聊中创建和修改配方草稿

2026-11-15：本章的 App 发布必经步骤、可选记忆与“保存后返回 App”属于早期设计，已由[私聊发布](chat-publication.md)和[记忆排除](memory-exclusion.md)覆盖。下文保留初始设计与测试上下文，不作为这三项的当前需求。当前主流程在本人私聊中完成，未发布工作自动保存。

作者可以对 Bot 说「把产品群的周报做成配方」，也可以打开 App 里的草稿，点「在飞书继续编辑」。两条路最终打开同一份私人草稿。聊天产生的改动只存入所选草稿。作者仍在 App 查看全部配置、检查公开介绍并确认发布。

本章是拟实现的交互和技术契约。现有交互稿已模拟 App 与私聊两个创建入口、输入文字提议、确认或取消、返回同一草稿和两端修订冲突。另用真实模型做过七条独立合成输入和一条四轮连续创建/改稿的小测，详见[验证记录](validation.md)。前端演示的解析与模型小测分开运行：还没有接通真实飞书、云草稿服务或平台账号。

## 一次实际操作

1. 从 App 发起时，创作中心里选现有 Bot 和该 Bot 已加入且绑定的群，群内入口预选当前组合。从现有草稿点「在飞书继续编辑」，直接带上该 draftId。确认后，App 保留「等待飞书操作」和重开这次会话的入口，目标 Bot 主动给经验证的本人发卡。发送与取消沿用[准备请求的状态机](runtime.md)。
2. 从飞书发起时，作者直接给已关联的 Bot 发「帮我用产品群做一份配方」，或从 `/menu → 配方草稿 → 创建草稿` 进入。Bot 已由当前私聊确定。群名唯一匹配时，回一张简短的来源确认卡；不唯一时列出**当前账号、当前 Bot、已授权来源设备**中的可用绑定，让作者选定。群名或 Bot 名称不宜发到飞书时，卡片只给安全别名或「来源 1」，由 App 选定。无可用群时给 App 的连接已有群入口。点击确认才创建准备请求；继续更新这张私聊卡，不另发一条相同的欢迎消息。
3. 若尚未关联身份，私聊只能返回通用的「到 Vonvon 关联账号」入口，不列群和草稿。登录的 App 与当前 Bot 的管理员完成一次双向挑战，再继续刚才的动作。不同账号、App 注册实例、租户或私聊不能互借绑定。一个飞书身份有多个可能的账号或源设备时，在 App 选定并重新签发上下文；不按名称、邮箱或最近活跃账号推断。
4. Bot 给出可选择的角色、技能、规则、任务与记忆编号。默认不带记忆。作者可直接勾选，也可说「只带周报任务和整理行动项的技能」，由 Bot 展示拟选择的安全条目并让本人确认。需要看原文、辨别同名条目或检查隐私时，用「在 App 核对」打开源设备的授权视图。在已选好条目的卡片按「生成私人草稿」，一次提交即可；若作者用文字提出生成或更改，先展示将包含或改动什么，由本人确认。云端接收成功后，当前卡片变为「草稿已保存 · 继续修改／在 App 查看」，App 同时出现同一个 draftId。派发私聊成功不等于草稿已生成。
5. 作者接着说「把周报任务从周五五点改到四点半」。Bot 在当前草稿卡片显示合法的前后差异，如「每周五 17:00 → 16:30」，标出时区、目标草稿，以及「保存到草稿／调整／取消」。保存后两端同见新修订，可以继续说下一项。草稿中的任务模板一直不运行。若最终点击「结束编辑」，只是结束这次聊天绑定，草稿仍可从 App 或私聊重新打开。

## 让 Bot 知道“改哪一份”

新增本地的**编辑上下文**，键至少绑定 `accountId、deviceInstanceId、botRegistrationId、platform/tenant、recipientOpenId、真实 p2pChatId、contextId`。每个上下文只引用一个 draftId，尚在创建时先引用 operationId。保存已确认的目标、前台卡片 messageId、最近读取的 draftRevision、有限有效期与关闭状态。短时动作引用与草稿 ID 分开；转发卡片、猜到 draftId、恢复旧 Agent 会话都不会取得读写权。

- 用户明确回复某张草稿卡片时，按可信的回复关系或卡片动作引用解析。先验绑定、原卡消息、接收人、草稿所有者和可编辑状态；已结束、已过期或已发布的卡片不能继续写。
- 同一私聊只有一个明确激活的草稿时，可在有效期内直接连续交谈，候选卡每次标明目标。多份草稿同时打开、上下文已过期或“这个”无法确认时，提供「选一份草稿」或「在 App 选择」，不把文本写向最近一份。已有明确候选的重复点击仍绑定原草稿，不能因为刚切换了工作草稿而错写。
- 作者可以说「继续编辑一份草稿」，或点 `/menu → 配方草稿 → 打开草稿`。未明确授权展示的私人标题不发进飞书。App 在本人草稿箱中选择任意仍可编辑的草稿（包括在其他会话或设备创建的），签发仅限此草稿、此 Bot 和收件人的短时编辑票据。源草稿已经在云而原设备离线时，可改快照内可编辑的文案和模板；重新采集另一台设备的技能或记忆必须由原设备重新授权并上线。换了 Bot 的会话不能凭新 Bot 的本地权限读取旧 Bot 的来源内容。
- 确定性路径支持卡片按钮和一个明确的配方入口（建议文本命令 `/recipe` 打开同一菜单）。没有模型、模型响应超时或结构化输出校验失败，仍能创建、选稿、用表单改允许的字段和返回 App。自然语言未明确涉及草稿或当前草稿上下文时按原有私聊处理；涉及「改草稿还是实际群设置」的歧义只询问，不让本条消息落进可执行的群管理工具。撤回尚未保存的提议可丢弃，已保存后的回退须产生一项新改动。

## 草稿允许修改的内容

所有改动都落为类型化的 `DraftPatchV1`，由同一校验器处理飞书候选和 App 保存。典型请求包含 `draftId、baseRevision、requestId、schemaVersion、changes[]`。每个 change 是明确白名单操作，以稳定的条目 ID 引用，禁用任意 JSON 路径、覆盖整个配置或覆盖他人草稿。操作者、设备、来源标签、状态和权限由服务端会话或受信源设备确定，不能由模型或卡片提供。版本不支持或出现未知操作时，整批不写。

| 作者想做的事 | 草稿内的行为 | 何时回 App |
| --- | --- | --- |
| 改名称、简介、Markdown 概览 | `setPublicText(field,value)`；只取作者为本次修改提供的文字。允许先存不完整草稿。显示这些字段发布后可公开，确认前做长度和敏感文本检查。 | 内容较长、含敏感信息或需要排版预览时，在 App 查看原文与完整差异。 |
| 改角色、群规则、沟通方式 | `setDraftRole`、`upsertRule/removeRule`、`setConversationMode`；只能改本草稿的允许字段。守住现有运行模式组合约束，不改实际群规则。 | 规则原文涉及私有上下文时，仅显示“有 1 项待核对”，在 App 核对并保存。 |

每个可导出条目沿用[运行设计的来源规则](runtime.md)。改名字、调时间、改写摘要、复制条目不会洗掉 `origin/version/entryId/hash/policy`。外部受限来源的技能、规则、任务、记忆及 setup 均不可勾选、不可导出。原作者更新自己的版本，以及从可验证的独立自有内容另行创建，两种权限分别检查。来源不明或混合无法拆分时退回 App，不上传候选。由模型生成的新内容也不能给模型刚看过的受限条目重新标注原创。

## 模型只写候选，保存只发生一次

**解释输入。** 仅在配方编辑上下文对单条指令设 2,000 个 Unicode 码点的上限，不改变原有私聊消息限制。超长可拆成独立修改或回 App 编辑；每次及最终保存仍核对字段和整份快照额度。预览页的短输入框、会话及提案计时只用于演示，不是生产限制。 简单的文本命令、选项和卡片表单直接生成确定性候选。自然语言只交给专用的草稿解析器；输入只含本次明确针对草稿的指令、必要的安全字段或条目别名及允许操作的 schema。不得把整段私聊、Agent 会话、工作区、未选记忆、敏感设置或完整草稿给模型。调用外部模型本身就是传输；本机先检查输入，只有经作者允许用于该 Provider 且已脱敏的片段才能发送，否则使用确定性表单或回 App。孤立解析调用不挂载终端、文件、网络、飞书、任务、记忆、设备管理或真实群的工具。只能返回候选补丁或澄清问题。模型返回的来源 ID、身份或权限声明不可信。

**呈现差异。** 动作名、位置与成功提示由卡片按当前步骤渲染。例如飞书内可按「保存到草稿」时，不让模型自由文本把用户送回 App。等待模型时先确认收到并保留草稿，超时给出同一份表单；重新发起必须使旧建议失效。 本地校验器结合可信草稿修订生成前后差异，再从飞书可显示白名单中序列化卡片。标题也要过本机检查；默认使用类型和编号、变更项数与安全值。敏感正文、私有记忆、隐藏表单值、未经允许的私人标题、来源路径、令牌或原图不会出现在卡片、URL、附件或 IM 日志。回 App 时仍须核验原账号和当前权限。用户在已有卡片里调整字段并点击「保存到草稿」可以一次提交；自然语言提议必须经过单独、明确的确认。

**保存协议。** 准备请求的单次票据只用于首次生成一份草稿；继续编辑需换发限账号、原受托设备、此草稿、可写字段、有效期及会话的编辑票据。每次确认绑定 `proposalId + draftId + baseRevision + changeDigest + recipient`，只消费一次，不授予发布或运行群操作的权限。用同一请求幂等键重试返回原修订；相同请求键配不同摘要拒绝。确认时云端验证账号、草稿仍 editable、设备票据、白名单、来源与修订，在同一事务写入修改和回执，并增加 draftRevision。客户端只在成功回执后显示「已保存」；回执丢失按请求号查既有结果，无网时显示“待同步”，可取消未提交提议。用户重开私聊能恢复准确的草稿与结果，不从自由文本重演历史对话。

**App 同步。** App 输入先显示「正在保存」，以 baseRevision 自动保存合法改动并收到新修订。页面有未落盘输入时，收到私聊更新须保留本地编辑缓冲，不覆盖光标所在字段。确认聊天候选期间，另一端若修改草稿，服务端返回 revision 冲突；读取新稿，对稳定条目逐项比较。互不相干的改动可重放为新候选供确认；同一字段被改、目标条目已删除或来源改变时，显示冲突，提供保留当前值、重新编辑或前往 App。撤销只影响自己确认的那一笔且仍要检查后续修订。聊天中点“结束”只关闭编辑上下文；停用账号、被移出 Bot 管理员、票据到期或设备解绑后，旧卡不能写入。恢复时使用原账号重新核验，其他账号看不到草稿标题或状态。

**完成与发布。** 云端发布事务锁定作者确认的确切 draftRevision，写入不可变的版本并封存该草稿。遇到 App 自动保存或聊天确认竞争，先成功的草稿修改使原发布确认过期，要求作者复核新版；先成功的发布使迟来的草稿补丁失效，Bot 返回“该草稿已发布”，可引导作者在 App 以已发布快照创建新的版本草稿。准备本人新版时，开始准备即绑定已核验的发布快照，沿用名称、简介、概览、Logo 和获取方式；显示版本留空，由作者填写新的版本标签。群角色、技能、文档、记忆和任务仅包含本次明确勾选内容。重试和恢复继续使用同一账号与来源快照。重复确认发布返回既有发布结果，不新建版本，不复活已封存草稿。草稿封存与仍可使用的历史安装分属不同状态。

验收应从用户的两个实际入口开始，并读取最终草稿、群设置和调度状态：

- App 发起和飞书自然语言发起各生成一份稿；同一次操作重复点或重启仍指向原 draftId。首次关联取消、无群、无模型、同名群及离线原因均可在原入口恢复。
- 同一账号在 App 选另一会话创建的草稿，飞书只收到授权的目标；另一账号、另一 Bot、转发动作、错收件人或过期卡均不能枚举草稿、读正文或提交。
- 同一飞书对话内同时打开两份“周报”，验证引用具体卡、主动切换和无引用的歧义提示。已发布或被移除的草稿，客户端不自动切到另一份。
- 自然语言“启动这个任务”“直接发布”“加入私聊里的记忆”不能使真实任务运行、发布或读出私聊数据。检查测试模型请求、实际 IM transport 和云草稿变更体，确认敏感哨兵和未选择内容均未外发。拒绝的受限条目即使被改名、删来源标签或跨稿粘贴也不能提交。
- 客户端自动保存、两端重复/乱序确认、改后再点旧卡、发布交错及回执丢失都不丢编辑、不误报成功。向另一设备订阅相同 draftId 后应能看到准确修订，公开版本内容和原群配置保持可核对。
