## 谁能让哪个 Bot 给谁发消息

App 的登录用户以不可变账号 ID 识别。设备凭据用于控制当前 daemon，飞书应用凭据用于发消息，三者分别验证。配方操作同时需要有效账号和当前设备的本地控制权限；在其他已配对设备操作时，通过已有授权连接交给目标 daemon。在本机登录账号不会自动为这个账号开通任意设备管理。

目标 daemon 保存 `(accountId, deviceId, botRegistrationId, appId, platform, tenantKey?, openId, verifiedAt, revokedAt)`。其中 `platform` 取现有 `AppCredentials.tenant` 的 `feishu | lark`；这是平台品牌，不能当真实租户 ID。可信事件能提供租户标识时一并校验；没有时，至少固定应用、注册实例及其经验证的事件通道。设备或 Bot 展示名、群名、OAuth 邮箱、跨应用的 open_id 都不能用于投递。登记管理员名单也不证明某个 GitHub/Google 登录者就是名单中的某人。

**首次绑定建议。** 已有可信绑定且该操作者仍为所选 Bot 的管理员，直接继续。初次没有映射时，App 在目标设备签发短时一次性绑定挑战，绑定当前账号、命名 Bot 和随机 nonce，页面显示「关联飞书身份」。用户把关联码发给刚选的 Bot，两端显示同一确认摘要；daemon 从受信任的 P2P 事件取发送人，检查该 Bot 的实际管理员资格，用户在发起操作的已登录 App 确认，再原子消费挑战并存映射。关联码只保存摘要，有期限、次数限制且一次有效。账号、设备或 Bot 不符、码被消费或身份不是管理员时均拒绝。可提示扫码注册者作为候选，但不静默选择注册者、第一位管理员或先前私聊过的人。身份已关联后，准备配方无须复制指令或主动给 Bot 发第一条消息。

目标设备不能断定收件人时，只显示「需要关联身份」，不发配方内容给任何候选人。管理员被移除、Bot 重注册或应用/租户变化使原映射失效，未完成请求暂停，重新关联方可另行确认。账号切换只允许原账号恢复对应请求；注销期间即使收到卡片回调，也不得借新账号授权上传或推进发布。

## 从 App 确认，到飞书准备，再回草稿

创作中心提供当前设备的 Bot 及该 Bot 已绑定的真实群聊；先选 Bot，再选群。从群内或为已有发布准备新版本时预选对应 Bot 和群，只有用户点击确认才提交。提交前重新读取来源、群成员关系、作者对原配方的更新权以及源配置 revision。相同设备上不同 Bot 的同名群分别列出，目标没有可选群时进入现有入群流程，完成后再返回。来源正在租用、只读或无导出授权时不可作为本地发布来源。

目标 daemon 的本地操作表先持久化 `operationId, requestKey, accountId, deviceId, registrationId, chatId, targetOpenId, purpose, parentReleaseId?, sourceRevision, expiresAt, state, stateRevision`。接口可形如 `prepareRecipe(source, clientRequestId, expectedSourceRevision)`、`getPreparation(operationId)`、`cancelPreparation(operationId, expectedRevision)`。客户端的重复确认复用同一 requestKey，重开私聊复用同一 operationId。同一账号/来源/用途已有未完成请求时先打开该请求；用户明确另建草稿才创建新请求。故障恢复依靠数据库/持久 journal，不依靠渲染状态、窗口句柄或浏览器缓存。

**准备请求的云端仲裁。** 由目标 daemon 生成 operationId，本地写入后，在云端以**相同的 ID**注册。云操作行只含账号 ID、本次设备标识、用途、状态、版本、到期时间和完成后的 draftId。Bot、群、收件人和内容留在源设备。设备在当前账号会话中证明其本次请求的设备密钥；服务端签发只作用于此账号、此设备和此 operationId 的短效操作票据，提交请求需证明持有相应密钥。登记和签发不授予常设设备控制权。未收到成功登记回执时 App 显示「待发送」，不调用飞书；网络恢复按原 ID 登记，若另一端已取消则收敛到终态。

任意已登录同账号客户端可向云端取消已登记请求。云以服务端时钟和单一事务决定草稿接收及取消的先后：署名/鉴权身份必须是原账号，草稿接收还必须核对设备、操作票据作用域、到期时间、状态和预期云 revision，CAS 只允许活动请求一次转为完成；在同一事务写入唯一的私人草稿并关联 draftId。对象暂存时，对外可读以事务确认为准，未获接收的暂存内容不可读并按时回收。提交之前已观察到取消或过期，连快照上传也不发起。并发请求到达时，取消先成功则服务端拒绝接收，后来的卡片无效；完成先成功则取消返回既有 draftId，不删除草稿。另一个设备可取消，不能持自己的设备凭据冒充源设备提交。服务端以复读终态处理重试和回执丢失。离线时点取消先在本机停止调度，App 标「取消待同步」，在收到云仲裁回执前不能承诺跨端已取消。若尚无登记或登记结果未知，用同一 ID 幂等登记取消终态（或写取消墓碑），阻止迟到的登记重新发出私聊。

操作票据短于操作本身时，同一账号和源设备只有在云行仍活动、未被取消且未到 operation 截止时间时才可续取票据。换号或退出只暂停本机发送和提交，不延期或取消原请求。原账号回到源设备先查询云端状态再恢复；明确取消及 operation 到期都是终态，只能另建请求。私聊事件的本地回执不替代云端“草稿已接收”的回执。

| 当前状态 | 转移与 App 呈现 |
| --- | --- |

App 和 daemon 均不能把“已打开飞书”视作发送成功。重启从未完成日志恢复；可按当前设备和账号查询并订阅状态，有断线时按 stateRevision 重新拉取。技术日志只需请求号、阶段和错误分类，不记录消息、挑战或选中内容。设备没有到达云的链接时不由云猜测私聊投递结果。

绑定证明与业务票据分开签发和失效。新卡无需 LLM 生成，daemon 可根据批准的来源和可选字段确定性构造。首次可能没有受信的 P2P chatId：使用该 App 验证的 open_id 发消息，以成功回执锁定真实 messageId 和可用的 chatId；若还不能确认会话属于 P2P，在验证邻接的消息来源和会话类型以前保持等待。禁止拿本地 `oc_dm_<appId>` 伪造物理 chatId，该值是群注册表的私聊聚合行。高频轮询和消息回声不生成发布请求。

卡片携带不可枚举、短效且仅用于本次动作的引用。处理器从已认证的 Bot 事件获取 bot、操作者、消息及会话，不信任卡片中自称的账号、设备或来源；重新检查当前管理员与绑定并匹配 P2P 和指定消息。发送确认落盘前发生回调时暂存待核实，用同一操作的受信消息对应关系对账；不能匹配则不应用。本地回调事件唯一键和本地 CAS 只允许一次冻结候选，最终是否生成草稿由云仲裁。仅关闭窗口不取消；再次打开继续同一请求。源群解绑或配置被改过，提示重新预览并确认，不悄悄导出新内容。

**飞书本身就是一次对外发送。** 生成任何卡片或私聊文本之前，daemon 在本机枚举、分域和检查候选条目，再从固定的卡片白名单序列化；禁止把源快照或正文作为隐藏字段、按钮 value、自动摘要、链接参数、替代文本、日志或附件发给飞书。卡片只含固定文案、经允许且检查过的安全标题或「Bot 记忆 1」这类临时编号，以及短效动作引用。标题不确定安全时统一显示编号。未选择的敏感记忆正文从不发送到飞书。即便已选择，卡片也仅显示该项编号/安全标题；需要看原文时，用户返回 App 的源设备视图，再检查账号、设备权限、请求与当前 Bot 管理员后，在本机展示并确认。只有明确选择、复核并通过扫描的文本才可提交给账号私有草稿服务。拒绝的条目既不出现在 IM 内容中，也不进入草稿。

从「分享链接」转发时携带不可变的配方版本，不发本机快照、私有草稿或分享码。衍生草稿展示原配方、原作者和安装版本，公开文案由新作者填写。安装时为每条规则、记忆、任务、技能及 setup 步骤保留来源标签（来源配方／版本、稳定条目 ID、原始摘要、作者与分发策略），以后编辑、改名或复制仍保留其来源关系。在「选择内容」中，其他作者受限配方的原始及衍生条目显示「仅限本机使用」，不可勾选、不可导出；草稿生成器也拒绝这些条目。获得该版本使用权的人可以继续在已授权的本机应用这些内容。原作者通过授权检查后可为自己的原配方发布新版本；另行发布只可选来源可验证、由本人独立创建的条目。来源缺失、与受限条目混合或无法区分时，禁止导出。服务端接收草稿和确认发布时分别根据受信安装/版本清单、条目来源链及账号所有权复核，拒绝删除来源标签、只改客户端字段或将受限步骤夹入自建条目的请求。此机制约束产品内的选取和导出，不能识别所有人工重写。

导出采用版本化的白名单结构。草稿预览、获准查看的版本详情和安装读取同一个冻结快照，缺省推荐字段展示「未指定」，空记忆保留空列表。校验时拒绝未知字段、无上限嵌套、过大附件、路径穿越及超额条目。公开介绍由作者填写，提交前也做敏感信息提示；不能自动用对话、内部角色或任务内容补成公开简介。

## 安装、共享项目和更新

账号持有某一版本的获取资格，设备持有群内实际安装。单个安装位置以 `(deviceInstanceId, botRegistrationId/appId, platform, physicalChatId)` 唯一，必要时附真实租户标识；比对当前注册实例可识别卸载/重新注册。初始版本允许同一群的不同 Bot 各自使用一份配方，单个 Bot 在同群只允许一份。同槽位已装 A 再请求 B 时显示占用，不能覆盖；可选择同群另一个已有 Bot，或走普通添加 Bot 的流程。用同名称的新群、用户切换设备、项目改名均不能串到其他记录。

1. 免费获取或分享码兑换先取得账号服务的版本凭证。一次性码在云事务内消费并写取得记录，对同一幂等键的网络重试读原结果。作者本人凭作品权限添加到群，无需为本人建立领取记录。取消入群仍能从「已获取」重新使用。
2. 普通入群表单携带只读 `recipeId/releaseId/digest`，来源固定到所选版本。在目标 daemon 确定目标 Bot、校验版本证据、必需配置及本机能力。创建群复用建群 journal 和 provider 的群创建幂等键；「Bot 已在群」的路径重查该 Bot 当下是否仍在目标群。已存在的同 Bot 绑定直接选用，缺绑定才调用原绑定逻辑，不重复建同名群。新建飞书群已成功而本地安装失败时记录其真实 chatId，从此群恢复，绝不自动解散群或重新创建。
3. 本地记录包含槽位、安装 ID、recipeId、releaseId、快照摘要、来源作者、账号引用、本地 revision、各条目的来源键及已应用的基准快照。摘要校验通过才写，安装与任务启用分开。使用安装 journal 记录预期 revision、计划、已完成子步骤；所有读写方使用同一槽位锁/变更 revision，写入暂存版本后以一个活动版本指针提交。若旧配置、任务或记忆写入不能参与同一数据库事务，就先准备不生效的数据，提交前后读者均按活动版本取值，后台按操作日志补齐可重复执行的写入。失败只撤销由该 operation 创建且 revision 未被用户改动的内容。
4. 原项目库可能由多个群共享。不要把配方写成共享项目里的全局设置、普通技能搜索路径或整个 Bot 的记忆。设计新增按安装位置读取的配置/技能/记忆覆盖层，并由该 Bot 在该群的上下文装配。新技能放在该安装的托管目录，目标群显式接入；没有隔离能力的资源应标为待完成并暂停应用。任务生成新的本地 ID 并绑定本群，按来源键幂等，不能改动同 Bot 其他群的任务。持有配方不意味着能修改同群其他 Bot 的规则。
5. 更新检测读公开发布指针，以不可变 releaseId 和发布顺序比较，不按字符串比较版本。忽略记在该槽位的 `ignoredReleaseId` 上，只隐藏这一次提醒；群内仍可查看已装版本及手动更新。后来不同版本再次提醒。账号换设备或相邻 Bot 的忽略状态不受影响。
6. 更新时固定 base=上次安装的作者快照，local=当前该槽位实际覆盖项，incoming=用户选中的目标版本。按稳定条目键三方比较：本地未改取新版，作者未改保留本地，两者相同直接采用，两边改动不同或一边删另一边改，列出具体差异让用户选择。拆分定时任务并保留启用决定，新增任务先暂停。最终操作记录源 releaseId、本地 revision、目标 releaseId/digest、权限验票和冲突选择。确认到落盘间群内设置、绑定或目标最新版本变了就返回冲突重新预览。可以在提交前再读云端发布指针并记录检查时点；之后恰好发布的新版本视为下一次更新，绝不把本机提交版本写成更新的版本。飞书“已提交选择”只代表收件；App 以目标 daemon 的安装提交回执显示“已更新”。
7. 账号云与本地文件没有共同事务。已兑换但安装中断保留该版本取得权；已装不擅自回收。需码的新版本先重新核验该版取得权，下载或后续写入中断不能再次扣码。免费版本从群内直接更新的，开始前由账号服务在版本仍在架时核验并登记限账号、版本、目标设备和 operationId 的待确认下载凭证。它不进入「已获取」，也不能拿任意公开下载冒充成功安装。普通撤下时停止新请求，已获下载凭证且成功落地的操作仍可用原凭证结算；平台封禁优先，保留本机事实但不再开放分发。目标机成功提交后写入按 `accountId/recipeId/releaseId/operationId` 去重的待同步记录；是否已更新看本机回执，是否已记入账号看云回执。失败退避或同账号下次登录重试，修复期间标「账号待同步」，不能借其他账号同步、降级已有较新版、或把当前已失败的更新记成成功。云记录可持多版资格；库默认展示已获且仍可用的最高发布 revision，不被之后补领的旧版降级。发布成功回执丢失也用同一发布请求号查询既有版本，禁止创建第二份发布。

**文字角色的目标兼容。** 当前服务允许角色说明至多 16 KiB，但现有群补充说明限制为 5,000 个 Unicode 字符。安装预检必须按目标版本的实际限制检查，超长时说明原因并停止，不能截断后安装。群内角色应写到所选 Bot 的群补充说明，不能写进影响其他群的 Bot SOUL。所选绑定的补充说明与安装元数据须在同一个项目记录内原子保存，确认后其他管理员改动、Bot 重注册或账号切换均使旧预览失效。

**setup 在本机的作用域。** 发布版本保存作者编写的步骤，使用者的选择由目标设备上的这份安装保存。打开「使用设置」时，读取现有安装记录与该 Bot 在该群的实际设置，能从入群时的选择确定的值直接显示。涉及本机能力的步骤沿用相应设置入口及其权限控制。重跑时只提交用户改动的项，使用已有安装位置和 revision 校验。取消保留上次已保存的设置。新版修改步骤时，在已有更新差异中指出新增或变化的要求。仍然适用的本地值继续生效，新增权限由用户处理，对应功能在条件满足后才可使用。安装结果与各项能力是否可用分别显示。

## 迁移、降级及验收

现有群、项目、任务、记忆不含配方，升级后默认没有关联。不能从同名群、技能包名、作者名或现存目录推断安装关系。新表可惰性建，旧行只读兼容；迁移先备份、记录 schema 版本及完成标记，可中断重跑。先在读取端和运行端加入槽位隔离与能力协商，再允许写入。旧版本不认识安装资料时只允许普通已有能力或提示升级，不尝试应用、刷新或清理这些资料；回滚保留日志和快照。解绑、Bot 移除或设备失联时将本机关联标记失效，云端已获取和已发布不随之删除。重新绑定要重新核验真实身份与来源。

| 验收场景 | 必须能观察的结果 |
| --- | --- |
| 两个云账号共用设备、同名 Bot、注册者已离开管理员、首次绑定码过期／错 Bot | 未授权身份看不到他人准备状态且不会收到任何私聊；仅匹配 Bot 的当前管理员能完成首次关联。 |
| 多次确认、重复回调、发送成功后宕机、超出上游去重窗口、飞书缺权限、离线后恢复、退出账号 | App 的状态如实区分“待发送/已发送/结果待核实”；重开同一请求只生成一份草稿，旧卡或新账号不会取得写权。 |
| 设备未登记、登记回执丢失、已退出或换号、票据过期、跨端取消与接收并发 | 未登记的请求没有 IM 调用；重复登记返回原操作。暂停后原账号可续办，其他账号和其他设备提交被拒。取消先赢无草稿，完成先赢重试/取消返回同一草稿，到期绝不复活。 |
| 同一群两个 Bot、两个设备有同名群、同一项目目录被多个群复用 | 只修改明确选择的槽位，原有 Bot 设置、任务、共享项目和所属人数据保持隔离。 |
| 首次设置、重开设置、作者更新步骤 | 有现成 Provider 的 Bot 可直接沿用它。重开能看到上次选择，取消后值不变。新版新增可选能力时保留原有可用功能，验证同群另一位 Bot 的本地设置没有变化。 |
| 未勾选记忆、自由文本含密钥、私聊来源、技能目录越界、setup/调度声明 | 为未选记忆正文、私聊原文和密钥分别注入不同哨兵。在测试 IM transport 捕获实际发出的消息 JSON/卡片、button value、URL 与附件，并在云端测试 transport 捕获实际上传体，两处均不得出现相应哨兵。验证无法通过安全检查的标题退化为编号，只有本机授权页面可见原文。首次安装不会执行命令或启动调度。 |
| 同一分享码并发兑换、兑换成功但断网、建群成功后崩溃、本机提交与云回执之间宕机 | 同一权利仅授予一次、同一物理群与安装只建立一次；网络恢复后以原用户原 operation 对账。 |
| 忽略一个版本后再发布、安装只读旧版、并行修改条目、CAS 失败、迁移中断及降级 | 再次提示新版，已安装详情能看原版本，冲突需要重新确认，失败操作不报成功；普通无配方绑定照常使用。 |
