# 在私聊中完成配方发布

2026-11-15 产品与技术设计。作者在本人飞书私聊里选择来源、修改、预览并确认发布，后续版本和分享码也能在同一入口管理。App 提供查看和管理便利，不要求作者进入发布向导。本文是选定契约，尚未完成实现和真实流程验收。

## 创作者的主流程

1. 作者完成一次账号与本人 Bot 私聊的关联。之后可直接在私聊发起分享。Bot 由对话确定；只有一个有权访问的来源群时直接展示，多群或重名时明确选择。App 群入口预选当前 Bot 和群，不再次选择设备。
2. 作者选择要包含的角色、规则、沟通设置、技能、文件和任务。记忆不参与取源。自然语言与卡片字段修改都产生确定的候选；作者采用后自动保存，不需要去草稿箱再保存一次。
3. 作者请求预览发布。卡片展示名称、显示版本、公开介绍、获取方式和实际配置清单，完整内容可在原私聊按节查看。较长内容也可打开同一修订的已登录只读预览，最终确认仍在聊天。
4. 作者点击“确认发布”。模型的一句回复或作者自由文本“发布吧”只能打开确认卡，不能直接公开。发布成功后，原卡显示准确版本及社区链接。
5. 作者从原卡或“我的配方”继续创作、准备新版、撤下版本，或查看、生成、停用和重显分享码。每个动作固定目标作品、版本或码，不用名字和尾号猜身份。

“草稿”作为内部持久状态保留。用户看到的是“创作中”“正在保存”“已保存”和“已发布”。中断或退出不删除未发布内容；未完成的保存不能显示为已保存。

## App 与私聊各自呈现什么

App 的“我的配方”分为创作中和已发布。创作中详情复用社区和群设置的完整配置结构，主操作是“在飞书继续创作”。删除必经的手工发布信息表单及 App 发布确认对话框，保留旧数据和此前未确认保存的读取恢复。

App 继续提供版本查看、撤下和分享码管理。已认证作者可以在 App 复制自己的码，不强迫跳去飞书。由私聊发起的码操作只把明文交给原来的、重新核验的本人私聊。两条入口都不把明文放进群、模型、普通通知、URL、日志或持久明文 journal。

详情、创作预览和发布预览沿用概览、模型与权限、能力、沟通方式、任务五个页签。返回、按钮、对话框和间距复用既有组件，不再加一套编辑器风格。缺省配置仍写“未指定”。

## 三个既有所有者

daemon 持有真实私聊上下文、来源快照、候选、原收件人批准及卡片投递状态。Main 持有 NativeAccount、确切已批准请求及其执行结果。云端持有草稿修订、不可变版本、取得权、分享码和幂等回执。

沿用现有 AuthoringLedger、AuthoringJournal、MetadataJournal 和社区事务，不新增云作品表、发布服务或长期云 Bot。模型不能提供账号、操作者、设备身份或权限声明。IM 回调不能取得原生账号令牌，也不能指定任意 HTTP 路径、method 或 headers。

每份创作使用稳定的初始准备身份与云 draftId。每张卡固定账号、tenant、openId、真实 p2p chatId、Bot incarnation、binding、来源设备、公钥、群 incarnation、messageId、cardId、ref 和 generation。每次外部操作重新检查本人、管理员、原账号及设备授权。

## 来源连接独立于当前设备视图

当前实现的页面 detach 已能保留已有操作，关窗也只是隐藏；切设备和完整退出仍会使原生 lease 失效。新的来源连接必须实际与 UI view 分开，不能只删除旧的 viewSeq 校验。

设备管理层按引用保留已经配对的来源 peer。切 UI 设备只切 view，不关闭仍被创作持有的来源连接，不把权限转给新选中的设备。移除设备、撤销配对、换钥、降权或断线仍使 lease 失效。多个创作共享经核验的关联，按账号和 binding 分区，不因新建一张卡替换其他账号的 Presence。

Main 登录或重启后恢复明确登记的来源关联。真实本人私聊消息可以产生限原 binding 的唤起意图；Main 通过已认证 owner desktop 通道恢复短期上下文。连接心跳不能延长人类批准，过期卡不能复活。

隐藏窗口后可继续。完整退出 App 后没有 NativeAccount 执行器，不宣称离线发布成功。工作保留，原账号与来源设备恢复并重新核验后继续。换账号不能处理另一账号的旧点击或看到其作品和码。

## 预览绑定确切修订

预览先等待所有已批准保存消歧，再读回准确草稿、canonical、附件及公开元信息。最终摘要包含 draftId、revision、显示版本、名称、简介、概览、获取方式、canonical 与部件摘要、来源和父版本。

卡片摘要与完整分节预览从同一快照派生。不能截断长内容后宣称已经完整展示，也不把未经检查的源文件或私人文本自动发到飞书。新修改使旧发布卡失效；先批准发布则暂时冻结该作品的继续修改。其他作品可以继续编辑。

本人点击后，daemon 持久记录精确批准。Main 以原账号、原来源和原请求执行，不从按钮或模型文本重新拼接正文。云端仍按 exact revision、canonical、来源与现有发布事务裁决。

## 发布、回执与分享码恢复

Main 派发前持久保存确切规范字节和原 requestId。仍获准重发时携带相同正文和键，重复点击或回包丢失不能创建第二个版本。首次派发检查活草稿；恢复路径不能因为成功发布已退役草稿而误报不存在。

批准过期或账号权限失效后，只读查询原回执，不用 POST 探测是否曾提交。新增的窄查询只接受原账号、确定动作、请求键和有界原始参数，由服务端重算既有参数摘要。返回非秘密的准确版本、首码或批次 ID；无命中仍为结果未知，不推断从未提交。

发布成功但社区链接或飞书卡更新失败时，只重试结果投递。首码与批量码按确切 codeId 查询当前状态并重显，已兑换或已停用就显示真实状态，不能靠再次发布或签新码补回包。

分享码列表分页显示稳定选择标识、后缀及可用、已兑换、已停用状态。发码确认具体版本和数量，沿用同键同批与现有上限。停用和撤下先展示准确目标及影响，由本人确认；已有合法取得权与安装配置按原规则保留。

## 实施依赖与验收

先实现来源连接和关联监督，再冻结私聊有限动作与状态契约。云端窄回执查询可独立实现，Main 后续复用原有保存、metadata、发布和码管理接口。完整私聊闭环通过后移除 App 的必经向导，保留完整只读详情和管理。

验收必须从正常用户入口完成：私聊选真实群、连续修改、完整预览、本人确认、打开实际社区版本链接、继续新版、撤下与多码三态。覆盖隐藏窗口、切设备、退出重启、换账号、管理员移除、群重绑、两份作品与回执丢失。核对源群配置、任务状态及原生记忆不变。不能以直接 RPC 成功代替 App 或私聊正常恢复入口通过。
