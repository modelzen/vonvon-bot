# 配方资源与 Agent 上下文

2026-11-15，按 owner 最新意见更新。本文是当前需求；上下文交付和 Agent 获取新版仍在实现，不代表已经通过验收。

## 产品模型

配方是账号下的版本化实体资源。它给 Agent 提供调整配置所需的资料，不是群聊持续绑定、订阅或安装的模板。一个群可以先后参考不同配方；同一份配方也可以用于不同群。Agent 结合用户本轮要求、配方指定版本和当前配置决定如何合并。

「我的配方」统一包含「已获取」「创作中」「已发布」。社区的「已获取」是进入同一页签的快捷入口。开始创作的主要入口叫「创作配方」，位于「我的配方」。群设置不再提供重复的创作入口，也不展示配方来源、安装版本或群级更新提醒。

资源有新版本时，在「我的配方」提示。获取新版与应用内容是两个动作。领取不会改变任何群配置，也不代表用户授权自动修改。需要分享码的新版本仍需满足该版本的获取条件。

## 创作与发布

创作先选一个 Bot，群聊可选。作者可以在私聊里提供链接、文档、教程或直接描述需求，Bot 据此整理内容并保存经作者确认的本地草稿。只有作者选择参考已有群时，Bot 才盘点该群的配置。已有作品继续使用原来源，不重新选择设备和群。首次本人私聊关联仍要验证收件人。

App 对已送达、待核实、后台准备和恢复已有私聊分别显示真实状态。只有收到送达回执才能说已发送；未知结果必须核对原请求，不能另起请求重复发卡。打开私聊失败后的重试只重开链接。

内容在私聊中整理和保存。完整预览在 App，App 可以明确确认发布；飞书短卡也可以直接明确确认指定版本。打开预览不会发布。配方不携带记忆；Setup 是普通技能和作者说明，不增加强制准备步骤。创作时核对来源群/项目依赖，有需要时询问作者是否整理初始化技能，推荐 `xxx-setup` 而不限制名称。能力列表把名称中包含 setup（忽略大小写）的技能置顶并提供用途说明；交给 Bot、完成目标群配置后，建议用户把含实际技能名的初始化指令复制到该群执行。

创作过程用于确认本人、原 Bot 和群配置的内部来源事实仍可保留。它们不等于使用配方后的群绑定，也不应公开为群配置元数据。

## 使用与更新

用户选定已拥有或已获取的精确版本，将版本引用与小型展示资料交给某个 Bot。此时不拉取完整正文和技能文件，Bot 先向已验证的本人私聊发送简短引导。随后由真实本人选定群并提出应用要求，例如「参考这个版本调整产品群，保留当前模型和发送时间」。Agent 通过准备资源工具核对本人轮次、目标群身份、账号和精确版本权益，校验通过后才拉取完整内容；再读取当前配置，按要求更新或合并。

Agent 可以查询该配方的新版本。用户要求使用新版时，先取得精确版本的账号权益，再读取内容。已拥有旧版或能公开浏览介绍，不代替新版权益。需要分享码时不跳过兑换条件。

群角色、规则、设置、技能文档和任务均可以是参考资料。Agent 继续使用现有配置、文件和任务工具；不增加独立的安装或更新向导。合并使用原读取版本检查冲突，不把别人的并发修改默认为自己的更新结果。技能文件保存和运行会话已加载技能是不同状态。

写入后的群配置保持独立，不需要记录或回报「已安装某配方版本」，也不从群反向轮询配方更新。原生写入工具保留正常权限、修订和保存检查。上下文交付本身不写群，不执行 setup，不启动任务，也不发布作品。

## 实现边界

- 浏览复用预存的精简展示接口，获取接口只登记权益；完整正文及对象读取要求当前账号对该精确版本 `owned` 或 `acquired`。公开可浏览不等于可读取完整对象。
- 复用已验证设备和本人私聊绑定，以及普通 Agent 的上下文和工具。不将 Supabase bearer、刷新凭据或整个 NativeAccount 暴露给 Agent 或远端 daemon。
- 只读内容、新版权益获取和修改群配置分别有明确权限。主动引导不能冒充真实本人轮次来修改设置或领取资源。
- 大配方在实际应用到已选群时提供完整、有界、可按需读取的资料，完整缓存绑定本次本人轮次和目标群身份。普通浏览、索引、查看技能说明和交给 Bot 的引导不触发完整读取。不能把全部对象塞入模型，也不能静默截断后声称完整应用。落盘路径由 daemon 决定，沿用内容哈希、文件类型和路径验证。
- 未知送达和断线重试使用原请求身份。账号、绑定、设备身份和管理员权限变更要中止在途的新读取；已按本人要求保存的普通群配置不随账号退出撤销。
- 上下文路径不经过 RecipeUseController 的群安装、prepare/commit、来源、ignoredVersion 或自动任务激活。旧实现数据先保留，迁移不能删除用户正常配置。

## 验收

创建、继续创作、App 预览发布和飞书直接发布分别在真实环境验证。上下文领取和交付后，群设置、任务和来源状态必须保持原样；只有本人随后提出修改要求，Agent 才经现有工具保存并读回结果。再验证同一群连续参考两个配方、保留本地修改、并发修订冲突、新版未获取、分享码、换账号、断线和重试。

以上需求覆盖早期设计中「同一 Bot/群只有一个配方来源」「群内更新提示」「按安装基准更新」「忽略某个群的配方版本」及配方安装向导。原文档可作为历史记录，不再决定新使用流程。
