# 账号、社区与群内 Bot 配方 · 首版 PRD

状态：2026-11-13 对审稿。本文取本轮 owner 的最后意见；交接记录与原型的早期分支不是当前需求。范围是能从一份真实群内配置发布，到另一个账号在自己的群内使用并更新。默认不引入付费、人工审核队列、中继或常驻云 Bot。

## 谁拥有什么

| 对象 | 归属、可见性和作用 |
| --- | --- |
| Vonvon 账号 | GitHub、Google、Apple 在网页授权，入口只叫「登录」。按 Supabase 默认身份关联规则；同一已验证邮箱可归入同一个账号（owner 已确认）。资料以稳定账号 ID 关联，邮箱只用于认证；Apple 私密中继等不同邮箱不猜测为同一个人。没有手机号、QQ、飞书组织登录、人工合号流程。 |
| 设备与 Bot | 保留设备切换菜单；管理设备 → 原设置「设备连接」，添加设备 → 原配对弹窗，账号管理 → 设置「账号管理」。登录显示账号头像，否则显示原 Logo。账号不自动发现、接管或打开远程设备；手动配对与本机运行独立于云登录。 |
| 配方与发布版本 | 作者拥有配方的编辑权；每次发布创建不可改的版本。公开页展示某一版本，群里执行的是安装到目标 Bot 的配置；领取者得到使用权，不成为作者。 |
| 草稿、已获取 | 都随账号。草稿只属于作者，所有已授权版本可再次使用；切换设备不会丢失。作者通过创作中心/来源群查看和管理版本，不在公共详情放「管理发布」。本人直接添加到群，无须领取自己。 |
| 群内安装位置 | 一台设备的一个群中，一位 Bot 最多关联一份配方。这个群的另一位 Bot 可以使用另一份，也可以完全不用配方；按各自原有规则协作。来源、版本只读，本群可改具体规则。不能在同一 Bot 上悄悄覆盖已有配方。 |

## 从社区看、选、找

社区首发一份「Vonvon Bot 使用与排错助手」配方。用户可在同一份配方里提问、排查本机故障，并在确认产品问题后提交反馈。[首发内容与验收](first-release.md)

导航顺序「此刻／社区／Bot／群组」。社区有「Bot 配方」和「Bot 租赁」，后者只出现一次「敬请期待」。早期没有分类、热榜、虚构的使用数。

- **横幅和 Logo**：作者在私人草稿「概览 → 编辑发布信息」填写名称、公开简介，可上传、替换或移除一张方形 Logo（PNG/JPEG/WebP，原图最大 2 MiB，居中裁成方形，设计预览输出 192×192）。默认图标也可以发布。在这里就能预览横幅，最终发布前再看一次。横幅用这一版的公开文案、作者、版本和 Logo 套版；不设单独横图上传，不需运营出图。Logo 在列表、详情和群内来源标识复用，绝不改飞书 Bot 或群头像。修改已发布 Logo 必须发新版本；衍生作品不继承他人 Logo。
- **谁算精选**：Vonvon 编辑可指定至多一个公开在架版本作首页推荐。不是类别、排名或自动看热度。首版建议从本人验证过、介绍清楚、别人能实际装起来的配方里选；凭码配方只有编辑具备合法测试资格时才能验证。小团队可在受控运营配置中指定，无需做后台。推荐精确到版本；撤下、更新不再命中，或没人选时，用「最新配方」，不显示编辑背书。
- **目录与搜索**：没有配方显示空态，有一份只显示一份。只要有内容，标题下就有搜索框，搜索全部已发布配方的公开名称、简介、作者；不是只搜当前屏，不搜受限正文。首页精选/最新占一张独立卡，其余按最近发布排序，去重，每次 8 份，手动「加载更多」，没有页码、没有强制无限滚动。搜索每次也加载 8 份；返回保留词、列表位置与已加载范围。
- **详情**：概览上方固定元数据，下方是作者自己的 Markdown；完整信息沿用群设置的模型与权限、能力、沟通方式、记忆、任务。字段未指定写「未指定」；没有记忆只留空。公开版不登录即可看完整可移植配置；凭码版未取得前只看公开介绍、Logo、作者、版本及获取条件。
- **分享链接**：点一下复制该版本的公共链接，成功在原按钮显示「✓ 已复制」；失败提供手动复制，不假报成功。任何人包括作者都可转发链接。链接不含分享码、安装权或作者管理权。

## 两次确认，分别确认什么

1. 创作中心选当前可操作设备上的 Bot，再选它已加入且已绑定的现有群；从群内「发布到社区」或已有发布准备新版时直接带入来源。没有群就不能发送，不凭群名猜匹配。**第一次确认的是“让这个 Bot 帮我准备这个群的配方”。**
2. 如果已关联本人在该 Bot 的飞书身份，Bot 给本人主动发第一条私聊。第一次尚不能证明收件人时，先在 App 完成一次关联；不是让每次分享都粘贴命令。App 标出 Bot、群和当前状态。发送失败、设备离线、权限缺失都有恢复入口；没有飞书回执就不显示「已发来」。重复点或重开私聊沿用本次请求。
3. 私聊挑选实际要分享的角色/规则、可携带技能、任务和可选记忆。记忆默认不带。工具凭据、主机路径、登录态、MCP 连接、聊天历史、整份项目不能随配方流出。先在本机整理与检查，仅将作者选择且通过检查的可移植快照同步为私人草稿。setup 是给使用者的指导，不因领取或打开配方自动执行安装命令。
4. App 待办变为「查看草稿」；返回直接打开本次生成的草稿，而非让人从列表再找。作者审核全部详细信息，单独填写对外的名称和简介；不从敏感的群规则/任务自动拼公开文案。可写 Markdown、上传 Logo、选直接获取或凭码获取。可以退出稍后继续；取消准备不产生公开版本。
5. **第二次确认才是“发布到社区”。** 云返回发布回执后才列为已发布；草稿、版本快照、公开目录与生成的首枚码不能呈现半套成功状态。新版本必须是这份配方的作者操作；并发编辑不能无提示覆盖别人的草稿修改。作者可从创作中心集中维护，群内只呈现与当前 Bot 及群匹配的记录。

聊天创建与修改的受理范围、确认和冲突见[聊天草稿](chat-drafts.md)。上传前到最终发布的大小与数量见[首版限额](limits.md)：每版 1 MiB，含最终 Logo；原 Logo 可上传到 2 MiB。单份超限保留可恢复的本地选择或上一份已保存草稿，由作者选择删减；超出历史版本或账号累计额度时说明具体原因，不建议用户靠删除旧版本解决。

## 从领取者再走一遍

1. 直接获取与凭码共用「获取配方」。未登录先登录，回到同一配方和版本；凭码只多一步输码。已取得时按钮为「添加到群聊」。领取与安装分两件事：关掉入群窗口不退还或重新消耗分享码，权利留在「已获取」。
2. 分享码绑定一个不可变版本，每枚一次；作者可批量创建、复制、查看可用/已兑换/已停用，停用未使用码。已兑显示时间及必要的账号显示名，不展示邮件或飞书 ID。相同账号已有此版不消耗另一码。停用不能撤回已合法取得权，新版本可有自己的码。
3. 复用原来的「拉 Bot 入群」入口与表单位置。两种路径是「创建群聊」和「Bot 已在的群」，只多一项不可改的配方。选目标设备与 Bot 后，确认本地模型、权限及工作目录；保留原有群内 Bot 和其他群的配置。若该槽位已装同版，打开已有配置；同一配方已有别的版本走更新；不同配方提示改选 Bot 或群，不覆盖。普通无配方入群完全可用。
4. 群内展示已应用的来源与**实际安装版本**。作者发布新版不自动改配置；可查看差异、通过私聊决定冲突项，也可「忽略此版本」。忽略只作用于当前群内 Bot 的这个新版，下一个版本仍提醒。需码新版单独验证。更新失败保留旧版；领取、建群、装配方分别回报，不能把兑换成功写成已安装。
5. 他人作品在群内可分享原链接；如果从本群准备独立作品，显式标「基于 原作者/作品/版本」，单独审核本地改动。分享码不是转授权。**首版再发布限制**：受限来源的技能、规则等作者内容默认不可转发成新作品（包括通过改获取方式绕开），来自受限版本的技能、规则、记忆、任务、setup 不可勾选导出；仅允许转发原链接及发布可验证为独立自有的内容；公开来源也不等于拥有第三方素材权利。

## 配方里的 setup 怎么用

2026-11-14 owner 最新决定：**setup 就是普通 skill**。需要在使用前执行时，由创作者在配方概览说明依赖、执行时机和运行方式。setup 技能与其他技能共用选择、详情、发布、安装和权限规则，没有保留名称或特殊格式。

例如依赖先拉取代码时，作者在说明中写明仓库和版本，并告诉使用者先让 Bot 运行自己的 setup 技能。工具安装、访问私有仓库和命令执行仍沿用使用者在目标设备的现有权限。获取、打开或安装配方均不自动运行技能。

不设置独立「使用前准备」导航、准备步骤编辑器、准备清单或系统完成状态。旧开发测试版本中的结构化 setup 字段只用于兼容读取，授权后可在概览中查看原说明，不把它自动变成可执行技能。任务安装后默认暂停，确认启用任务仍是独立操作，不依赖 setup 状态。

例如首发排错助手可以直接回答用法问题。官方反馈表由维护者配置一次，使用者只在决定提交时核对报告和收件方。即使用户选择了反馈功能，每一份报告仍由用户看过后确认发送。

## 边界与演进

社区首版是免费获取或凭码获取；不做支付、租赁结算、团队配方、多重配方覆盖、账号合并和全网远程控制。不同账号登录不能看到前一人的草稿、授权或飞书待办；本机已装配置与已手动配对设备照常保留。「退出登录」只结束当前会话，不自动删除本机配置，不使手动配对失效。「删除账号」是独立的不可逆操作；重新验证身份、列出有关作品与权益的影响后再确认，不能把这两个动作都写成「注销」。

未来的账号设备管理必须由用户在目标设备上主动开启，可明确撤销；浏览社区、登录、手动配对三个动作都不能代替这个授权。租赁将来作为社区类型；取得租约后从设备菜单切到出租方上下文，Bot 列表只显示租来的 Bot，不能据此浏览出租方其他群、文件或发布其配方。今日无需提前实现租赁表与控制服务。

下架分两种，不混用。**作者撤下**：从目录、搜索和精选移除，停用新获取和未用码；无权者打开链接只见下架提示。已有授权者仍可看、重下原版，作者仍可管理。**平台强制封禁**：不再向任何用户分发该版（包括已获取者）；账号保留状态记录，已装配置不遥删。下架与封禁使用不同的服务端权限及审计。开放公众发布前须定删除账号的保留期及申诉/处置负责人。
