### 用同一个例子对一遍

**Clay 用小助手发布产品群的周计划。** Clay 在「我的配方」点击「创作配方」，选择“小助手／产品群”。目标设备核实本人私聊和群访问后，Bot 主动发送引导。发送结果未确认时 App 显示待核实，不能假称已发卡。Clay 在私聊中整理内容、公开介绍和 Logo，保存到同一份私人草稿；随后在 App 查看完整预览并确认发布，也可以在飞书短卡上直接确认 v1.0。这时发布的才是社区可访问的版本。

**林溪用一个分享码获取 v1.0。** 看介绍不需要码，看受限配置需要这个版本的授权。兑换、消耗和回执在一个数据库事务内完成。断网重试不会花第二枚码；领取后资源属于账号，即使暂时不使用，也能在另一台设备登录同一账号后找到。林溪把指定版本交给 Bot 作为上下文，再在本人私聊中要求它调整产品群。交付本身不改变群，Agent 按本轮要求和现有工具权限读取、合并并保存普通配置。

**Clay 发 v1.1。** v1.0 的链接、内容和凭码授权仍指原版。「我的配方」提示资源有新版，群不检查或跟踪这个更新。林溪可以先不获取；要求按新版调整时，先取得 v1.1 权益，再由 Agent 比较当前群配置和所选版本，保留她指定的本地修改。其他管理员并发改动时，原修订保存检查仍生效。获取成功、上下文送达和配置保存是不同事实，分别按实际回执显示。

### 已裁定的关键取舍

- 同一已验证邮箱的 GitHub、Google 登录沿用 Supabase 自动关联；账号权利绑定稳定 ID。Apple 中继等不同邮箱不自行合并。
- 早期首版使用社区和编辑精选，不设分类和热门算法。可选 Logo 是作者唯一需要准备的图片，首页横幅自动排版；搜索固定可见，名单每次追加八份。
- 配方是账号下的版本化上下文，群配置独立；更新提示属于资源，不属于群。登录绝不隐含开启设备远控。租来的远端 Bot 是未来独立权益，不能复制出租方配置或获取设备管理权。
- 每版 1 MiB 含最终 Logo；每账号未发布草稿总计 10 MiB，历史发布总计 25 MiB。这是小规模试用的产品限额，须用脱敏作者样本校准，不是云套餐保证。
- 单次发布、兑换和应用都要能查询已有结果。单纯隐藏客户端按钮不算权限控制。分享链接、飞书卡片、本地目录访问都不能替代账号/版本授权。
- 初期不引入收费、后台全量扫描、账号合并、自动生成营销图片。手动精选和强制下架只给运营者，须留下操作记录。

### 开发结论

产品路径已能闭环，可以进入**第一片实现和联调**。不能以本地设计稿代替实际飞书投递、三种 OAuth、云访问策略或真实群运行隔离的验收。建议优先做关联身份→主动私聊的纵向验证，与云端版本授权并行；达不到验收条件的能力不进对用户开放的发布。具体通过条件见验证表。
