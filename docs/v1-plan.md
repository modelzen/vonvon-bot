# Vonvon Bot 第一版计划

这份计划把定稿的 `docs/product.md` 拆成里程碑、切片和实验。第一版做什么以 product.md 为准，本文不加它没有的功能，两者冲突时以 product.md 为准。每合入一片，就在本文第 3 节的清单里把它勾掉，写上 PR 号。本文随代码 PR 一起改，不为它另开文档 PR。同时最多两个产品 PR 在飞（`AGENTS.md`），所以切片分两条线做，见本文第 1 节。

切片和实验的 PR 不用 owner 认可：按 `AGENTS.md`，由 Claude 找另一个模型审查、CI 通过后合入。product.md 的修订按本文 4.2 分两类，只有改了承诺或范围的才等 owner。owner 出面的时候：里程碑验收；被叫去做决定；本文第 8 节列的提前准备的事。

写法和 product.md 一样："主人"指 bot 的主人，"owner"指本项目的 owner；`D/` 指 `packages/daemon/src/`。不带"本文"的节号都指 product.md，比如"3.5""第 9 节第 5 项"；本文自己的节写成"本文第 3 节"。行数都是约数，不含 lockfile 和生成文件。

## 1. 两条线和第一片

**两条线。**
- 第一条线按里程碑顺序做，当前里程碑的片做完，就出预览版给 owner 验收。
- 第二条线做依赖已满足、不挡第一条线的片：当前里程碑里能并行的片；下一个里程碑里没有依赖的片，比如 M3 的 s10、s11、s12、s16；M4 之后的迁移准备 s58、s59（本文第 2 节 M10）。尽量挑和第一条线不改同一批文件的片。
- 实验 PR 是纯文档，不占在飞名额，随时可以开（本文第 4 节）。

**第一片是 s01**（v1 计划、改名和第一版权限表），理由有四条：
1. 它本来就要和这份计划一起写：里程碑、切片清单、实验清单、Windows 代码去留，以及 product.md 没写、由 Claude 定的默认值，都在本文里。
2. 小而低风险。s01 约 800 行，其中代码和测试约 300 行，只改文案、权限常量和一处日志，其余是这份计划。
3. 直接推进 M1。新用户扫码时看到的预填名、一键授权里的权限，是 owner 第一次验收最先看到的东西。
4. 后面的片要靠它开工。`im:message:readonly` 进了必需权限，s04 的清单才能检测它，s09、s14 的补拉才有权限；`include_bot` 和 `self_manage` 进了授权链接，s27 和 s53 才用得上。

s01（#295）和 s02（#296）已合入，M1 预览版 2026-10-14 装到了 owner 的 Mac 上，等 owner 验收。同时可以开实验：e01、e02 已在 JP-VPS 上做完（#297），Mac 上先做 e06、e10。

### M1 第一个预览版（s01、s02）

**给 owner 什么：** 在自己的 Mac 上装好预览版。预览版用 Mac 钥匙串里的 Developer ID 签名，没有公证，只出 Apple Silicon 包。owner 自己扫码建一个新 bot，开权限和事件订阅、发布，拉进测试群，@ 它用 Codex 干活；再下载 Claude，绑第二个群用 Claude 试一次。这是 v2 第一次有人从头扫码建成 bot，也是 Claude 的回合第一次在真机上跑。

通知里写明：Claude 的登录要 owner 事先在终端里用 `claude` 登好。登录检测在 M2 才有，M1 的界面上还看不出 Claude 登没登录。

**怎么验收：**
1. 打开预览版会话装好的 Vonvon Bot。旧的 bridge 照常用，两边是不同的飞书应用，互不影响。先别打开"咖啡一下"，它会替换 bridge 正在用的 hook（M10 再处理）。
2. Bot 页点"添加 Bot"，用手机飞书扫码，确认预填的名字是 Vonvon Bot，然后建好。
3. 在 bot 详情页点"重新授权"开权限。在飞书开发者后台的"事件与回调"里选长连接，加上事件 `im.message.receive_v1`、`application.bot.menu_v6`、`im.chat.member.bot.added_v1`、`im.chat.member.bot.deleted_v1` 和回调 `card.action.trigger`，创建版本并发布。
4. 把 bot 拉进一个测试群，在"群聊"页给这个群绑定一个文件夹。
5. 本机环境页看 Codex 那一行，应该显示找到的 codex。显示"未安装"的话，点"安装托管副本"，装好后显示"codex <版本> 已安装。"。装了托管副本，bot 就先用它，不用自己装的 codex。#296 的检查在隔离 HOME 里这样装过，用的是 `/usr/local/bin` 下的 npm 和 node。
6. 群里 @bot 让它做件小事，看 Codex 的运行卡。
7. 在本机环境页下载 Claude（0.3.296），再拉 bot 进第二个测试群，绑定时执行工具选 Claude，@ 一次。群绑定后界面上换不了执行工具：`bindGroup` 带 `tool`，群设置页的执行工具只读。

哪一步不对，回一句"第几步、看到了什么"就行，Claude 修好后再装一版。

### M2 首次运行清单和开机自动运行（s03 到 s08）

**给 owner 什么：** 打开 app 先看到一张首次运行清单（product.md 3.1 第 4 条）：扫码建应用、开权限、长连接、事件订阅、发布、Codex 和 Claude 的版本与登录、登录电脑时自动运行。每一步实时变绿，失败时告诉你怎么做。打开"登录电脑时自动运行"以后，bot 跑在 macOS 的后台服务里，退出 app、注销再登录都在线（3.10）。终端里能用 `vonvon service status` 查看状态。

**怎么验收：**
1. 打开新装的预览版，清单显示 M1 那个 bot 每一步的状态。
2. 再扫码建第二个 bot，只照清单一步步做，直到全部变绿；拉进测试群 @ 它，能回复。
3. 在清单里打开"登录电脑时自动运行 bot"，然后退出 app，群里 @bot 仍然回。
4. 注销再登录，不打开 app，@bot 仍然回。
5. 终端执行 `vonvon service status`，显示在运行。
6. 在"应用与启动"页关掉"登录电脑时启动"，`vonvon service status` 显示未注册；重新打开后恢复。
7. 建议：把第二个 bot 拉进一个真实、低风险的群，日常用起来。之后每个里程碑都在这个群里顺带用，遇到问题随时回一句，越早发现越好。

### M3 群里的上下文（s09 到 s16）

**给 owner 什么：** 群里的对话更像同事（3.5、3.12）：
- bot 叫得出群里人的真名。
- 从主区开的话题里，bot 知道主区刚才在聊什么。连续群里有人开话题，bot 在话题里单独聊，主区那条会话不受影响。
- 话题里补拉完整，不再每轮重复话题第一条。
- `/new` 开新会话，`/resume` 换回去；bot 忙时 `/compact` 自动排队。撤回的消息 bot 不再用。
- 十分钟没有输出才算超时，超时或断网的卡片上有重试按钮。群里其他人也能领 bot 发的文件。
- `/model` 能手填模型 id；运行卡头部一直显示上下文仪表。

**怎么验收：** 在 M1 的测试群（规则模式，主区开话题）和一个新建的连续群里做：
1. 连续群主区先不 @ 说两句，再 @bot 问"刚才大家在说什么"。在开话题的群里 @bot 开一个话题，问同样的问题。
2. 话题里不 @ 说一句，再 @bot，看它知道你刚说的话、叫得出你的名字。
3. 在连续群里自己开一个话题聊几句，回主区问 bot 话题里的事，它应该不知道。
4. 在连续群里 `/new`，再问之前的事，它不记得；`/resume` 回去，又记得。
5. 让 bot 跑一个两分钟以上没有输出的任务，不会被掐断。
6. 撤回一条 bot 读过的消息，再问它这条消息的内容。
7. 请同事点 bot 回答里的文件链接，能领到。

### M4 崩溃恢复、诊断和 Linux 命令行版（s17、s18、s19、s20a、s20b）

**给 owner 什么：**
- 崩溃恢复（3.10）：daemon 或某个 bot 崩溃后自动重启，主人在飞书私聊收到一行原因。10 分钟内崩溃 3 次就停下：网页和桌面端照常打开，诊断页顶上一条红条，带"恢复运行"按钮。只是某一个 bot 反复崩溃时，只停这一个。
- 诊断页（3.1 第 8 条）：按 bot 列出连接状态、Codex 和 Claude 的版本和登录、缺的权限，以及最近没回的消息和原因。
- Linux 命令行版（3.10）：用 npm 安装；`vonvon service install` 装 systemd 用户服务，并处理 linger；`vonvon open --print` 打印 ssh 转发的办法；`vonvon bot add` 在终端里扫码建 bot。Claude 已在 JP-VPS 上走完安装、崩溃重启、停止和卸载，记录在本文第 10 节。

**怎么验收：**
1. 终端执行 `vonvon daemon status` 看 PID，再 `kill -9 <PID>`。几秒后 bot 回来，私聊里收到"刚才崩溃过一次"。
2. 10 分钟内再 `kill -9` 两次：诊断页顶上出现红条，群里 @bot 不回。点"恢复运行"后恢复。
3. 在诊断页看各 bot 的连接状态和版本；在一个没绑定的群里 @bot，诊断页里能看到没回的原因。
4. Linux 部分不用 owner 做；有 Linux 机器的话，可以照本文第 10 节的记录试一次。

### M5 智能模式（s21 到 s28）

**给 owner 什么：**（3.4）
- 新建的群默认智能模式：bot 自己判断接不接话、回在主区还是开新话题；进群时说一句"我会读群消息，合适时接话"。
- 多 bot 群里只接对自己说的话：@ 了谁、引用了谁，就谁回；bot 不进别的 bot 的话题；主区命令要 @。
- 同一台 Mac 上几个智能 bot 合成一次判断，只放行一个回复。
- 智能 bot 之间能互相 @，没有真人插话时最多来回 3 轮。
- 群详情页能切换智能或规则模式，改回复方式和"运行中来了消息"。
- 可以填 OpenAI、TypeSafe 或 OpenRouter 的 key 来做判断。
- 用量页显示判断次数，诊断页显示"不回"的原因。
- 已有的群仍是规则模式，行为不变。

**怎么验收：** 照 product.md 3.4 的例子：同一台 Mac 上至少两个 bot，一个规则模式、一个或两个智能模式，都在一个新建的测试群里。
1. @ 规则模式的 bot 问一句，只有它回。
2. 不 @ 说一个产品问题，比如"下周发布要不要先砍掉导出功能？"，智能 bot 里只有一个开话题回。
3. 说一句闲聊，没人回；诊断页能看到"不回"的原因。
4. 发一条 @所有人，没人回。
5. 在智能 bot 开的话题里，让它 @ 另一个智能 bot 帮忙看，对方会回复；来回 3 轮后停下。
6. 引用某个 bot 的回答说一句，只有它回。
7. 在群详情页把这个群切成规则模式，再切回来；在用量页看判断次数。

### M6 提问卡片、权限档和子 agent（s29 到 s35）

**给 owner 什么：**
- 提问卡片（3.8）：agent 向人提问或请人确认方案时，群里单独发一张写清后果的卡片，@ 能回答的人，只有发起人或管理员能点。等回答期间，这一轮不会被超时杀掉；15 分钟没人答，卡片收成一行结果。直接打字回复也算回答。重启后点旧卡，卡片会说明已失效。
- Claude 的权限档（3.8）：只读、读写档下不再写到工作区以外，关网时连不上网，开网时能用 WebFetch。
- 子 agent（3.9）：Codex 和 Claude 的子 agent 显示在运行卡的子 agent 区，每个能单独停；子 agent 都结束，这张卡才收尾。

**怎么验收：**
1. 在一个用 Claude、读写档的群里说"先用选项问我用哪种方案，再动手"。群里出现选项卡，选一项后 bot 接着做。
2. 再来一次，这次直接打字回答。
3. 再来一次，不理它；15 分钟后卡片变成"没人回答"。
4. 请同事点一张不是他发起的卡，他会看到提示。
5. 在一个用 Claude 的只读群里，让它往桌面写一个文件；它被拒绝，并说明原因。
6. 让 Codex 和 Claude 各起两个并行的子 agent 做事，看运行卡上的子 agent 区，单独停掉一个。

### M7 个性、记忆和多工作区（s36、s36b、s37 到 s42）

**给 owner 什么：**（3.2、3.3、3.6）
- Bot 页：能改个性（SOUL.md）、规矩（AGENTS.md）、智能提示词、公共记忆、工作区和代码仓库。
- 群详情页：能给每个群补充或替换个性、换工作区、加仓库，查看和修改本群记忆。
- 把 bot 拉进已有的群，不再弹私聊绑定卡，群里直接能用，默认只读、关网（3.8）。
- 新群不用再选文件夹，自动建在 `~/.vonvon-bot/projects/<bot 名>/groups/<群名>/`。群没设工作区时只用自己的目录，bot 的代码仓库照常带上。
- 说"记住……"以后，卡片上显示"已记到本群记忆"，可以撤销；别的群看不到。
- bot 能同时在多个工作区和代码仓库里干活。
- bot 的会话不再读写你自己 Claude 和 Codex 的自动记忆。

**怎么验收：**
1. 在 Bot 页给一个 bot 写几句个性，比如"说话简短，不客套"；在群里 @ 它，语气变了。
2. 在某个群的详情页给这个群补一句个性，只在这个群生效。
3. 把 bot 拉进一个新建的群：不弹私聊绑定卡，群里 @ 它能回。在群详情页把权限档改成读写，让它写一个文件；到 `~/.vonvon-bot/projects/<bot 名>/groups/<群名>/` 下能找到。
4. 给 bot 加一个本机代码仓库，让它在仓库里改一处，再在工作区里写一个文件。
5. 在一个群里说"记住：发版在周四"，卡片上出现"已记到本群记忆"。点撤销，再说一次。去另一个群问什么时候发版，它不知道。
6. 在 Bot 页查看并修改公共记忆，两个群都能用上。

### M8 skill、MCP 和查飞书上下文（s43 到 s48）

**给 owner 什么：** 桌面端有本机 skill 库和 MCP 库（3.6）。skill 可以从 `~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills` 或任意文件夹导入；MCP 可以从 Codex、Claude 的配置导入，也可以手填命令或网址。导入后给 bot 启用，在某个群里另外增减。新建的 bot 不再带你自己的个人指令和 skill，导入的 bot 不变。bot 能用 vonvon 飞书 skill 查本群的话题和另一条会话（3.5）：在主区问"两个话题的结论"，它去读了再答，卡片上写读了哪些。

**怎么验收：**
1. 在 skill 页从 `~/.claude/skills` 导入一个 skill，给 bot 启用，在群里让 bot 用它；在另一个群的详情页把它移除，那个群里就用不上。
2. 从 Codex 配置导入一个 MCP，给 bot 启用，让 bot 调一次。
3. 新建一个 bot，问它有哪些 skill，里面没有你自己的个人 skill。
4. 照 product.md 3.5 的时间线：在主区开两个话题，各聊几句；回主区 @bot 问"两个话题的结论"。卡片上写着读了 T1、T2 的会话，回答里有两边的内容。

### M9 私聊（s49、s50、s51a、s51b、s51c、s53 到 s57）

**给 owner 什么：**（第 4 节、3.7、第 6 节）
- 主人和管理员私聊 bot，就是正常干活，不再弹管理菜单。私聊默认用读写档，这是本文第 5 节记的默认值，可以在设置页改。
- 别人私聊时，收到一张"在群里 @ 我"的卡片。
- 在私聊里直接说"以后在测试群说话活泼点""给测试群加上某个 skill""把测试群改成读写档""建一个发布群，把我拉进来"，bot 自己改好，回一张写明改了什么的卡片，可以撤销；扩大能力的改动单独标出。
- 飞书应用里另外加的管理员和开发者也能管 bot；设置页标出每个管理员是从飞书来的，还是本机加的。
- 设置页能关掉"聊天改设置"。

**怎么验收：**
1. 私聊 bot："在工作区写个脚本统计行数"，它直接干活。
2. 请一个不是管理员的同事私聊 bot，他收到一张卡片，上面列着你们都在的群。
3. 在私聊里说"以后在测试群说话活泼点"，收到改动卡片；去测试群看效果，再回来点撤销。
4. 在私聊里说"给测试群加上某个 skill""把测试群改成读写档"，卡片上这两项标成"扩大了 bot 能做的事"。
5. 在私聊里说"建一个发布群，把我拉进来"。
6. 在飞书开发者后台给应用加一个开发者，10 分钟内他就能私聊 bot；设置页标出他来自飞书。
7. 在设置页关掉"聊天改设置"，再在私聊里让 bot 改设置，被拒绝。

### M10 从 bridge 迁移（s58 到 s64）

**给 owner 什么：**（第 5 节）桌面端发现 `~/.feishu-codex-bridge` 就显示导入页，页上有预检表，以及"会感到的变化"和"失去"两张清单。点一下就把全部 bot 搬进来：群、话题和旧会话都在；迁来的群用规则模式，沿用原来的设置；咖啡一下的 hook 重新装好。任何一步失败都会自动回滚，并重新启动 bridge。迁移之后，误开 bridge 会被拒。bridge 最后一版的分支和 PR 已准备好，发布时间由 owner 定。

s58、s59 不依赖 M3 到 M9，M4 之后就在第二条线上做。s59 的预检先在 Mac 检查会话里用 bridge 数据的副本和隔离的 HOME 跑，不碰 owner 在用的 bridge。

## 7. 预览版怎么出

1. Claude 经 Paseo 开预览版会话 `Mac 预览版 <里程碑名>`，模式 auto，规则见 `AGENTS.md`"工具和同步"。
2. Codex 在 Mac 上从 main pull，`npm ci`，`npm run build`，再在 `packages/desktop` 下用 `electron-builder --config electron-builder.yml --dir` 打包，也就是今天的 `package:dir` 脚本。electron-builder 会自动用钥匙串里的 Developer ID 签名。不公证，只出 Apple Silicon。
3. 打好的 .app 装进 /Applications，通知 owner 验收。
4. 具体命令以仓库脚本为准。M1 预览版（2026-10-14）按第 2 条做通了，打包前补跑 `node node_modules/electron/install.js`，在沙箱外打包和验签，用 `ditto` 装进 /Applications。

下面几条来自 #296 的 Mac 检查和 M1 预览版：
- Mac 上 Paseo 用的仓库，本地 main 可能是旧的（M1 预览版时停在 d90f4d4）。预览版和检查会话的提示里写明先 `git fetch`，核对 main 或分支的 sha 和 Claude 给的一致再构建。
- 在沙箱里打包会跳过签名（electron-builder 输出 `0 valid identities found`），应该是 auto 模式的沙箱看不到钥匙串。所以在 `packages/desktop` 下跑 `npm run package:dir` 要申请在沙箱外执行。验签也在沙箱外做：沙箱里的 `codesign --verify` 报 `invalid signature`、`Authority=(unavailable)`，沙箱外是通过的。
- `npm ci` 之后第一次打包缺 Electron 的二进制，原因没查（Mac 的 npm 版本没记）。打包前先跑 `node node_modules/electron/install.js`。
- auto 模式下，联网（`npm ci`、`gh`）、沙箱外的命令、打开 app、用 Computer Use 操作 app 都会发申请，没人批就一直等。#296 的检查卡在这里将近一小时。Claude 发起会话后要盯着这些申请，按检查范围用 `paseo permit allow` 批准，范围外的不批。
- 在终端里用 `open` 启动 app，会继承终端的长 PATH。要模拟从 Finder 打开，显式加 PATH：`open -n --env PATH=/usr/bin:/bin:/usr/sbin:/sbin --env HOME=<临时目录> ... <app>`。
- 测 Claude 时，隔离 HOME 下读不到 owner 的 Claude 凭据：owner 的凭据写在 `~/.claude/settings.json` 的 `env` 里，不在钥匙串。要测已登录，那一条命令用真实 HOME，VONVON_HOME 仍用临时目录。
- 退出桌面端不停 daemon（product.md 3.10）。测完用包里的命令行 `daemon stop` 停掉隔离 HOME 里的 daemon。

测 Claude 后端时，用 owner 本机的 Claude 登录跑少量回合。这是测产品，不是在 Mac 上开 Claude 的开发会话。

## 9. 开发时的做法

只写 `AGENTS.md` 里没有的，或者容易忘的：
- 审查前先用 code-simplifier 把 diff 过一遍，再交给审查的子代理。
- 写网页和桌面端界面时用 frontend-design。
- 网页界面在 JP-VPS 上用 playwright 无头打开，截各种状态看。
- 新 worktree 跑 typecheck 前，先 build `@vonvon/protocol` 和 `@vonvon/client`，不然找不到它们的 dist。
- JP-VPS 上的 npm 11.19 默认不跑依赖的安装脚本，`npm ci` 后 electron 的二进制不在。要在 JP-VPS 上打 Linux 目录包（`electron-builder --dir --linux`）验证打包结果时，先跑 `node node_modules/electron/install.js`。Mac 上打包也缺过这个二进制，原因没查，见第 7 节。
- 行数可能超过 1500 的片（s06、s51a 到 s51c、s59），开工后先用 `git diff --stat` 量。
