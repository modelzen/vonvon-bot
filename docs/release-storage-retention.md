# 发布存储保留策略

2026-11-04，owner 同意把 Linux 与 R2 纳入现有每日存储维护。存储维护只清理已失去用途的旧版本文件，不构建新包、不更改版本、签名清单、stable 或官网入口，也不代替正式发布。本轮云端验收只做只读预演，不删除安装包。

## 保留范围

| 位置 | 常规保留 | 说明 |
| --- | --- | --- |
| 本地发布目录 | 最近 3 个正式产品版本的完整最终包 | 包括 Mac 两架构最终 ZIP/DMG、Windows 两架构安装包、Linux x64/arm64 两个 tar.gz；发布中的候选和被引用文件额外保护 |
| COS：Mac、Windows、Linux | 统一产品最近 5 个正式版本 | 按正式产品版本排序，各端共同使用同一组版本，不按文件数或平台分别计数 |
| R2：Linux | 与 COS 相同的最近 5 个正式版本 | 仅处理指定生产桶内已识别的 Linux 版本化对象 |

最近 5 版是基础保留范围，不是存储数量的硬上限。下列文件或其所属版本额外保留：

- 云端上传不足 14 天的对象；时间不明时不删除。
- 任一端 stable、官网入口或回滚记录引用的版本。
- 尚未结束的候选、活动发布及其恢复过程引用的版本。
- 无法可靠识别归属、引用或用途的对象。

发布证据、回执、清单快照与哈希记录长期保留，不随旧包一起清空。清理本地旧包不等于删除整个发布输出目录。CDN 缓存不作为永久备份；删除旧源文件不能以“边缘缓存还在”为依据。

按当前包大小估算，每版 COS 约 0.964 GB，R2 约 128 MB；5 版约为 4.82 GB 与 640 MB。这里只估算当前包体积，不是费用承诺或容量上限；额外保护的版本、元数据和未来包大小变化另算。

## 云端清理边界

COS 沿用各平台已识别的版本化对象白名单。R2 只允许删除指定生产桶中下列对象，目录版本与文件名版本必须相同：

```text
bot/server/<X.Y.Z>/vonvon-server-<X.Y.Z>-linux-x64.tar.gz
bot/server/<X.Y.Z>/vonvon-server-<X.Y.Z>-linux-arm64.tar.gz
bot/server/<X.Y.Z>/manifest.json
```

R2 的安装、卸载脚本、`stable/`、未知键、内部构建记录及其他前缀不删除，不按整个目录递归删除。COS 和 R2 的 Linux stable 清单都须读取并验证签名，联合保护其引用版本；两端指向不同版本时，两者都保留。任一必要入口无法读取、验签或确认状态时，跳过依赖该信息的删除，不能把失败当成“没有引用”。

## 每日执行与验收

现有本地 Codex 自动化每天北京时间 10:00 执行维护，范围已加入 Linux/R2；实际执行仍依赖本机任务运行，不是云端定时器，也不保证关机时执行。连接配置可放在 `~/.config/vonvon-release/` 等仓库外目录，只引用凭据环境变量名；账号标识、token、密钥和机器 IP 不进入 Git。

每次维护按以下顺序执行：

1. 完整分页枚举相关 COS/R2 对象，读取各端 stable、官网、回滚、候选和活动发布状态。镜像同步或发布活跃期间，不执行云端历史对象删除。列表不完整、权限不足或状态不明时跳过受影响范围，不扩大权限。
2. 先保存只读计划：保留与删除候选、保护原因、预计释放空间，以及对象的 ETag、size、lastModified 和入口/状态快照。计划不得把不在白名单内的对象列为可删除。
3. 真正删除前重新读取对象元数据和稳定入口/状态。ETag、size、lastModified 或任一保护引用发生变化，立即停止对应计划并重新预演；不能沿用旧计划继续删。只执行再次确认仍满足保留策略的精确对象。
4. 保存执行结果；未执行、权限不足、状态变化与成功删除分别记录。证据长期保留，不报告未发生的清理。

验收至少覆盖统一最近 5 版、14 天保护、任一端引用保护、COS/R2 签名清单联合保护、分页不完整、未知键、元数据或发布状态在计划后变化、权限不足跳过，以及本地 Linux 两架构最终包随最近 3 版保留。生产云端只读预演须列出候选和保留理由，并确认没有发起删除请求。
