# 配方数据库

在专用的空测试数据库中，以迁移管理员按文件名前的时间戳顺序执行 `migrations/*.sql`，每个文件使用独立事务。PostgreSQL 15 的 psql 可用 `psql -X --single-transaction -v ON_ERROR_STOP=1 -f <migration>`。记录已执行版本，已有数据库升级时只执行新增迁移，不重复运行建库文件。迁移需要创建 schema、非登录角色和 pgcrypto 扩展的权限。Supabase 中 pgcrypto 应安装在 `extensions` schema。部署前先在目标项目的 staging 环境验证权限和扩展位置。

API 使用单独的 LOGIN 角色，只授予 `recipe_api` 成员资格。API 每个请求开始事务、切换到 `recipe_api`，设置事务局部的 `app.recipe_account`（本环境已验证的 Supabase subject，游客传空串）和 `app.recipe_code_key`（32 字节随机专用服务端密钥，64 个十六进制字符），然后执行 `recipe_api` schema 的对应函数并提交。连接池不得在事务以外设置这两项。定域凭据、查询参数和回执须从数据库及代理调用日志中排除。备份专用密钥，使现有可用码在应用重启和恢复后仍可复制、兑换。该切片固定使用 v1 密钥，轮换应先迁移、验证现有可用码。

基础表在 `recipe_private` 中，均启用 RLS。公共及普通客户端不可直接读写表，网络服务只有绑定了每个动作身份和参数检查的函数执行权。函数由独立的非登录 owner 执行。数据库普通连接不能经由网络接口设置账号 ID。托管环境的 PostgREST 暴露 schema 应保持默认，不加入这两个内部 schema。

读写契约与额度见 [云端设计](../docs/design/accounts-recipes/cloud.md) 和 [配额](../docs/design/accounts-recipes/limits.md)。此实现支持公开文字与一条私有角色说明。草稿最多 20 份，已发布配方最多 20 个，每个最多 30 版。每位作者每日最多发布 10 版、签发 500 枚码，累计最多 5,000 枚；每批最多 100 枚，每版同时可用最多 500 枚。数据库对每个作者的创建、修订、发布与发码操作串行核额，对同一码并发消费使用条件更新。用于 CAS 的 baseRevision 同时包含草稿修订和创建时固定的配方版本，发生冲突需重新核对来源。

草稿的幂等回执保留最多八个近期请求的 ID、输入摘要和修订号。迟到的旧修订返回冲突。删除或发布时同一事务清除该草稿的保存回执，保留草稿 ID、账号、原创建时间的墓碑以拒绝旧请求复活。按 UTC 自然日每账号最多新建 100 份草稿，删除不会释放当日创建额度。领取记录同时保存最初成功请求的 UUID 和摘要，无需为每次再次领取同版新增业务记录。成功发布及发码回执仅引用不可变版本和码记录，可用码的明文仅在作者明确申请时重建，已兑换或停用的码永久清除其 nonce。

草稿、详情和精确版本获取由产品 API 调用。领取库每页最多 50 行，目录每次 8 行并按版本排序，码管理每页 50 枚，续页均传回服务器返回的 nextCursor。作者作品列表返回最多 600 行轻量元数据。此切片的受控字段可暂存于 PostgreSQL。开放一般技能、文件及 Logo 之前，须接通对象存储中的不可变版本、生命周期状态及删除流程。
